# orchestrate-tasks

任务编排与迭代接力,仅显式调用执行.默认由当前任务担任负责人,拆分给内部子 Agent,完成一个批次后由当前任务整合,验证,完成必要文档并统一交付.不会先创建一个新的 Codex 负责人,也不会自动迭代接力.

委派决定谁承担完整交付责任,拆分决定负责人如何组织工作,迭代决定是否逐轮推进.这些选择可以组合,不再把“委派”和“拆分”合并为一个入口.普通开发和仅讨论不自动派发,已明确的选择不因一句“继续”而重置.

| 你的选择 | 实际执行方式 |
| --- | --- |
| 未指定其他分支 | 当前任务负责,内部子 Agent 分工,本批统一交付 |
| 委派给新 Codex 任务 | 新负责人默认拆给内部子 Agent,收口后回传 |
| 委派,不要拆分 | 新负责人独立完成,不再创建助手或下级聊天 |
| 拆成多个 Codex 任务 | 当前负责人按独立成果安排多个侧栏任务并负责整合 |
| 委派后拆成多个 Codex 任务 | 明确授权一位负责人创建一层执行聊天,结果先归负责人再回原主任务 |
| 迭代或 GOAL 接力 | 按目标与停止边界逐轮推进,保留唯一后继及串行交棒 |

除默认内部拆分外,其他分支须用户明确选择.允许按需创建任务不等于必须创建.拆分要有独立成果和实际收益;很小或强串行的工作没有合理拆分点时说明原因后直接完成,不为凑数量拆分.用户明确不拆分时尊重该选择.

## 安装与发现

从[公共仓库](https://github.com/luck-gh/agent-skills)取得完整目录,公共下载仅含已发布内容.在宿主发现目录安装实体或指向唯一实体的准确目录链接;Codex 的用户级位置见[官方文档](https://developers.openai.com/codex/skills#where-codex-loads-local-skills).无额外运行依赖,settings 或后台服务,派发需要宿主工具及有效权限.

旧名 `orchestrate-subagents` 已改为 `orchestrate-tasks`,无兼容入口.升级需保留本地配置和用户改动,核对实体及发现位置,验证新入口指向和内容后再清理准确旧链接;删除链接不能扩大为删除实体.仓库内容更新不会修复仓库外链接,应由安装升级流程完成交接.列表未刷新时重启 Agent.

## 简短调用

```text
使用 $orchestrate-tasks 完成我们已明确的工作.
```

```text
使用 $orchestrate-tasks,由当前任务负责拆分给内部子 Agent,完成本批整合,验证和必要文档后统一交付.不提交,不推送.
```

这两个调用都使用默认路径.“一次性交互”指一个有界交付批次,执行方收到完整任务包后自主闭环;必要修复与验证不会省略,但不会自动续轮或反复要求你说“继续”.当前负责人须收齐必需内部结果再结束,不能依靠内部 Agent 在结束后唤醒它.

AI 从已有上下文整理目标,范围,验收和有效授权,只补问缺口.默认值不替代宿主授权,调用不会撤销“先不提交”等限制,也不自动获得新聊天,跨聊天消息,Git 或设备权限.

明确委派时,可一次说明交付与授权:

```text
使用 $orchestrate-tasks,把我们确认的完整成果委派给一个新的 Codex 任务,负责人默认拆给内部子 Agent.你派发后结束本回合,授权负责人向本主任务回传结果,以及本主任务发送必要的集中验收反馈.不提交,不推送.
```

希望新负责人独立完成时,加上“委派后不要拆分”.想由当前任务按独立成果创建侧栏聊天时,明确说“拆成两个 Codex 任务”,并说明其成果和消息授权;若先委派再由新负责人创建这些聊天,须明确这一层级,数量及各级消息路径,不能从一次委派推导无限任务树.

迭代示例(轮数仅为示例上限,不用预先手写 GOAL):

```text
使用 $orchestrate-tasks 对项目 P 进行迭代编排,完成离线保存,验收为保存后关闭重开可逐字恢复,不做网络同步.从 1 到最多 3 轮,达标提前停止.授权每轮新建 Codex 任务,同项目 local,允许内部子 Agent,验收后更新文档并精确本地提交,不推送.你派发后结束本回合,授权终止轮向本主任务汇总回传,无法自行解决的真实阻塞也可提前反馈;正常接力无需逐轮汇报.
```

只需方案时加“只讨论,不要派发”.显式迭代才需要接力,普通内部拆分的依赖推进与集中修复不属于新的迭代轮次.

## 回传与整合

默认内部拆分由当前任务接收内部结果并统一交付,不使用跨任务回调.只有明确采用侧栏任务时,才按已选方式交付:可在必要初始核验后结束等待回传,也可明确保持事件等待或仅创建交接.实际回传前核实接收任务准确标识,宿主发送并继续对话能力,以及人类对消息路径的授权.条件不足会明确限制,不会虚构后台唤醒或增加服务.

同一层的多个 Codex 执行任务可分别向所属负责人反馈,无需另建收集任务.委派后再拆分时,下级先交受委派负责人,由其整合后统一回原主任务.接收方依据已有批次/任务标识防止重复计数,派发和整合.需要合并,联调或组合验证时,待必要结果齐备,版本明确且相关写者结束后由执行负责人完成;只有用户明确选择或已有批次授权覆盖时才另建整合任务.只需汇总结论则直接验收.

子 Agent 只向所属负责人交付.负责人负责协调,验证和整合,不把内部责任交回纯总控.普通实现选择和可自行解决的测试失败由原所有者处理,不持续催促或逐步指导.显式迭代各轮自主接力,整批达标或停止时汇总;真正需要上级解决的阻塞可按授权提前反馈.

## 文档责任

各执行方式都按 [共同规则](SKILL.md#共同文档收口) 判断必要记录,覆盖新功能,Bug 修复,性能优化和测试流程改进.通用职责沿 bootstrap-project-context 的现有文档契约和项目真源,不重复建立台账或每轮初始化.各方提供自己范围内的事实和证据,共享文档由指定负责人维护,纯总控验收.

必要更新在交付前完成,有提交授权时按项目规则先收口再提交.只读任务仍只读,受限更新在交付中具体说明.不强制每次刷新全部文档,不把局部已完成修复塞进 PLAN 或把等效重测当新能力.

## GOAL 与读取范围

默认目标文件为项目根下的 `docs/GOAL.md`,用户指定或项目既定入口优先.首轮安全确认初始缺失后,在实施前创建;已有则复用,后轮缺失先核查恢复,不会重新生成一份覆盖进度.

GOAL 只保留批次目标与范围,验收标准,剩余/阻塞项及证据指针,停止边界.它和 PLAN 不维护重复任务状态,不要求额外生成日志,交接账本或其他基线文档.每轮只传固定契约与编号,动态项目事实从仓库读取.

执行时只加载 [SKILL.md](SKILL.md) 和所选分支需要的说明:默认内部拆分读子 Agent 说明,自动选模才加模型指导及 JSON;明确侧栏执行才读新任务及回调说明,明确迭代才读接力规则.多个负责人各带子 Agent 或委派后再拆成 Codex 任务时读混合承载,README 不作为执行必读.

## 模型配置与交付

具体模型 ID,适用任务和默认推理建议集中在 [model-routing.json](references/model-routing.json),更换候选只维护此文件;判断方法见[模型指导](references/model-selection.md).保留用户指定及继承优先,当前主任务不自动换模.JSON 不承诺宿主支持,用户侧任务另守工具的选模授权条件;请求模型与实际确认值分别报告.

自动选模按具体成果区分局部代码修改,视觉检查,有界界面操作和基于材料的写作等画像.候选加入目录不等于全局默认或能力实测结论,也不自动取得视觉输入,浏览器和设备工具权限.

交付说明任务身份和状态,主要结论,修改范围,实际验证及依据,必要文档位置,未完成项与在途操作.组合产物由指定负责人在最终候选上验证,纯总控不接管实施或复验.创建成功,回合结束或单项测试通过均不代表完整成果已验收.

静态校验,模型路由回归和独立模拟分别验证结构,数据及决策;[行为样例](tests/behavior-cases.md)用于维护回放.模拟不证明真实用户侧聊天,回调或两轮接力成功,真实接力需明确批次授权.本目录按 [Apache License 2.0](https://github.com/luck-gh/agent-skills/blob/main/LICENSE) 分发.
