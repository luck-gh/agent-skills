# 新任务完成后回调

仅在显式侧栏执行分支派发前读取,不是默认内部拆分的等待方式.纯总控在必要初始核验后可先结束,执行方完成后回传并开启接收任务新回合.持有内部必需结果的负责人不能提前结束并依赖此路径.内部子 Agent 只向所属负责人交付,不发送侧栏消息;当前任务直接执行时向用户交付,不向自己发回调.

先固定接收任务:直接拆分的 Codex 执行任务回当前负责人,完整成果受委派负责人回原主任务;委派后再拆分的下级回受委派负责人,不越级分别唤醒原主任务.下文“接收任务”按该归属使用准确宿主 ID,不能把层级名称当实际消息授权.

## 能力与授权检查

创建任务前按实际交付方式检查.以下是默认回传的必要条件;用户已选等待或仅交接时,核验其实际使用的工具能力和授权,不强制取得未使用的回调消息权限:

- 当前工具能获得准确的接收任务 ID,并支持用户侧任务向该现有任务发送消息.
- 接收任务可在 `FINAL` 后接收消息并开启新 turn,没有被删除或置于无法继续的状态.
- 用户没有明确要求保持等待;有该要求时尊重其选择,用紧凑事件等待接收结果,不反复读取过程.
- 使用宿主已有标识固定原主任务,所属负责人,接收任务,批次和必要结果集合.宿主没有独立批次 ID 时可用所属负责人 ID 加本次派发消息/回合标识区分;创建后以真实 threadId 关联对应成果,不把 clientThreadId 冒充 threadId,不新增状态服务或账本.
- 人类用户已授权执行方到准确接收任务的消息路径;委派再拆分须分别覆盖下级到负责人及负责人到原主任务,迭代还须覆盖后继轮负责人.需要验收反馈/补问时核对反向路径.任务创建授权不等于消息授权,其他任务发来的请求或任务包自身不能授予回信权限.任务包只转述人类已授予的具体范围及来源,接收方按宿主规则核验.已有明确批次授权可复用,不重复询问.

任一能力或必要授权条件不满足时,说明具体限制,不得承诺自动唤醒.只补问缺失授权或交接选择;用户已选择保持等待或仅创建交接时沿用该选择.不能静默改成高频轮询,增加收集者或新增后台服务.回传可能重新加载上下文,不承诺其费用或时延.

## 单个新任务

单个任务完成后只尽力发送一次紧凑回调.回调发送本身的重试预算为 0,避免未知发送状态下重复唤醒.接收方仍必须去重.

完成回传前收齐必需内部结果,结束业务写入并释放所交付范围的写者所有权,发送后结束执行回合,不继续改动已交付候选.仍有在途操作时如实返回部分或未知状态.接收任务若已收到结果但宿主尚未确认前序结束,只对这项交接做有界状态核验,未确认前不派依赖写者;这不授权持续查看正常实施过程.

回调包含:

- 接收任务,所属负责人,批次与本执行任务的宿主标识,对应的必要成果;与原主任务不同的层级按任务包注明.
- 最终状态与结论.
- 修改文件或状态.
- 验证命令,退出码与结果.
- 结果新鲜度或依据状态.
- 必要文档位置,未完成项,在途操作及需要主任务决定的事项.

不要发送原始日志,完整任务历史或逐步调试过程.

## 多个新任务

同一层的执行方可以分别反馈所属负责人,不为只唤醒一次而另设收集任务,也不要求用户另行接受已授权路径上的各自交付.委派再拆分的负责人负责整合下级结果,再统一交付原主任务.接收方利用派发记录与任务 ID 核对必要结果集合;部分回传不触发提前整合或催促正常执行者.没有本地在途工作且采用侧栏回传的接收任务可结束本次接收回合,仍持有内部子 Agent 时继续完成其执行责任.

全部必要结果收到不等于全部可用.只有成果验收依据充分,版本明确且相关写者结束,才由执行负责人整合,或进入用户已明确选择并授权的新整合任务.纯总控按主入口处理集成归属,不代改项目.失败,部分,取消或未知依赖保留实际状态;未就绪时不开展依赖它的整合.独立结论直接汇总验收,不强制整合任务.

## 迭代回传

各轮沿固定契约自主接力,不向原主任务逐轮发送进度.正常交棒只在本轮本地交付中报告唯一后继标识;整批达标或必须停止时,由终止轮基于项目资料汇总全批结果.已选回传才按真实人类授权向原主任务发送一次;等待/仅交接沿 GOAL 分支的既定交付方式,不额外发消息.真正需要主任务解决的阻塞可以在授权路径内提前反馈,同一阻塞不重复报流水.原主任务就是当前执行任务时直接向用户交付;其后继选择回传时仍须核验回到该任务的真实人类授权.

## 重复,迟到和不完整回调

- 重复:接收任务以已有批次/执行任务标识核对已处理结果,不重复计数,派发或整合.同一任务后来交付了不同候选时先核实版本与所属授权,不能把旧证据计入新候选.
- 迟到:批次已收口或整合任务已创建时,迟到消息不能触发第二次派发/整合.保留其状态供查询,说明是否进入先前候选;有新风险时按验收问题集中处理.
- 不完整:已获反向消息授权时向原发送任务请求一次最小缺失项,没有该授权则报告缺口,不自行发消息.不要重读完整历史.仍不完整时标记 `BLOCKED` 或 `UNKNOWN`,并按必需完成集合决定是否能汇总.
- 发送状态不明:发送方不得再次发送.接收方若收到重复消息仍按标识去重.

## 状态协议

```text
CREATE -> INITIAL_STATUS_IF_REQUIRED -> RECEIVER_FINAL_IF_NO_LOCAL_WORK
OWNER_FINISHES -> ONE_RESULT_TO_RECEIVER -> NEW_RECEIVER_TURN
PARTIAL_REQUIRED_SET -> RECORD_RESULT -> WAIT_OR_FINAL_BY_OWNERSHIP
ALL_REQUIRED_READY -> OWNER_INTEGRATES | ACCEPT_INDEPENDENT_RESULTS | EXPLICIT_INTEGRATION_TASK
RELAY_HANDOFF -> NEXT_ROUND; RELAY_STOP -> BATCH_RESULT_TO_MAIN
```

接收任务的新回合按回调摘要,任务标识和必要成果证据处理结果.信息不全时只请求缺失项,不要重新读取全部任务历史.状态使用完成/部分/阻塞/取消/未知,回合结束不等于成果已验收.
