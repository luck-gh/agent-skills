# GOAL 有界串行接力

仅用于用户明确选定的迭代编排,不是默认内部拆分批次.本分支默认由启动聊天整理固定契约并创建首轮,每个后继都是新 Codex 任务.用户明确要求在本任务中执行时,当前任务可直接担任本轮负责人,不强制另建首轮;后继仍须另有真实授权与有界停止条件.负责人自主实施,按主入口默认评估合理内部拆分;用户明确本轮或整批不拆分时由负责人独立完成.唯一后继权始终属于轮次负责人,不因内部或获准侧栏拆分下放.不建立常驻总控,并行轮次,后台循环或自动恢复器.

## 固定契约与 GOAL 路径

启动接力前从已有上下文整理:已保存项目,GOAL 路径,批次目标与可验收终点,范围及范围外,起止编号,首轮执行位置,创建首轮/后继和本地提交的授权,拆分选择与许可,用户模型偏好与已指定预算.按主入口回调说明核验已选交付方式所需的能力与授权;选择回传时核验原主任务准确 ID,宿主继续对话能力及人类授予各轮返回原主任务的消息路径,将授权来源纳入固定契约.已选等待或仅交接不要求未使用的消息权限.缺必要项只补问缺口,不自行填轮数或预算.当前任务执行授权只覆盖已允许的本轮工作,不推导后继创建,消息或提交权限;缺续轮授权时本轮完成后交付并停止.本地提交不包含 push,tag,merge 或发布.

GOAL 使用项目根相对路径,默认 `docs/GOAL.md`.用户明确指定的路径优先,其次沿用项目规范确定的现有目标入口;不迁移有效文档或新建竞争副本.启动者根据已知上下文和必要指令确定唯一路径,需要核实项目事实时委派只读调查,再将路径固定在首轮及后继契约中.目录不明确或与有效项目规则冲突时先解决,不逐轮换路径.两个文档职责分开:PLAN 管项目方向及后续计划,GOAL 管本批验收目标与剩余缺口;已有任务或证据真源只给指针.

用户指定总时长时固定含时区的绝对截止时间.累计费用/token 预算须固定总额,统计范围/起点及宿主或已有项目证据来源;每轮读取真实累计用量,不重新起算,不把账户总使用率当批次用量,不新建预算账本.无可核验来源就不能启动该预算接力;中途不可核验则不续轮.未指定预算不增设数值.

首轮与所有后继沿用相同完整固定契约,只递增当前轮编号.首轮执行位置按固定字段中的用户选择处理,后继均为新任务.不携带前轮总结,HEAD,日志或下一切片建议;动态事实从仓库继承.最小模板:

```text
使用 $orchestrate-tasks 执行迭代编排,你是第<当前编号>轮负责人.
每轮读取当前 Skill 入口,goal-relay.md,创建任务时读 new-tasks.md,回传时读 new-task-callbacks.md,以及适用项目规则.
项目:<已保存项目>.GOAL:<项目根相对路径>.
目标与验收终点:<固定内容>.范围/范围外:<固定内容>.
编号:<起始>至<末轮>,仅为上限.同项目 local,串行单写者.
首轮位置:<新任务或用户明确指定的当前任务>;后继使用新 Codex 任务.
授权:<首轮和唯一后继创建,本地提交范围,内部代理许可>.
拆分选择:<默认内部 Agent,用户明确不拆分,或明确授权的 Codex 拆分范围>;下级无权创建迭代后继.
原主任务/批次:<准确宿主标识>.回传:<宿主能力,人类授权路径与来源或已选替代方式>.
文件,资源及共享文档所有权/就绪依赖:<固定范围和准入条件>.
模型与 reasoning:<用户指定或宿主默认>.预算:<仅已指定项及其固定核验来源>.
首轮在安全确认 GOAL 初始缺失时,按已定目标在实施前创建;已有则复用,后轮缺失先恢复核查.
从仓库核验事实,自主完成可验收切片,自查和验证,按主入口共同文档规则收口并在授权内精确提交.
验收提交完成,写者结束且仓库操作冻结后,仅在目标未达且边界允许时创建唯一后继;必要创建核验后退出.
后继只接收本契约和递增编号.达标,无有价值下一项,必需失败,缺输入,状态未知或触及边界即停止.
正常接力不向原主任务逐轮发消息;整批达标或必须停止时汇总结果,已选回传则按已授权路径发送一次,否则按事先明确的交付方式处理.
真正需要主任务解决的阻塞可提前反馈,内部子 Agent 只交所属负责人.
```

填完整占位项,模板不是授权.用户变更目标或边界时停止沿旧契约续派,按新指示处理当前工作;确需重启时重新固定契约,不静默改写批次.

## 首轮与每轮进入

1. 默认由纯总控按 `new-tasks.md` 查询项目并创建唯一首轮,明确 `local` 环境;纯总控不写 GOAL 或先实施.用户指定本任务执行时,当前任务直接承担首轮调查,GOAL 和实施责任.不预建后轮或默认新建 worktree;用户要求隔离时须先明确状态继承,整合及授权.
2. 每轮重读本 Skill 入口,本分支及项目规则,按需读取创建/回调及本轮领域说明.核对目录,分支,HEAD,工作树/index,前序收口证据和写者.前轮仍 running 可能只在核验创建状态,不能仅因未 FINAL 而等待;有在途写入反证或移交证据不一致则停止接管.
3. 保留用户已有 staged,unstaged 与 untracked 修改.无关路径可分离才继续;同路径归属不明或影响验收时停止相关工作,不 stash,reset 或覆盖.已有实现缺收口时先补缺失项,不重复实施.
4. 取得所有权后检查固定 GOAL 入口.首轮确认文件初始不存在且无前次执行/删除冲突时,在本轮实施前按下节创建;GOAL 缺失本身不要求用户手写.已有普通文件则读取并保留有效内容,仅补本批所需信息.后轮缺失,原文件曾存在后消失,内容与固定目标冲突,或路径为链接/目录/状态未知时停止受影响工作并核实,不得凭启动词覆盖或重建动态状态.
5. 从 GOAL 与实际实现选择能在本轮验收收口的纵向切片,明确减少的缺口及验证方式.预留验证和提交预算;不为凑轮数制造工作.

## 最小 GOAL 文档

新文件只需目标/范围,可观察验收标准,当前未完成或阻塞项及必要证据指针,停止边界.沿用已有格式,不造空章节,不复制 PLAN,完整测试日志或逐轮聊天.创建前检查目标及父目录的有效指令和普通路径类型;只在所需目录安全且获授权时创建,异常路径不跟随或覆盖.创建/更新后回读,并纳入本轮获授权的提交.

每轮按最终候选更新剩余项与验收状态,失败保留真实缺口;已完成项不再充当待办.证据引用已有真源,没有现成记录时在 GOAL 留最小验证摘要即可,不强制增设 task,verification,handoff 或状态账本.已有历史按项目规则保留,不因压缩丢失独有证据.仅修改或讨论本 Skill 不在当前仓库生成项目 GOAL.

## 实施,收口与交棒

1. 负责人完成端到端切片,缺陷按复现修复并定向查相关相邻实现,执行必要验收.内部派发时才读子 Agent 与选模说明,后继创建权不下放给内部执行方.
2. 收齐必需结果并结束其他写者,负责人独占整合与最终收口.依据主入口验收规则核对最终候选;后续修改使证据失效时补相关验证.所有工作类型均按主入口共同文档规则判断必要更新,不只更新 GOAL 或新功能说明;共享文档由指定负责人维护,必要更新先于提交.
3. 更新 GOAL 与必要项目证据,精确提交本轮已验收且获授权的改动,核对提交对应最终候选,保留无关用户改动.必需失败或无法可信收口时保留失败,不交给新编号掩盖.
4. 只有本轮验收与提交完成,仍有合理未完成目标且输入就绪,后继创建及已选交付方式所需的真实授权有效,编号与全部指定预算允许时才继续.回传方式核验消息权限,等待/仅交接不因此新增消息权限要求.当前任务直接执行也受此门禁约束,无提交授权不擅自提交,无后继授权不续派.达标,无价值下一项或到界立即停止,上限不要求填满.
5. 继续前确认全部内部写者及仓库操作进程已结束,核对交接证据,备齐项目查询结果和创建参数,然后冻结本轮所有仓库操作.冻结后不得再读写仓库,运行测试/构建/Git;只允许创建后继,必要创建状态核验及汇报.
6. 用固定契约创建唯一下一编号任务,按 `new-tasks.md` 做必要初始状态核验后退出,不持续跟踪或创建第二个后继.创建信息仅在聊天汇报,不回写仓库.

前轮允许在最终退出前创建后继;驻留总控的“前任务必须已结束”门禁不用于自接力.交接条件是验收提交完成,写者结束及仓库冻结,后轮自行核验仓库证据.

## 异常与返回

- 创建结果未知只核查原请求,不重复创建或改用子 Agent.只有明确证明未创建且授权仍有效时,才可在一次重试预算内重试.已冻结但交棒失败时仍不恢复仓库操作,后续明确续接的任务先核验所有权与证据.
- 异常结束不代表没有写入.恢复先查旧任务/写者,Git,产物与验收,释放所有权后按原编号补缺失收口;不回滚或重复已确认副作用.
- 必需验收失败或真实输入缺失时当前轮在范围内解决;无法解决就记录最小证据和缺口并停止,不降标准或新建一轮重试.用户停止先停新派发,安全保留成果;取消或强制终止仍须授权.

启动者报告首轮入口与实际观察的状态后默认结束当前回合;用户明确等待时才保持等待.轮次负责人交棒后在本轮交付中报告唯一后继状态,不逐轮给原主任务发进度.整批达标或必须停止时,终止轮从项目资料和证据汇总全批状态,主要结论,修改范围,实际验证,必要文档位置,未完成/在途项与停止原因,按固定交付方式处理:已选回传则向原主任务发送一次;明确等待时由主任务从轮次结束事件取得唯一后继标识并切换事件等待,直到取得终止轮结果;仅交接时终止轮在自身聊天交付,不承诺通知主任务.等待中标识未知时做一次有界核验,不能猜测或重建后继.真正需要主任务解决的阻塞可在授权路径内提前反馈.单轮完成不等于批次完成,创建成功不等于执行成功,消息结果未知不得盲目重发.
