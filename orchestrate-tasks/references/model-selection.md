# 按需选择模型

仅在内部自动选模,模型方案或能力复评时读取;模型名称与候选映射只在 [model-routing.json](model-routing.json).任务运行时只读配置,以后换模型改 JSON,不在 Markdown,metadata 或固定启动词复制具体型号.

## 选择次序

1. 用户指定有效值或要求继承优先,允许目录外但工具支持的指定模型;无效指定报告 refused,不静默替换.当前主任务不换模,用户侧任务按其工具覆盖条件处理.
2. 用即将调用的工具 schema 检查模型,reasoning 与上下文组合,不混用另一工具的列表.按实际歧义,风险和可验证性选最低足够等级及主要画像,再从 JSON 筛选匹配且可用的候选.不靠主题标签推断复杂度,选择 L3/L4 要说明具体判断难点和较低等级不足的依据.
3. 同级候选仅在任务及工具描述支持差异时择优,目录顺序不是优先级.无法区分或没有匹配时报告 omitted 及原因;只有已知继承足够且允许时才能继续,否则请求决策.不改承载绕过限制.

目标清楚且可局部验证的工作可直接交给足够能力的执行方闭环,不强制强模型先规划或弱模型先试错.困难判断与大批常规实施仅在交接收益大于协调成本时拆分;同问题的调试,修复和验证留给原所有者.新成果重新评估,复用已有代理也须有依据,换模与一次能力升级遵守入口和内部子 Agent 交接规则.

## 等级与画像

- `L4`:重大歧义,高风险且难以局部验证的判断.
- `L3`:复杂整合,故障定位,审查或跨分支判断.
- `L2`:边界明确的探索,修改,重构和测试.
- `L1`:明确且易于验证的扫描,整理和重复工作.

等级是判断强度建议,不是角色,官方排名,价格或质量保证.每级均可做叶子,不授予递归权,不形成逐级委派流水线.成本考虑执行,上下文,协调和返工,不宣称低等级必然省钱.

选一个主要画像,仅实际需要时补次要画像:

- `strategic-control`:目标,授权,风险与收口判断.
- `cross-branch-decision`:跨分支冲突与架构取舍.
- `branch-coordination`:协调后代并整合结果.
- `dependency-integration`:整合依赖与多来源成果.
- `complex-review`:复杂代码,协议或质量审查.
- `high-risk-reasoning`:重大影响的协议或一致性推理.
- `ambiguous-problem-solving`:甄别竞争解释的开放问题.
- `browser-debugging`:浏览器观察,定位与验证.
- `read-only-code-exploration`:有界只读源码探索.
- `targeted-code-change`:目标明确的局部修改与测试.
- `focused-refactor-test`:小型重构及聚焦验证.
- `granular-ui-iteration`:既有界面的细粒度修改.
- `visual-inspection`:基于已有图像,截图或图表核对内容与界面,范围和判断标准明确.
- `bounded-computer-use`:目标,操作边界和结果核验明确的浏览器或应用界面操作.
- `source-grounded-writing`:基于已提供材料和明确受众撰写或改写,保留事实及必要细节.
- `bounded-scan`:固定范围资料或日志扫描.
- `documentation-research`:有界文档检索与归纳.
- `code-mapping`:代码位置,关系与所有权梳理.
- `repeatable-validation`:固定规则下重复验证.
- `high-volume-clear-work`:输入输出明确的批量工作.

视觉检查,界面操作和基于材料的写作按实际工作选画像,不把普通文档检索,复杂故障定位或跨分支决策一并归入.局部代码修改仍使用既有画像并比较所有可用候选.模型匹配不提供看图或操作工具,使用前仍核验实际输入,工具与授权;能力缺失不由换模弥补.

## Reasoning 与证据

用户指定有效 effort 优先.按本次工作判断,JSON 的默认建议不覆盖任务需要:机械低风险 `light` -> `low`,常规理解与编辑验证 `balanced` -> `medium`,复杂逻辑/高风险审查 `deep` -> `high`;仅确有需要且工具支持时采用 `exceptional` 对应的更高 effort,不默认最高值.建议值不支持时,有工具依据才选其他枚举,否则省略并说明.

派发报告可写从 JSON 解析出的具体请求值与选择理由,但工具未回显时不能声称实际模型已确认.能力不足须有修复后证据,不能把缺工具,资料,权限或普通超时当作换强模型的理由.
