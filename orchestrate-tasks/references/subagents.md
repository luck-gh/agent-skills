# 内部子 Agent

默认直接拆分或显式分支的负责人进行内部拆分时读取;共同所有权,任务包,文档收口和验收按 Skill 入口.默认由当前任务拆给内部子 Agent,受委派的新负责人也默认采用内部拆分.用户明确不拆分时不派助手;没有合理拆分点时按入口说明具体原因后直接完成,不为凑数量创建工作.

一次性交互按一个有界成果批次执行:每个子 Agent 一次收到完整工作包,自主完成调查到验证后返回.同批前置依赖完成后才能派发的工作及集中验收发现的必要修复仍在本批处理,不机械限制工具调用次数;不自动创建下一轮,自我接力或反复发送“继续”.

## 派发与模型

- 检查实际工具 schema,空闲槽位与并发约束.满槽时事件等待,不接管在途写入,不因缺槽位改成新 Codex 聊天.先收口积压结果再派新工作.
- 宿主缺少内部 Agent 工具或不允许实际调用时,明确无法落实默认拆分.继续不依赖它且在权限内的工作;必须改变承载时只询问这一选择,不静默新建侧栏任务或把降级说成已完成拆分.用户的显式编排请求和已选分支按入口传递,不把默认内部拆分变成重复索取许可.
- 显式调用本 Skill 要求按需自动选择内部模型与 reasoning,用户指定或继承优先.自动选模按主入口加载模型指导和 JSON;每个工作单元重新判断,不因已有代理就沿用配置.
- 先检查历史继承与选模组合.当前 `spawn_agent` 的完整历史继承(省略 `fork_turns` 或 `all`)不接受模型/推理覆盖;覆盖时默认 `fork_turns="none"`,或选择工具支持的必要有限历史.传完整精简任务包,不能依赖父聊天隐藏上下文.
- 用户同时要求完整继承和不同模型时报告冲突并请求选择;仅要求继承模型时省略对应覆盖,不能假设无历史一定改变或保持配置.以上均以当前 schema 为准,不虚构参数或实际模型.
- 子 Agent 负责所属成果的调查,实施,调试,验证及范围内事实/证据交付,不得创建用户侧聊天.普通子 Agent 是叶子,不能因加载本 Skill 就重新套用默认拆分;确需有界内部递归时须获准后代范围,槽位,所有权与收口责任.GOAL 后继创建权不下放,内部任务不能改成侧栏执行来绕过无槽位或权限限制.

## 等待,追加与收口

1. 由所属负责人记录执行标识,范围,模型请求及确认状态,依赖和必需完成集合.负责人有必需内部结果未返回时不能宣称完成或结束其执行回合,不能依赖内部 Agent 在结束后回调.这不要求未持有子 Agent 的原主任务持续等待侧栏负责人.
2. 负责人可继续自己的独立工作,需要结果时事件等待;不高频轮询完整历史/原始输出或逐步指导.依赖满足再派发,正常实现与可自行修复的问题留给原所有者;真实缺口按主入口的中途协调边界补充最小信息.
3. 同一问题由原所有者修复与验证,集中反馈验收问题,不拆成逐步指导.同批新的独立成果重新选模,匹配时可复用空闲代理;追加工具不能换模时,先等原执行结束并核实最后写入和所有权,再创建合适执行方,只交接必要成果和证据.能力升级仍受主入口的一次预算约束,不取消在途工作或重做副作用.范围外新成果不因已有助手就自动纳入本批.
4. 子 Agent 结果只交所属负责人,不走侧栏回调或分别唤醒原主任务.负责人收齐后负责协调,最终候选验证,结果整合和共享文档收口,不能把这些责任交回纯总控.子 Agent 完成不代表负责人或批次完成.

## 内部任务包

```text
所属负责人:<当前执行任务>.独立成果/就绪输入/依赖:<内容>.
范围与非目标/文件及资源所有权/授权/验收/停止条件:<内容>.
你是本批叶子执行方,收到完整任务包后自主完成,不继续套用负责人默认拆分或开启接力.
完成范围内调查,实施,自查和验证;交付实际状态,改动,证据,文档事实及未完成/在途项.
共享文档由<指定负责人>统一维护,仅在分配给你的文档范围内写入.
只向所属负责人返回,不创建侧栏任务或向原主任务发回调.
```
