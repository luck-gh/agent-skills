# bootstrap-project-context

为新项目或首次接管的代码库建立工程化 Agent 开发基线,也可按明确授权校准已有规范与项目文档.它让后续 Agent 知道任务开始先读什么,实现受哪些约束,如何验证,结果写回哪里,并区分目标,已实现能力与验证证据.

适合项目启动,首次接管,明确的方向校准或文档收敛.普通读码,局部修复,排版和会话交接不需要启动本流程;完成建档也不会自动继续开发.

## 安装与调用

从[公共仓库](https://github.com/luck-gh/agent-skills)取得完整的 `bootstrap-project-context/` 目录,保留入口,引用和 metadata.当前工作区的未发布改动应直接从当前目录接入,公共下载只包含已发布内容.

Codex 用户级发现目录是 `$HOME/.agents/skills`,Windows 为 `%USERPROFILE%\.agents\skills`.把完整目录放在其下,或保留独立实体位置并创建精确指向它的目录链接,不要产生两份编辑源或覆盖已有目录.其他 Agent 先核对自身发现契约.可见后输入 `$bootstrap-project-context`;未刷新时重启 Agent.参见 [Codex 安装说明](https://developers.openai.com/codex/skills#where-codex-loads-local-skills).

## 从这里开始

在目标项目工作区中发送:

```text
使用 $bootstrap-project-context,为当前代码库建立工程化 Agent 开发基线.检查已有任务,架构,日志,测试和交付文档,保留各自真源;生成简短 AGENTS 开发规则与按需读取入口,补齐三份项目文档.不要修改项目代码,生成后不要提交.
```

进阶用例:只校准已存在文档,无需重新初始化:

```text
使用 $bootstrap-project-context,按当前实现核对 docs/PLAN.md 和 docs/FEATURES.md.允许更新这两份文档:纠正失实能力,删除已验收完成的计划,保留未解决风险与独有证据.不建立新计划,不修改其他文件.
```

## 输入,成果与过程

输入是明确的项目根目录,目标与约束,当前实现和允许修改的文档范围.未确定的产品意图会保留为待确认项.

初始化目标是 `AGENTS.md` 与 `docs/PLAN.md`,`docs/FEATURES.md`,`docs/EXPERIENCE.md`.先检查指令入口与文档职责,判断基线完整,可补齐或冲突.完整基线返回 no-op;可补齐时按空项目或已有代码选择分支,先完成三份项目文档,最后补根规则,回读核对职责与链接.显式校准只处理获准文档,不自动补建四文件.详见[项目文档契约](references/project-document-contract.md)及[校准流程](references/explicit-calibration.md).

直接调用本 Skill 且未限定只读或校准,即授权补齐基线,无需再次确认.只处理项目文档,不启动软件开发或交付流程,不修改任何项目代码,测试代码,脚本,配置或依赖文件.仍遵守本次用户限制,更高优先级指令和宿主权限.

生成的 AGENTS.md 是简短的项目开发规则:按当前项目提炼范围,架构与关键行为边界,验证要求,再提供文档维护路由.可参考用户提供的规则文档组织表达,不照搬其他项目的事实或长篇复盘;已有有效规则保留,整体压缩须明确授权.

工程文档按职责协作:任务真源拥有计划与验收状态,技术/架构文档拥有边界和决策,日志/Bug/测试文档拥有诊断方法与证据,交付规范拥有相应操作要求.四份基线将这些入口连起来,按任务选择读取,不每轮加载全部历史.缺少专项文件时用必要短规则覆盖,不自动建立整套空模板.详见[工程开发工作流](references/engineering-workflow.md).

文档维护有进入和退出规则:无新的长期信息不写,同主题原位合并,已验收计划退出,经验按机制归并,当前规范与历史证据分开.新 AGENTS 以约 60 行短规则为参考,超过 100 行触发内容复核,不机械删减或合成长行.其他文档按重复,失效和职责混杂判断是否收敛;先合并再按独立职责及授权考虑拆分,不自动分卷或新建归档,保留未解决风险与独有证据.

建档不主动查询或操作 Git,也不要求先满足分支,暂存或远端同步条件.生成或更新完成后不自动暂存,提交或推送,这一边界也会写入生成的 AGENTS.md.需要版本管理操作时,由用户另行明确要求并作为独立任务处理.

使用无需 settings 或额外 Python 包.Agent 需要当前项目的文件读取能力;写入按任务授权.若要验证项目本身,采用项目已有入口与环境,不自行猜测命令.

## 限制与常见问题

- 为什么没有新建文件?四份文档已完整时保持不变;只读校准也不会落盘.
- 为什么停止建档?根 `AGENTS.override.md`,路径链接/大小写冲突,相互矛盾的职责或疑似敏感资料需要先处理;不能通过整篇替换绕过.
- 每次修复都要更新 PLAN 吗?不需要.后续计划由讨论确认后入档,普通局部实施不登记为长期计划.FEATURES 独立按主要能力和证据变化维护.
- 为什么保留当前名称?`bootstrap-project-context` 表达建立开发上下文与规则的起点,显示名称为“建立工程化 Agent 开发基线”.它建立或校准工程机制,不承接每轮功能开发;无需为名称扩展成通用开发总控.

已有静态检查和样例建档证据,本次 README 另核对内容与分发链接.这不证明所有宿主的自然触发,全新机器安装或自动校准质量;实际输出应逐项与项目证据核对.
