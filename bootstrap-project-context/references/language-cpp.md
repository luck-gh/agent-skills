# C++ 防御边界

仅为 C++ 组件建立或校准开发规范时读取.先核对语言标准,编译器选项,框架与现有异常策略,不从某个大型项目推导所有 C++ 项目都应禁用或启用异常.

- 外部数据经解析和受控构造建立对象不变量,内部依赖已成立的契约.类型不能单独保证原始指针有效,视图未悬空或长度算术无溢出;这些前提必须在对应所有权和使用位置成立.
- 使用项目已有的 RAII 资源封装与容器,区分拥有者和非拥有视图,避免手工释放路径遗漏.不为每个调用再建包装类,不在已有合适依赖外重写通用资源管理.
- 允许异常的项目在无法履行操作契约时按既有异常体系传播,只在有恢复或转换责任的位置捕获;不每层 `catch (...)`,不以默认对象掩盖失败.析构清理和异常传播约定须一致,需要上报的关闭/刷新错误由显式接口承担.
- 禁用异常或受限运行环境沿用项目的状态/错误返回方案,调用方处理失败和输出有效性;不能把异常示例直接搬入.采用 `expected` 等类型须先确认实际语言版本和已有依赖,不为范式偏好升级工具链.
- 保留边界长度,整数转换,对象寿命和并发正确性.断言可能被构建配置移除,不用于必须生效的外部验证;`noexcept` 不是吞错或防崩溃机制.
- 跨 C ABI,插件或硬件接口时明确资源所有权,错误表示与异常跨界限制;只为实际存在的接口定义规则.按失败路径核对资源释放与对象状态,不以编译通过替代行为验收.
