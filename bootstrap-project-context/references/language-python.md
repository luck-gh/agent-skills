# Python 防御边界

仅为 Python 组件建立或校准开发规范时读取.依据实际 Python 版本,已有类型检查与解析库提炼适用规则,不要求引入新依赖.

- 类型注解不执行运行时验证.外部 JSON,CLI,文件或仪器响应先按输入契约解析和校验,再传入内部代码;类型,范围,单位与必填项只在负责建立保证的层处理.
- 内部遵守类型和返回值契约,不重复 `isinstance`,不对保证非空的返回值加 `None` 兜底.合法的可选值应在契约中明确,按业务含义处理,不能用任意默认值掩盖失败.
- 只在具体外部操作边界捕获可预期的具体异常,缩小 `try` 范围,必要时带操作上下文并保留原因重新抛出.不写宽泛 `except`,不把程序错误当作正常空结果;用上下文管理器或 `finally` 保证资源释放.
- 若已用 Pydantic 等校验库,复用现有模型和版本支持的接口.是否允许类型转换由输入契约决定;不能一律开启严格模式或接受隐式转换.绕过校验的构造只能处理已有可靠保证的数据.可变模型被改写后,原验证不自动保证新状态;按实际变更入口维护不变量,不因此逐函数重复解析.
- `assert` 可在优化运行时移除,不得用于必须生效的外部输入校验.检查正常输入,具体解析失败及错误上下文,不为防御性分支制造不存在的内部状态.
