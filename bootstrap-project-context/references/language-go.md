# Go 防御边界

仅为 Go 组件建立或校准开发规范时读取.沿用项目实际 Go 版本,接口和错误处理约定.

- 外部解码成功只证明已执行的解析,必要的业务范围和必填条件仍在入口建立.使用现有类型与解析能力,不要重复验证已经保证的内部条件.
- 处理文件,网络和第三方 API 返回的 `error`;忽略返回值必须有具体且可证明的理由.只有契约允许缺失时才将 `nil` 作为正常结果,不返回伪造零值掩盖失败.
- 需要补上下文时保留可识别的错误原因,用项目已有的错误分类和传播方式,不靠字符串匹配任意错误.不要每层重复记录同一错误.
- `panic` 不作为普通输入失败的返回方式;`recover` 不用来吞掉程序错误并继续.已有包内部用 panic 实现控制流时,遵守其明确包边界转换契约,不推广到整个项目.
- 按资源成功取得后的所有权安排关闭,必要时检查刷新或关闭错误.有 goroutine 时明确退出条件和取消传播,不假定调用方超时就会终止后台工作;数据竞争不能靠重试或兜底值解决.
- 按实际风险验证错误传播,资源结束与取消路径;并发行为需要时用项目既有 race 检查入口,不为所有项目新增统一并发测试框架.
