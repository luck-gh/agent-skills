# C 防御边界

仅为 C 组件建立或校准开发规范时读取.识别目标 ABI,编译器,运行环境及现有驱动/平台规范;不将桌面库的恢复方法移植到中断或裸机场景.

- 外部长度,索引,数值和指针约定在入口建立,明确缓冲区容量,所有权与有效期.先检查尺寸运算的可表示性再计算分配量或偏移,保留越界,整数溢出,对齐和寿命方面的必要正确性约束.
- 内部已有明确且成立的前置条件时不逐层判空或补默认值.C 的类型声明通常不保证长度,有效地址或寿命;不得仅因签名含指针就视为已验证,也不能用判空证明任意非空指针有效.
- 按具体 API 契约处理可能失败的分配,I/O 和外设操作,明确错误码及输出有效性.不忽略必要返回值,不在失败后继续使用无效输出;统一清理路径只覆盖实际取得的资源,不吞掉主失败.
- `assert` 可能被 `NDEBUG` 移除,不能代替生产必须执行的输入校验或硬件失败处理.开发期不变量断言与运行时错误返回分清,不能仅为减少分支删掉内存安全要求.
- 涉及 MMIO,中断,DMA 或驱动时,遵守项目已确认的寄存器访问宽度,副作用,时序与所有权规则.轮询退出条件和超时以协议及运行约束为据,不虚构等待值.`volatile` 不替代同步,原子性或必要内存屏障.
- 生成规则保留目标相关的构建和验证层级:宿主测试,静态分析,仿真与实机各自说明覆盖,缺少目标硬件不能宣称实机通过.本次建档不执行驱动修改或设备操作.
