# 现有代码库基线

仅在项目已有有意义的源码,构建配置,依赖清单或测试证据时读取本说明.

## 检查到达时的真实状态

把现有说明,计划和历史验证结果视为有延迟的交接信息:它们用于定位证据,不能保证到达当前工作区时仍然成立.按以下顺序检查,保持范围足以建立项目基线:

1. 现有项目文档,根目录说明及其指向的任务或规范真源.
2. 依赖 manifest,lockfile,构建配置和工具配置.
3. 入口,核心源码,公共接口和关键数据流.
4. 测试目录,测试配置及已有验证命令.

逐项核对旧文档中可以验证的当前状态.工作区与旧声明不一致时,当前可验证状态优先;在目标文档职责内按公共契约最小纠正,并把差异列入交付.无法验证的意图,理由或未来方向保持为待确认,不要从代码反推为确定需求.

只使用环境中已经具备的依赖执行验证.运行前从项目配置和工具行为中识别命令可能写入的缓存,构建产物,快照或数据,优先采用项目已经支持且不改变验证语义的无缓存或无写入方式.只有在全部可能写入位置都能限定于项目内,且命令不会修改,覆盖或删除任何已有路径时,才可运行仍会写入的验证;所有可能生成的精确路径必须在运行前确认不存在,并建立覆盖这些位置及隐藏文件的前置清单.无法证明这些条件,需要凭据或无法安全运行时不要执行,按公共契约记录验证缺口.

验证后逐项对照预期路径的前后清单.只可清理清单证明为本轮新建,且项目或工具明确视为可丢弃的精确生成路径;清理前再次确认目标位于项目内.不得运行广泛清理,不得删除或覆盖预先存在的路径,也不得还原验证修改的文件.保留用户所有已有内容和改动,只允许运行写入范围可由上述清单完整覆盖的命令.如果命令违反前置判断而改变已有路径,产生清单外变化,或者出现无法归属或无法安全处理的新变化,停止后续文档写入并报告.

记录验证观察时按公共契约引用稳定入口或专项命令,并记录观察日期,退出码,适用范围和与结论相关的简要结果.

## 建立当前基线

按公共契约使用检查到的事实填充 `docs/PLAN.md`.从代码推断但尚未验证的结论必须明确标为待确认.

按公共契约路由当前能力和验证缺口,不要降低证据门槛.

按公共契约提取本次检查中可复用的经验,不要把初步印象当成证据.

把确认可复用的验证入口路由到 `AGENTS.md`.无法确认时如实标记缺口,不要猜测.
