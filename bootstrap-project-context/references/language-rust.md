# Rust 防御边界

仅为 Rust 组件建立或校准开发规范时读取.核对实际 edition,依赖及 panic 策略,不要假定标准库可用或所有 panic 都会展开栈.

- 外部输入使用已有解析器或受控构造建立有效类型,用 `Result` 表达可恢复失败,用 `Option` 表达契约允许的缺失.枚举,所有权和受控构造已保证的内部条件不逐层重复校验.
- 不对外部输入,文件或网络失败随意 `unwrap`/`expect`.仅当项目契约允许且不变量确实成立时使用,说明保证来源;不把 `panic` 当作正常错误返回,也不把所有程序错误包装成可恢复成功.
- `?` 只传播错误,在真正需要上下文的边界附加操作信息;不为每个函数套错误转换层.资源生命周期沿所有权与 RAII,需要报告的显式关闭/刷新失败仍按 API 契约处理.
- `unsafe` 和 FFI 单独核对指针来源,长度,对齐,寿命,别名,所有权及 ABI.类型签名不能证明外部调用满足这些条件;每个 unsafe 操作说明其安全前提由何处保证.检查空指针不能证明任意地址有效,不能用额外分支假装修复调用方违约.
- 明确 FFI 的错误和 panic 跨界约定,不让不支持展开的 ABI 意外承接 panic.按现有约定验证解析失败和相关边界;不把 safe Rust 的保证泛化到外部内存或硬件协议.
