# 需求与技术决策

仅在用户要求选型或授权内容确需技术决策时读取.普通建档,仅 GOAL 或只校准能力事实不自动进入此分支.

先从现有材料和用户请求确定使用者要完成的任务,输入,可观察结果及必要约束,再讨论实现手段.已有事实先查证,只询问影响决策且材料无法回答的问题;未知的性能指标或验收阈值保持待确认,不从参考模板填入数字.

仅在用户要求选型或本次授权内容确需技术决策时评估语言或技术栈,不因为整理文档而开展选型访谈.比较可行方案与推荐理由,重点取决于当前项目:目标运行环境,已有代码与依赖能否复用,维护者能力,生态维护状况,性能与互操作要求,部署和长期运维成本.重要选择核对官方资料或成熟实现,注明结论成立的前提与仍需验证的假设,不按项目标签预定语言.多语言方案须说明各自承担的实际职责,接口/构建/调试成本及单一语言是否已足够.

当前实现只说明事实,推荐方案仍是候选,用户明确的有效选择才作为决策依据.已有决定不重复提问;新选择交由用户决定,沉默不等于认可.待决项只阻断依赖该选择的定案,可继续整理独立的目标,文档职责与已知事实.决策和必要理由归已有架构真源,无专项真源时按公共契约归 PLAN,不另建决策台账或强制逐阶段审批.

定案前核对:只有愿景不从模板选语言,已有有效选择不重复确认,未回复的推荐仍是候选;所引用的成熟做法具备当前适用证据,不能仅凭 star 数或项目规模判为最佳.
