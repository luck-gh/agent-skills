# Agent 工程开发工作流

用于建立开发基线,或校准开发规范与文档分工.成果应让后续 Agent 从任务走到相关规则,实现,验证和事实更新;本 Skill 只建立这条工作路径,不执行其中的功能开发,排障修复或发布.

## 识别现有工程文档

先查看项目文档目录与标题,从根 AGENTS,README 和计划入口沿有效指针定向阅读.规范正文需要读全;历史记录只抽查与当前规则有关的证据.不要将整个历史文档库一次性加载,也不要仅凭文件名认定它是权威来源.

按以下职责核对实际承载位置.示例名称仅用于识别,不是强制文件清单:

| 职责 | 常见承载 | 需要确认的内容 |
| --- | --- | --- |
| 开发入口 | `AGENTS.md` | 不可破坏的规则,任务读取条件,验证与交付要求 |
| 目标与任务 | `PLAN.md`,`TODO.md`,任务系统或专项计划;迭代批次可用 `docs/GOAL.md` | 目标,优先级,验收条件与唯一任务状态归属;GOAL 沿项目既定入口,普通任务不加载批次目标 |
| 架构与决策 | `TECHNICAL.md`,架构说明,ADR | 模块职责,依赖方向,接口不变量,已确认取舍及适用条件 |
| 诊断与排障 | `LOGGING.md`,`TROUBLESHOOTING.md`,Bug 规范 | 可观察的输入到结果链,错误与未知状态,隐私边界,复现与根因验证方法 |
| 验证与证据 | 测试手册,项目测试入口,专项结果 | 前提,操作,预期结果,实际观察,失败判据与未验证范围;用例定义和执行结果分开 |
| 交付与来源 | 发布规范,安装指南,来源与许可证说明 | 交付物,授权,验收,失败处理与第三方来源;存在文档不代表获准执行其操作 |
| 当前事实 | `FEATURES.md`,`EXPERIENCE.md` | 能力及其可信范围,可复用实证结论;详细证据保留在原真源 |

现有文档可能兼任多个职责,也可能互相重复或过时.区分长期规范,已确认决策,任务状态,测试定义与历史结果:新的事实可以否定旧背景,但不自动撤销仍有效的设计选择.把重叠和矛盾按公共契约处理,不把参考项目的整套文档当成无条件正确的模板.

## 识别语言与防御边界

从实际源码,依赖清单,构建配置与已确认决定识别各组件的语言,版本,运行环境及已有错误处理约定.只核对与规则有关的配置,不要把偶然使用的构建脚本语言当作产品语言,也不猜未声明的版本或自动升级配置.新项目可沿用已确认语言,但尚未引入的运行时和依赖仍是待实施事实.

按 Skill 入口的语言条件选择引用,只读本次需建立或校准规范的组件.语言未决时不加载语言文件;未覆盖的语言从项目有效规范及对应版本官方资料定向提炼,无法确认的规则留作缺口,不套用相近语言.多语言按组件职责分别加载,数据跨进程,网络或 FFI 后重新核对保证,不假定两边类型定义相同就可信.

生成规则时对每个新增检查说明:输入从哪里来,哪层负责建立保证,失败如何显式返回,进入内部后哪些条件已成立.只在用户输入,外部文件,网络/IPC,第三方 API 或硬件响应等真实边界验证不可信数据;复用现有解析器,校验库与项目契约,不为边界检查再建通用包装层.

内部直接使用已经保证的条件,不重复判型,检查不可能状态,补兜底值或吞错.保证依赖可变状态或外部资源时,确认它在使用前是否仍成立;必要的状态同步和操作失败处理不能删掉.可恢复的预期失败按已有错误通道显式交给有处理责任的层,契约破坏尽早暴露.断言服务于开发期不变量,不能代替生产必需的边界验证;资源释放,内存安全,并发同步与组合逻辑完整性属于正确性要求.

只将当前项目适用的短规则写入根入口,专项细节沿已有规范按组件/任务路由.不把这些 Skill 引用路径写入生成项目,不因存在多语言就自动为目标项目新增一套规范文件.必要的新专项文档仍须在本次授权范围内;后续开发无需回读本 Skill.

## 筛选参考规则

参考项目或外部 Skill 只提供候选方法.迁入前说明它解决的问题,成立前提以及当前项目的适用证据;依据只是一次历史事故或旧实现限制时,先核对问题机制是否仍存在,不把补丁做法固化成普遍约束.当前规则已有等价覆盖时复用原条目,不重复添加.

保留能改变后续开发行动的机制,例如按任务读规范,验证根因和绑定实际交付对象;去掉原项目名称,技术组合,设备标识,固定等待时间和事故叙述.安装,提权,提交,发布与协作方式沿当前项目和用户授权,不能从参考材料继承操作权限.规则写入后应能在当前项目独立执行,不依赖原项目资料或外部 Skill 的运行时读取.

## 形成短入口与按需路由

在 AGENTS 中以短条目或小表写出“任务类型 -> 先读的实际文档 -> 必须满足的要求”.只列当前项目存在且有用的入口,不要让每轮工作都读取全部文档.规则的详细定义仍由原规范拥有,AGENTS 只保留不可遗漏的边界及指针.

- 日常功能修改:先读 PLAN 与对应任务真源;涉及模块,接口或关键行为时,再读相应架构/技术规范和验收定义.
- 非简单故障:先读排障与日志规范,取得复现和实际证据,提出能被观察推翻的根因假设,用有区分力的检查排除替代解释;最小修复后执行原始复现及受影响回归.只有需要持续调查时才按项目约定建立 Bug 记录,不为每个局部修复建档.
- 重要设计选择:先核对已有依赖和成熟参考,明确取舍与验收;语言和技术栈仅在入口所列选型条件成立时评估并由用户决定,其他设计沿已有授权更新唯一真源,不把候选方案写成已批准决策.
- 交付或部署:只在用户明确要求该操作时读取并执行对应规范,按授权渠道交付.本地验证完成不等于获准上传或发布;文档生成完成也不自动暂存,提交或推送.

未来开发的通用次序可压缩为一条:明确目标与验收 -> 按需读取约束,写入需指导实施的已确认规则或计划 -> 最小可运行修改并保证可诊断 -> 执行相关验证 -> 按证据收口受影响真源 -> 最终核对 -> 按授权提交或直接交付.要求提交时,文档收口在最终暂存及提交前完成,提交后只读核对与报告;不提交时在交付前完成必要更新.详细触发,提交后证据与范围限制按[公共契约](project-document-contract.md#更新时机与本轮收口),不要把这条次序变成要求每次先新建计划,设计或测试报告的固定手续.

## 按结果与风险定义验证

把目标写成使用者能观察的结果,并说明验证对象与环境.接口受理,编译成功,单元测试或模拟各自只证明所覆盖的层级;不能据此宣称实际用户路径或目标设备已经可用.缺少运行条件时保留验证缺口,不降低成功标准.本节指导生成开发规则,不扩大本次建档的执行权限.

按当前项目的实际风险选择必要检查,不要将以下场景变成所有项目的固定清单:

- 有界面或宿主集成时,在目标宿主,相关视口及真实交互路径上验证可见和可操作结果;静态预览不能替代宿主行为.
- 有异步任务,监听或外部资源时,明确创建者与释放责任,检查取消,重复进入及退出后的迟到结果是否改变失效状态;不照搬固定延时作为完成判据.
- 首次进入与恢复已有状态走不同路径时,分别定义前置状态与预期结果;一次成功不代表两条路径均已验证.
- 有打包,安装或外部交付时,核对被测对象与实际交付对象的版本,配置和身份,防止把旧实例或另一份产物的结果记为当前成功.

验收沿已确认的可运行纵向切片覆盖输入到结果,保持现有可运行路径.实际观察,失败与未验证项按原职责留在对应证据真源,不为上述检查新增固定报告体系.

## 文档所有权与生命周期

- 默认建立或补齐公共契约的四份基线.工程化程度按职责和工作路径是否清楚判断,不按文件数量判断.
- 已有任务,架构,日志,测试,Bug 或交付文档时,复用其职责和路径;AGENTS 建立任务读取入口,PLAN 保存方向与任务导航,FEATURES/EXPERIENCE 引用证据.不得把 TODO 复制进 PLAN,或把同一验收状态同时维护在多个文件.
- 专项文档缺失但短规则已经够用时,直接写入 AGENTS 或对应基线.关键事实不明时明确缺口,不编造日志系统,测试结果,发布设施或架构决定.只有用户已明确要求建立相关专项规范时才新增专项文件,按实际授权目标完成路径预检与回读;不为了模仿参考项目批量生成空模板.
- 复现,日志,实验过程与测试结果留在其原真源;已证实且可复用的结论归 EXPERIENCE,长期防错要求归相关规范,AGENTS 只保留必要入口.这些内容不应随每次工作重复追加到根规则中.
- PLAN 只删除自身已验收的活动条目;外部任务系统,TODO 或专项记录依各自契约关闭,不因清理导航而删除证据或宣称任务完成.

增长控制统一使用公共契约的进入,合并,退出和篇幅复核规则.识别工程文档时同时区分当前工作集与历史证据:根入口沿任务指向相应规范或主题入口,只有需要复核来源时才深入历史记录.冻结历史不会自动删除记录,也不要求后续任务每次读取它;不靠新增归档目录转移无限增长的问题.

## 可用性验收

用当前项目适用的请求作纸面走查,不执行功能开发或交付;不存在的场景标为不适用,不补造能力:

- 功能修改,故障修复,交付:能从 AGENTS 找到相关规范与验收,知道状态写回何处;授权,实施完成与验证通过不混淆.
- 重复修复,等效重跑,计划关闭:分别复用原经验,保持未变能力记录不动,移除已验收活动项;不生成重复报告,不删除独有历史证据.
- 提交与不提交:必要文档分别在最终暂存/提交前或直接交付前收齐;暂存后修改须重审并更新暂存,提交后只读核对.限定文件或已有暂存不扩范围,失败及等待 CI 的计划不提前关闭,遗漏沿已有后续授权处理.
- 条件加载:语言未知不套默认规则,单语言不读其他语言,多语言只覆盖相关组件;边界失败显式传递,内部保证不重复检查,必要正确性要求仍在.仅 GOAL,只读校准和完整基线 no-op 不被语言分支扩大范围.

回读根入口及实际指针,确认没有竞争状态,空模板,泛化口号或历史流水.纸面走查只证明规则衔接,不能宣称真实项目开发或独立 Agent 行为通过.
