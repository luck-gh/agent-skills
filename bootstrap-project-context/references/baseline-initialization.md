# 初始化状态与写入顺序

仅初始化或首次接管读取,与项目文档契约共同使用.显式校准和仅 GOAL 不加载本文件.

## 目标与基线状态

目标文档集固定由以下文件组成:

- 根目录 `AGENTS.md`
- `docs/PLAN.md`
- `docs/FEATURES.md`
- `docs/EXPERIENCE.md`

检查 `docs` 及四个目标路径的原始名称和原始路径类型.`docs` 必须是缺失或普通目录;每个目标文档必须是缺失或普通文件.任何大小写变体,目录占位,符号链接,Junction,reparse point 或 broken path 都是冲突.

在写入前读取所有已有目标文档并判定唯一状态:

- 完整:四份普通文件均存在且非空,各自承担项目文档契约定义的职责,`AGENTS.md` 提供简短开发流程,三份基线及适用专项文档的读取与更新路由,其中的指针可解析.没有独立专项文档本身不构成缺失.保持所有文件不变并报告 no-op.
- 可补齐:目标缺失,为空,或者现有内容与对应职责兼容但不完整.允许创建缺失目标,填充空文件,或只补充缺失职责.
- 冲突:`docs` 或目标路径类型不安全,文档承担不同职责,已有目标或约束相互冲突,或者无法在保留有效内容的前提下安全合并.在任何写入前停止并报告.

保留 `docs` 中的所有非目标文件和目标文档中仍然有效的信息,不要求保留每段历史原文.不得重命名,移动,删除文件或整篇替换来规避冲突.获准收敛文档时,可按项目文档契约的增长控制规则合并与删减正文,但不能消除尚未解决的冲突.现有目标文档的当前状态被更新且可验证的证据明确推翻时,不属于语义冲突;应在其原职责内最小纠正,并在交付中说明.涉及产品意图或证据不足时不得猜测哪一项过时.

## 写入与一致性验收

1. 在写入前完成所有目标路径,现有内容,语义职责和冲突检查.
2. 根据所选分支生成或补充三个 `docs` 文档,将每项信息路由到唯一权威位置.
3. 对目标文档执行反向一致性检查:新增和保留条目均符合入档条件,已完成且已验证的能力不再留作开放工作,失实描述已按职责纠正或移除,局部过程与已失效方案已收敛,重要未解决项及必要证据未丢失,文档之间没有职责重叠或事实矛盾,所有指针均可解析.
4. 按项目文档契约中的 AGENTS 要求核对开发规则具体且有依据,表达简短,文档路由完整,无自动提交规则,验证入口仍由当前配置支持.`FEATURES.md` 不把计划或失败验证写成成功能力,`EXPERIENCE.md` 不含未证实建议.执行敏感信息和衍生数值检查.
5. 先完成并回读三个 `docs` 文档,最后创建或补充 `AGENTS.md`,再回读四份文档.任何目标未完成时不得声称基线已经建立.
6. 本 Skill 不拥有的外部文档存在冲突时只报告,不得顺手修改.
