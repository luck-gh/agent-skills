# 空白项目基线

仅在项目中没有有意义的源码,构建配置,依赖清单或测试证据时读取本说明.这里的“空白”由实现证据决定,不要求目录刚刚创建.

## 建立计划

从用户请求和现有项目说明中提取已知目标与约束,并按公共契约填充 `docs/PLAN.md`.信息足以形成有效方案时,定义第一个可运行纵向切片及其工作项或任务真源指针,验收标准和主要风险.没有明确产品目标或关键输入不足时,不要发明切片;只记录阻塞性的开放问题和下一步需要用户澄清的事项.

预期依赖可以进入计划,但必须标为尚未引入.为第一个切片给出可验证的完成条件,但不要声称不存在的命令已经可用.

## 保持当前事实为空

`docs/FEATURES.md` 明确记录当前没有已实现并验证的能力,因为项目尚无实现与验证证据.不要把计划中的纵向切片复制为功能.

`docs/EXPERIENCE.md` 明确记录当前没有经过实施验证的项目经验.不要用通用工程建议填充空白.

`AGENTS.md` 中的稳定验证入口若尚未建立,应如实标记.它仍需包含公共契约要求的项目规则,三份文档的读取与更新路由,以及交接前的一致性规则.
