# 显式校准与纠偏

仅在用户明确要求判断项目方向是否偏离已确认目标,依据目标与证据更新指定项目文档,或收敛其中膨胀和陈旧的条目时使用.不读取空白或现有代码库初始化分支,不自动初始化完整基线,不承担常规润色或代码修复.

## 明确本次授权与比较基准

- 区分只读判断,更新指定文档,记录已确认纠偏.只要求审查或判断时保持只读;允许更新文档不等于用户认可改变目标,也不等于授权实施纠偏代码.
- 从请求确定目标文档与比较范围.先读有效项目规则,相关计划或专项真源,再按需检查源码,配置和已有验证证据.只校准某个文档时不强制全项目走查;工具和调查路径由任务决定.
- 列明已确认目标,非目标,验收标准和相关决策的来源.找不到足够基准时说明缺口并询问影响判断的关键问题,不得从现有代码反推用户意图.实现与计划不同也可能是已批准调整,先核对变更依据.

## 判断与证据

按受检范围给出无已证实偏差,有证据的偏差,或证据不足.分清文档陈旧,实现偏离既定目标和目标变更提案;分别说明事实,推断及未验证项.不把局部未发现偏差宣称为整个项目正常.

默认使用只读取证和可绑定当前状态的既有验证结果.确需执行验证时只使用已有依赖,先查清命令副作用;优先无写入模式.仍会生成文件时,全部精确路径必须位于项目内且预先不存在,不得修改任何已有路径;建立包含 ignored 文件的前后清单.无法限定副作用,需要凭据或授权不足时跳过并报告缺口.意外修改,清单外变化或执行结果无法确定时停止后续文档写入,不自动还原用户文件或广泛清理.正常取得的测试失败是偏差或验证缺口证据,不因此阻止安全且获准的文档校准,也不能写成成功能力.保留原 Git index 与所有已有改动.

基于当前证据提出最小纠偏建议,包含收益,受影响范围和验收办法.涉及改变目标,删除能力或放宽约束时,在确认前保留为提案;不得把自己推荐的方案写成用户已确认.

## 选择承载位置

- 仅文档事实陈旧:授权范围内在原事实真源最小修正,不强制建立纠偏条目.
- 文档膨胀或职责混杂:先按公共契约判断已有条目的入档资格,再更新或移除,不按长度截断或另建归档.删除局部或已失效描述不改变实际能力,也不代表问题已解决;符合项目级条件的未完成验收,独有证据和待确认选择仍须保留,其余未解决局部问题在交付或已有任务真源交代.仅整理文档不强制建立 CORRECTION 文件,也不要求 PLAN/FEATURES 成对修改;核对后没有必要变化时可交付不修改结论.
- 普通方向纠偏:仅符合项目级入档条件时写入 `docs/PLAN.md` 当前纠偏条目.采用公共契约要求的证据,确认依据,范围,旧决策,行动和验收信息,明确待确认或进行中;验收关闭后移除活动条目,不保留已关闭状态日志,不为每次检查新建文件.
- 复杂跨阶段纠偏:只有正文确实需要独立维护时才选 `docs/CORRECTION.md`,或复用已有专项真源.先确认写入范围包含专项文件和 `PLAN.md` 路由;若用户仅授权修改单个指定文件,请求范围确认,不顺手改其他文档.正文与状态只在专项真源维护,`PLAN.md` 只放定位及指针.
- `AGENTS.md` 只补充缺失且兼容的稳定读取,适用范围和关闭规则,且必须在本次授权范围内.不要每次纠偏重写它,不要记录当前问题细节,不要创建 `AGENTS.override.md`.

只有用户确认依据清楚,仍活动,适用范围和被替代旧决策明确的纠偏才能指导相关后续工作.文件名,出现时间或“优先阅读”均不赋予更高指令权限.没有确认的新建议不能取代旧目标,确认过的局部纠偏也不能覆盖当前用户要求,安全边界或无关规则.

## 写入与失败处理

1. 写入前固定授权文档集合,读取现有内容与各路径的有效指令.对所有目标及父目录检查原始路径:必须是缺失或对应普通文件/目录;拒绝大小写冲突,链接,Junction,reparse,broken path 或目录占位,不跟随或覆盖.已有同名专项文件职责不同则报告冲突,不整篇替换.
2. 按公共契约检查职责,确认依据,敏感信息与指针.保留有效内容,不创建未授权的缺失基线或新目录体系.候选的目标变更仍未确认时只标提案,不能更新现行目标为新方案.
3. 先写并回读事实或专项真源,再更新并回读指向它的 `PLAN.md`,如获准补充 `AGENTS.md` 则最后处理.没有依赖的指定文档无需机械套用整组顺序.任何部分失败时停止,列出已写与未写文件和待修复指针,不宣称事务回滚或全部完成.
4. 复核本次所有变更:事实与计划未混淆,确认与提案分明,旧决策替代范围明确,无重复真源,指针可解析,未改无关文件.未运行的验收如实保留,不因为文档已更新而标纠偏完成.

## 关闭与交付

只有获得与纠偏范围匹配的实际验收证据后才关闭纠偏.把长期决策更新到原决策真源;主要能力或可信范围变化且符合公共契约的更新条件时才更新 `FEATURES.md`,已证实经验按原职责归回 `EXPERIENCE.md`.只是恢复已声明行为时不强制补写能力记录;需要写入未授权文件时先请求确认.解除活动替代关系,按公共契约移除已关闭的活动条目,仅在仍影响当前工作时保留简短结论与证据指针.不自动删除专项文件或创建归档体系.仍有证据缺口时保持未关闭并说明原因.

交付校准结论及范围,关键证据,实际文档变更,待确认提案和未完成验收.只读审查可以正常交付而不落盘.提醒在恢复受影响工作前显式重读 `AGENTS.md`,相关 `PLAN.md` 条目及其活动专项真源;不自行唤醒,重启或广播到其他任务.随后停止,不继续编码或替用户接受新目标.
