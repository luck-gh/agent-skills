# 建立工程化 Agent 开发基线

为软件项目建立可持续指导 Agent 开发的工程规则与事实基线:明确每类任务先读什么,按什么约束实现,如何验证,结果写回哪里.本 Skill 负责建立这套规则和文档,不在建档后继续实施功能,也不创建单次会话 handoff.

## 先区分请求

- 初始化或首次接管:用户要求建立 Agent 开发规范,或直接调用本 Skill 且未限定只读,校准或仅建立 GOAL 时,即授权建立或补齐工程开发基线,不再询问是否建档.单纯讨论点子或只读了解代码库不触发初始化.
- 显式校准:用户明确要求判断项目偏航,依据目标与当前证据更新指定项目文档,或收敛其过时和重复条目时进入校准流程.不要求基线缺失,也不自动补建四份文档;只要求分析时不得写入.
- GOAL 建档:仅在用户明确要求建立或补充迭代目标文档时处理,默认项目根相对路径 `docs/GOAL.md`,显式路径或项目既定目标入口优先.按下方 GOAL 分支保留唯一真源;不把 GOAL 加入普通四文件基线,不启动迭代.
- 同时要求初始化与其他文档处理时先完成基线,再处理已授权目标.不能从一次 Skill 调用推断用户批准了新的目标或纠偏实施.

## 建档授权与写入边界

- 基线可补齐时,直接在目标项目创建缺失的 `docs/PLAN.md`,`docs/FEATURES.md`,`docs/EXPERIENCE.md`,填充空文件或补充缺失职责,最后创建或最小补充 `AGENTS.md` 的项目开发规则与文档路由.已有有效内容和用户已有改动必须保留.
- 本流程只负责项目文档,不启动软件开发或交付流程.补齐基线的授权不扩展到任意文档整理或显式校准.用户本次明确要求只读或另行限制写入时按其要求执行;更高优先级指令,宿主权限,路径与敏感信息门禁仍须遵守.
- 不修改任何项目代码,测试代码,脚本,配置或依赖文件,不安装或升级依赖.
- 本 Skill 只负责项目文档,不主动查询或操作 Git,不以分支,暂存状态或远端同步作为建档前置条件.生成或更新完成后不自动暂存,提交或推送;用户另行明确要求的版本管理操作,作为独立任务处理.

## 定位项目根并检查指令入口

按以下优先级确定项目根:用户明确指定的目标,当前上下文已明确的项目根,唯一的 workspace root,当前目录.只有按此顺序仍无法唯一确定目标时才询问用户.

仅 GOAL 建档时不创建或修改 AGENTS,按平台优先级采用实际生效的根级指令,包括普通 `AGENTS.override.md` 或当前上下文已明确加载的非标准入口,不扫描全局配置猜测文件名.读取前检查这些指令及其路径为普通文件/目录,大小写冲突,链接,Junction,reparse 或 broken path 时停止;合法 override 本身不阻断目标建档.

其他模式仍按以下规则检查根级入口:

1. 只用项目根直属的 `AGENTS.md` 与 `AGENTS.override.md` 判定根级契约,并按原始名称和原始路径类型检查.不得搜索父目录,子目录或全局位置来替代它.如果当前运行上下文已明确标出一个通过平台配置加载的根级非标准指令文件,停止并报告,不得创建会遮蔽它的 `AGENTS.md`;不要自行扫描全局配置猜测文件名.
2. 存在大小写不同的同名项,目录,符号链接,Junction,reparse point 或 broken path 时停止并报告,不得跟随或覆盖.
3. 根目录直属 `AGENTS.override.md` 会优先于待建或已有的 `AGENTS.md`,因此只要该原始路径存在就停止并报告.不得创建一个实际不会生效的根契约.

上述范围只用于判定根级契约.写入前仍须按平台优先级检查并遵守对实际目标文档生效的嵌套项目指令;例如普通的 `docs/AGENTS.override.md` 或 `docs/AGENTS.md`.合法的 override 优先级本身不是冲突.只有路径异常,无法唯一确定实际生效的指令,或有效指令与本次文档写入冲突时,才在任何写入前停止并报告.

完成入口检查后,完整读取本模式实际生效的根级指令及[证据与文档写入安全](references/evidence-and-safety.md).按下表选择本次模式,未命中的引用不读取;不要先扫描或加载整个 references 目录.

## 按模式读取

| 条件 | 加载与下一步 |
| --- | --- |
| 仅明确要求 GOAL 建档 | 只读[可选迭代目标](references/goal-document.md)及目标所需项目上下文,跳过下方初始化,选型与语言分支.不创建或修改 AGENTS |
| 初始化或首次接管 | 读取[项目文档契约](references/project-document-contract.md)与[初始化状态及写入顺序](references/baseline-initialization.md),判定完整/可补齐/冲突.完整只读 no-op,冲突在任何写入前停止;只有可补齐才继续下方初始化分支 |
| 显式校准 | 读取项目文档契约与[显式校准与纠偏](references/explicit-calibration.md),按实际授权目标预检,不读初始化分支,不自动补建四文件.只要求判断时保持只读 |
| 初始化同时附带校准或 GOAL | 先处理基线,再按已授权目标进入对应分支;基线完整只结束基线步骤,不能跳过附带请求 |

初始化可补齐时读取[Agent 工程开发工作流](references/engineering-workflow.md),识别文档职责与当前实现,再恰好选择一个分支:

- 没有有意义的源码,构建配置,依赖清单或测试证据:读[空白项目基线](references/blank-project.md).
- 已有上述任一实现证据:读[现有代码库基线](references/existing-project.md).

编辑器配置,许可证或孤立说明文档不构成实现证据.校准仅当范围包含开发规范或文档分工时读取工程开发工作流,只校准能力事实不进入它.固定四文件预检与整组写入顺序只用于初始化;其他模式沿实际授权集合执行.

## 条件加载技术与语言规则

只有用户要求选型或授权内容确需技术决策时,读取[需求与技术决策](references/technical-decisions.md).普通建档不自动展开选型访谈,已有有效选择不重复确认;候选与当前实现不能冒充用户决定,待决项不阻断独立的文档工作.

仅初始化可补齐或校准开发规范时,按工程工作流识别实际组件,语言及契约,再从下表选择相关引用.先完成识别再加载;语言未决不读,其他语言不读,工具脚本不因存在而触发其语言规范.多语言只加载本次规范涉及的组件,并核对跨边界保证.选型阶段只评估候选,不预加载所有候选的开发规范.

| 已核实正在使用或用户已选定,且本次规范涉及的组件 | 读取 |
| --- | --- |
| Python | [Python 防御边界](references/language-python.md) |
| JavaScript 或 TypeScript | [JavaScript/TypeScript 防御边界](references/language-javascript-typescript.md) |
| Rust | [Rust 防御边界](references/language-rust.md) |
| Go | [Go 防御边界](references/language-go.md) |
| C | [C 防御边界](references/language-c.md) |
| C++ | [C++ 防御边界](references/language-cpp.md) |
| Verilog 或 SystemVerilog | [HDL 边界](references/language-hdl.md) |

未覆盖语言从项目有效规范及对应版本官方资料定向提炼;没有依据的要求保留缺口,不套用近似语言.上述引用用于提炼当前项目规则,不是自动新增依赖,改配置或开展代码审查的授权.

## 完成与交付

- 生成 AGENTS 是短开发入口,保留项目硬约束,任务读取条件,验证与收口要求;语言细节按组件路由到已有项目规范,不复制本 Skill 的整套引用.缺少专项文档时必要短规则已足够,不自动批量建模板.本次建档不改代码的边界不得变成项目永久禁止开发.
- 按项目文档契约落实唯一真源,进入/合并/退出与篇幅复核,将必要维护要求写入生成文档.PLAN 只管理已确认计划及活动纠偏,FEATURES 只记录有实现与成功证据的主要能力;候选,失败和未验收项不能写成成功.本轮必要更新在交付前完成;后续获准提交时按契约先收口文档,提交后只读核对.
- 按所选模式完成预检,授权内写入及回读,保留已有有效信息和用户改动.部分失败停止并报告实际状态,不宣称全部完成.纸面走查不等于真实项目或独立 Agent 验证.
- 交付后结束,不继续编码或自动提交.纠偏不改变指令优先级,不自行创建 override,唤醒或广播到其他任务;受影响工作恢复前显式重读更新规则及活动条目.

交付简洁列出项目根,采用模式,基线状态或校准结论,实际读写范围,纠正与保留项,验证结果及待确认事项.
