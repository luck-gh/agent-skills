# new-skills

创建,安装,修改和验收 Skill 的统一生命周期入口.它把目标平台规则,物理存放位置,Agent 发现入口,内容质量和升级边界放在同一流程中,让改动形成可检查的实际成果.

适合新建或修订 Skill,修复发现问题,迁移安装位置,查询更新及获准升级.正常使用领域 Skill 不启动生命周期实施,但完成自动检查接入的安装会先运行轻量更新检查.

## 安装与发现

从维护者提供的分发包或现有工作区取得完整 `new-skills/`,保留 scripts,references 与 metadata.当前工作区的未发布版本应直接接入当前目录,公共下载只取已发布版本.

Codex 用户级目录为 `$HOME/.agents/skills`,Windows 为 `%USERPROFILE%\.agents\skills`.把实体目录安装为其中的 `new-skills`,或创建精确指向现有唯一实体的目录链接.先检查冲突,不覆盖未知文件或普通目录,不通过复制制造第二编辑源.其他 Agent 先核对自身平台发现契约.输入 `$new-skills` 调用,必要时重启刷新.参见 [Codex 官方说明](https://developers.openai.com/codex/skills#where-codex-loads-local-skills).

需要自动检查时,按 [安装与自动检查接入](references/update-installation.md) 完成更新初始化和宿主全局指令块.仅复制 Skill 或运行 CLI add 不代表接入完成.默认公共安装使用标准实体目录;自选磁盘路径保留完整 Git 仓库与 upstream,通过链接发现,以便复用 fast-forward 更新.

已有完整目录但不能发现时,可以请求:

```text
使用 $new-skills,检查当前 Skill 的实体位置和 Codex 用户级发现入口.我授权为缺失入口创建精确目录链接,但不覆盖已有目标.核对最终指向,报告冲突与尚未完成项,不要搬迁实体或升级内容.
```

## 创建和改进示例

```text
使用 $new-skills,在当前获准目录创建 summarize-build-errors Skill,用于从我提供的编译错误中定位根因和下一步检查.不运行构建或自动修改代码.先核对近邻能力,交付入口、必要引用和用户 README,完成 Codex 与内容验收,不提交 Git.
```

真实问题驱动的修改:

```text
使用 $new-skills,修复指定 Skill 在“生成文件”请求下只给建议的问题.先保留当前工作区版本和已有用户改动,固定正常用例与只读负例.实施最小修复,用相同输入验证实际交付和授权边界;出现退步时只恢复本轮相关改动.达标后停止,不要全库优化或自动提交.
```

只读审查可以明确要求安装/配置说明或 README 正文候选;此时不写 settings,不初始化,不检查远端更新或创建发现入口.

## 项目级创建与编辑

项目自有 Skill 默认保存在该项目的 `skills/<name>`,显式项目内路径优先;已有项目 Skill 在原实体目录编辑.这条路径不读取或写入 new-skills 的全局 settings,也不创建或更新用户级 `.agents`/`.codex` 发现链接.本轮可指定 `SKILL.md` 路径加载并调试,目录本身不保证宿主自动发现.已有系统级 Skill 仍按原位置和安装契约维护,不会因当前聊天位于项目中而搬迁.

```text
使用 $new-skills,在项目 <project-root>/skills/review-build-errors 创建 Skill,只分析我明确提供的构建日志,不运行构建或修改代码.交付入口、README 和必要资源,在项目内调试并完成验证.即使全局 settings 已存在也不使用它,不建立用户级发现链接,不提交 Git.
```

```text
使用 $new-skills,编辑现有 <project-root>/skills/review-build-errors/SKILL.md,补充日志缺失时的处理.保留已有改动,按项目级标准原地验证.本轮不迁移或安装到系统级.
```

项目级同样遵守命名,frontmatter,README,渐进加载,资源闭包,风格和验证标准.项目资料作为明确输入提供,事实留在项目真源;Skill 保存可复用方法及自身资源,不复制项目事实或暗中依赖父目录脚本.只有你确认项目及 Skill 调试成功,并另行明确授权提升到系统级,才进入迁移和发现接入流程;验证通过或仅确认成功不会自动提升.

## 设置,依赖与输出

系统级任务的当轮明确物理目录和使用目录优先;已有信息足够时不强制补配置.只有明确要求保存系统级默认值或缺少必要路径时,才按[设置合同](references/local-settings.md)使用同级 `settings.json`,字段仅为 `physical_root` 与 `usage_root`.两者相同时直接安装,不同才在授权内按宿主约定创建入口.项目级不使用这些默认值.参见[安全示例](settings.example.json);设置不是修改文件或链接的额外授权.

脚本基线为 CPython 3.12 / Windows x64.通用 validator 需要 PyYAML 6.0.2,精确来源,许可与 artifact hash 见[验收合同](references/validation-contract.md);其余工具按实际分支使用标准库,系统链接能力,Git 或受约束的 skills CLI.平台 initializer/validator 由目标平台提供,不假设每个宿主都自带 Codex 工具.不要求运行第三方 Skill 来改进本 Skill.

输出是实际修改的 Skill,必要 metadata/入口与验证结果.检查工具可以独立使用,在本目录运行,把目标占位路径替换为实体目录:

```text
python -X utf8 -B scripts/validate_skill.py --json <physical-skill-dir>
python -X utf8 -B scripts/check_content_style.py --json <physical-skill-dir>
```

工具只检查,不自动格式化或修复.通用校验涵盖入口,资源闭包,metadata,settings 结构和存在的 README 链接;风格检查保留代码/原文引用.平台验证与真实业务行为仍需分别完成.

## 修订与停止

固定当前工作区基线和成功标准,区分规则缺陷与输入/环境问题,完成一个可运行改动后对照真实成果.需要独立评审时匿名比较前后答卷,不让答题方看另一版答案.保留实际有效且无新增退步的修改;只涨分或更长不构成改善.恢复仅涉及本轮内容,并发归属不清时停止该段操作.达到目标,没有可检验新假设或达到用户预算后结束,不默认后台运行,无限迭代或提交代码.

README 面向使用者,SKILL.md 面向执行.项目要求的 README 应说明真实安装,调用和能力边界,但不能代替入口的运行规则或资源声明.通用工具允许无 README 的外部 Skill,本项目的分发验收要求每个实际 Skill 都有 README.

## 更新与限制

完成接入后,每轮使用这批已安装 Skills 时,宿主指令触发更新器.默认缓存成功结果 24 小时.同一会话已知尚未到期时直接复用;需要调用检查器时,自动缓存命中只读本机状态并返回简短结果,不扫描 Skills,查询 Git 或联网.到期才完整校验并联网检查;网络失败不延长缓存,下次使用再尝试.已知安装改变或需要立即刷新时可强制检查,实际升级始终重新校验.发现可升级版本后先完成当前工作,再询问是否更新.源码维护,项目级 Skill 和设计参考研究不触发该检查;用户明确只读,禁止联网或禁止状态写入时跳过.具体见[更新合同](references/repository-updates.md).

说“最近不更新,只检查”会保存 check-only 偏好:之后仍按期检查并报告,不再自动询问或升级,直到你明确恢复询问.没有明确期限就不猜天数;后来直接要求升级时可按本次授权执行.缓存命中不重复询问,也不会把拒绝升级记录成已升级.检查器不创建后台任务,24 小时到期后由下一次使用触发,无人使用时不会自行唤醒.

手工目录副本不自动纳入公共更新管理,公共模式要求指定来源,真实 CLI lock 与安装基线;Git 模式拒绝脏工作区覆盖.安装后必须立即检查建立基线,否则在远端改变后首次检查会因缺少基线而阻止覆盖.授权升级后,Agent 从目标版本发布说明确认改名,保留本机配置,完成新入口验证后再清理准确旧链接.

```text
使用 $new-skills 升级我已安装的 Skills,同时维护这些安装的发现入口.如果有明确的改名,保留本机配置,接入新名称并清理对应旧链接,完成后验证可读取.遇到内容或归属冲突先保留并报告,不要覆盖无关安装,不要提交或推送 Git.
```

公共更新器的 `retired` 和 `available` 只表示旧名退役和新名可安装,不自动构成改名关系.关系确认后由 Agent 安装并验收新名,完成旧安装交接,再用更新工具的 `retire` 收尾旧 lock 与基线.它不删除实体或链接.如果只更新了内容而入口,配置或记录尚未处理,结果必须写明安装未完成.具体操作与失败处理见[入口交接](references/junction-safety.md)和[更新合同](references/repository-updates.md).

验收区分静态检查,工具回归和 Agent 行为模拟.更新工具的离线用例覆盖同名升级,配置保留及改名记录收尾;独立模拟检查 Git/公共改名接入,只检查或只改源码,链接冲突,未知结果和缺少改名依据.这些证据不等于真实公共安装器与所有宿主的完整升级实测,也不证明并发恢复或所有机器兼容.
