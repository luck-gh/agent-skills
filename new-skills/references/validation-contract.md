# Generic validation contract

只在修改前需要行为对照,验证 Skill 或修改验收流程时读取本说明.区分静态契约,行为质量与领域逻辑,只执行本轮适用检查.通用 validator 接收明确的 physical skill dir,输出稳定 JSON,失败时不修改输入.

## Lifecycle acceptance

1. 核对核心触发和近邻排除,入口共同规则,明确的分支条件与完成标准;引用保留分支必要步骤,检查点,失败处理和验证.开放任务允许不同合理路径,高风险操作核对必须遵守的顺序.不用文件行数或字数替代语义验收.
2. 实施后运行下列通用检查,并运行目标平台声明的 validator.官方 OpenAI Skill 还需 `skill-creator` 的 `quick_validate.py`.静态通过只证明对应契约,不证明行为正确.
3. 本轮涉及领域逻辑时运行所属 Skill 的相关现有测试,并为已证实缺陷补必要回归.领域测试留在所属 Skill 内;不为纯文案,标题或已由 validator 覆盖的规则创建占位测试.本 Skill 的 `tests/` 覆盖 validator,风格,discovery 和更新管理工具,修改这些工具时运行相应测试.
4. 复杂或高风险变更在用户要求或风险确实需要且承载可用时独立复核.复核者获得原始需求,安全边界与质量标准,不接收实现方的预期结论.失败交回原所有者修复,不默认扩展为多轮评审.
5. Settings 变更核对显式输入优先,目标冲突,业务值与隔离分发;discovery 变更核对 exact target.仓库工具变更运行自身测试;完成时运行适用范围的 `git diff HEAD --check`.规划或只读任务遵守其不写入边界.

```text
python -X utf8 -B scripts/validate_skill.py --json <physical-skill-dir> [...]
python -X utf8 -B scripts/check_content_style.py --json <physical-skill-dir> [...]
```

## Focused behavior comparison

仅在用户要求对照,或本轮触发,加载,工作流变更需要行为证据时使用.不对未修改 Skill 重复整套模型测量,不建立逐 Skill 管理文档或通用评测框架.

- 修改前固定本轮相关的代表性输入,质量标准及版本,允许记录已知失败.危险操作只在隔离样例或模拟环境复现;修改后用相同输入与配置验证,范围内已确认缺陷必须消除.
- 覆盖实际改变的命中,近邻负例,分支读取,完成质量,失败处理和越界风险.模型对照使用用户已选择且实际可用的模型,记录模型与配置,使用独立上下文,不泄露前次答案.没有模型对照授权或运行能力时如实报告证据层级,不自动扩大为选型研究.
- 开放性样例按目标与质量标准判断,不要求复刻实现步骤或工具.正确的安全拒绝不是质量退化;也不以旧版失败为新版失败开脱.
- 先比较可靠性,质量与安全,再记录可获得的实际 token,调用次数,耗时和无关加载.没有真实用量只报告加载变化,不编造节省,不设强制压缩率.证据有波动时针对相关用例复测,不泛化为所有模型兼容.
- 区分真实发现,metadata 选择模拟与加载后行为回放.版本或哈希仅固定前后版本及规则切换,不逐次审计读取.

## Evidence-led revision

创建时把明确需求变成可验收的最小路径;修改时从真实失败,用户反馈或已确认的新契约出发.先区分 Skill 规则缺陷,输入不足,工具/环境不可用及执行未遵约,只把能由本 Skill 修正的问题写进它.没有可定位问题或新目标就结束审查,不以优化请求推导全库修改.

1. **固定基线**:保存本轮相关文件的修改前内容及已有未提交改动的边界,基线取当前工作区而非仅取 HEAD.固定代表性任务,近邻负例,必守约束和预期可观察结果;需要行为对照时在修改前取得答卷,不要事后重建成功基线.无可执行旧版时如实标明缺失.临时证据放在任务授权的临时目录,不默认向每个 Skill 写过程日志.
2. **有界修改**:围绕一个可解释的问题完成最小可运行切片,允许同步修改相互依赖的入口,引用,metadata,工具和 README.不强制每轮只改一个文件或评分维度,也不借相关性修改无关 Skill.对已证实失败明确触发条件,可执行处理与仍失败时的停止/报告,不为假想风险堆叠通用禁令.
3. **对照验证**:按前节保持相同任务,事实,工具条件和运行配置,比较实际成果与失败行为.修订内容应有可观察收益或满足明确新契约,同时保留必要能力与边界.静态合规,模拟决策和实际业务运行分别报告.可选的无 Skill 对照只用于判断该规则是否产生额外价值,不能替代旧版对照.
4. **独立复核**:本节不强制所有文案修改使用多代理;按 Lifecycle acceptance 的风险条件选择.独立答题方不看另一版答卷,评审方不参与实现或答题.评审在同次上下文中对照匿名的前后成果,使用预先固定的标准,获得必要原始事实和约束,不获得实现者预选结论或之前的评分.区分更好,等效,退步及证据不足,每项给出具体行为依据;顺序偏好或波动会改变结论时只复核相关案例.多评委意见不能抵销必守约束失败,自评分和多数偏好都不是实际效果证明.
5. **保留或恢复**:目标达成且适用验证无新增退步时保留.只涨分,只变长或没有对应问题的改动不保留;文档补全等明确新契约可以用内容和分发证据验收,不要求虚构行为增益.退步时先修正本轮问题,无法修正则仅撤销本轮引入的相关改动,恢复到进入本轮前的有效基线并回读验证.不自动 commit,stash,revert,reset 或覆盖整文件;恢复前发现同段并发修改或所有权不清时停止该恢复,报告冲突,继续不受影响的工作.证据不足的行为改进不标记完成或替换已验证的有效版本;保留已证明的独立修复并交代未决部分.
6. **停止**:原目标与回归已通过就结束.没有可检验的新假设,后续只重复既有证据,改动没有实际收益或已达到用户的时间/预算限制时停止本方向.只有尚未解决的具体缺陷和可执行验证才继续相关修订,不为凑轮数或评分开展无限优化,不自动后台运行,扩展到其他 Skill 或提交代码.

## Checks

1. 要求 Skill 根目录是名称合法的 physical directory,并拒绝运行时资源目录中的 symlink,Junction 和其他 reparse point.
2. 检查 `SKILL.md` 是 strict UTF-8 regular file,frontmatter 可解析,目录名与 `name` 一致,`description` 非空且符合通用平台长度边界.
3. 解析 `agents/**/*.{yaml,yml}`.若存在 `agents/openai.yaml`,检查 `interface` 的必要字段,`default_prompt` 中的 `$skill-name` 和图标资源闭包.`icon_small` 与 `icon_large` 始终相对 Skill 根目录解析.
4. 检查 `SKILL.md` 与一级 references 中声明的本地 Markdown 目标不逃逸且存在.每个 `references/**/*.md` 和 `scripts/` 下的公开 Python 入口都必须由 `SKILL.md` 中的直接 Markdown 链接声明.`[validator](scripts/validate_skill.py)` 是声明;fenced code,inline code 和完整命令均不是声明,即使命令带参数且包含该路径.`src/` 内部模块只做物理边界和静态源码检查.
5. 若存在 `settings.example.json` 或 `settings.json`,检查 example,同级 `.gitignore` 的精确 `/settings.json` 规则,UTF-8,2 空格缩进,逐字段换行,末尾换行和 settings 的 unknown 顶层字段.
6. 对 `scripts/` 和 `src/` 下的 Python 读取源码并静态编译,不导入模块.拒绝源码字符串中显式 `_dev` 路径段或带分隔符的父目录路径段,避免兄弟 Skill 和仓库级隐藏运行时依赖.

存在的顶层 README 也检查普通 UTF-8 文件及本地链接,但不要求由 SKILL.md 引用它,也不接受仅在 README 声明的运行资源替代入口声明.通用 validator 不替所有平台强制要求 README;项目若要求每个 Skill 配备它,由项目分发验收核对覆盖.README 的本地链接限 Skill 自身,外部安装文档或许可证使用明确 URL,保持单独分发后的可读性.内容风格检查涵盖存在的 README,沿用代码和引用排除规则.

## Non-goals

- 不运行 initializer,领域入口,领域测试,网络请求或 discovery 写操作.
- 不判断 settings 业务值,凭据可用性,外部服务状态或动作授权.
- 不判断触发语义是否完整,正文内容是否常驻必要,或引用内容是否只在条件命中后需要;这些由 `SKILL.md` 生命周期流程结合具体用例人工验收.
- 不替代目标平台 validator,语言类型检查器或领域测试.
- 不要求目标 Skill 创建 `tests/`,也不把 tests 当成运行时资源.

## Runtime dependency

Validator 使用 PyYAML 6.0.2 解析 YAML.来源为 [PyPI](https://pypi.org/project/PyYAML/6.0.2/),license 为 MIT.当前验收平台的 artifact 是 `PyYAML-6.0.2-cp312-cp312-win_amd64.whl`,SHA-256 为 `7e7401d0de89a9a855c839bc697c079a4af81cf878373abd7dc625847d25cbd8`,运行边界为 CPython 3.12,Windows x86-64.其他平台必须选择 PyPI 对应 6.0.2 artifact 并核对其哈希.不要自行实现 YAML parser.

独立分发保证 `new-skills` 自身文件和资源闭包完整,不 vendoring PyYAML.隔离副本验证使用宿主已经提供并核对为 6.0.2 的 PyYAML;这证明副本不依赖兄弟 Skill 或仓库运行时代码,不证明第三方依赖自包含.

## Output and exit codes

必须使用 `--json`.成功与契约问题都输出 `schema_version`,`status`,`checked_skills` 和 `issues`;调用输入错误另含 `error`.

- `0`: 所有 Skill 通过.
- `1`: 至少一个 Skill 存在契约问题.
- `2`: CLI 用法或 physical skill dir 输入无效.
