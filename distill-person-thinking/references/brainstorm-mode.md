# 思维风暴

本模式把同一问题交给互补的已蒸馏方法,通过比较和反驳改进方案.人物只是方法来源,输出是当前 Agent 的分析,不模拟本人开会或生成内部思维逐字记录.

## 1. 固定共同问题

只有入口所述显式请求才进入.先从当前对话确定要解决的问题,行业或使用环境,可用资源,硬约束,时间尺度以及什么结果算好.用户只给行业时,优先沿用当前对话的具体决策;没有可辨认目标时只询问要解决的关键问题,不擅自替用户决定投资或创业目标.

用一份简短的共同事实底稿区分已知事实,用户假设和关键未知.涉及最新市场,政策,技术参数等必要事实时由主 Agent 定向核验并共享结果;人物 Sources 不是当前事实库,不要求各视角重复打开其原始出处.不能核验时保留未知,不得把风暴推断升级为事实.

事实标注必要的来源,时间,单位和口径.历史时点问题只能使用当时可获得的信息;同轮新增事实由主 Agent 同步给受影响的视角,不能让不同视角分别基于不同版本的事实互相反驳.

在看到各视角结论前确定比较标准.优先采用用户给定的硬约束和成功标准;缺少非关键偏好时说明合理假设并继续.常见维度是目标贴合,证据支持,成本与可行性,失败代价及可验证性,只选与当前问题有关的维度.

## 2. 选择互补视角

复用[推荐流程](recommend-mode.md)中的来源选择,身份和外部 frontmatter 有界检索规则,但本模式的数量及继续执行规则以本节为准.默认 3-5 个人物,每人选 1-2 个直接相关的具体模型.仅有两个合适视角时用两个,不凑人数.明确指定人物时尊重该集合;需要更多视角时说明每个新增视角的独立用途,大集合分批处理.

- 从[索引](model-index.md)导航,按任务与方法筛选,排除条件先于相关性,再核验所选模型的 frontmatter 和正文.领域相同不代表方法互补;不能用五个相似的价值投资视角冒充五条独立证据.
- 通常覆盖机会或生成方案,现实或工程约束,风险或反证中的相关角度.这是选模启发,不强制给每道题安排固定人物或机械配齐角色.
- 跨领域问题先拆关键约束再选人.例如 AI 芯片方向可能需要架构与性能,制造与成本,软件生态,客户需求及失败风险;按当前瓶颈选择有适用模型的视角,可由一人覆盖两个有关问题,不为配齐人数把无关人物拉进来.比较研究路线时区分学习范式,数据,算力和验证条件,不能仅按 AI 从业身份选模.
- 只加载入选人物,不得遍历全部人物正文或默认打开外部资料.外部优先,内外不混拼,路径检查与冲突处理遵循入口及[使用流程](apply-mode.md).
- 对每位写明人物身份,具体模型 ID 与此次要审查的角度.跨分类,中文名和英文别名先按入口核实为同一 person_id,每个人物只计一个视角,同一文件只加载一次;同人的多个模型不冒充多个独立视角.传递内置 person_id,模型 ID,来源和索引精确路径,不从 ID 拼文件名.缺失,不适用或证据不足者明确排除;用户限定的人物不可擅自替换.未经蒸馏的候选不能凭记忆上场.
- 合格视角不足两个时说明无法完成多模型比较,可交付已有视角的有限结果及缺口,不得称风暴已完成.新增或修复模型另需蒸馏请求.

## 3. 独立首轮

有可用且获准的子代理工具时,每位子代理收到相同问题,事实底稿,评价标准,自己的精确模型文件或必要正文,以及以下输出要求.不附主 Agent 的预选答案或其他视角结论;能选择上下文继承时采用最小上下文.按可用并发槽分批,主 Agent 也可承担一个尚未看见其他答案的视角.不为风暴创建用户侧独立任务,不指定未获授权的模型升级,不调用不可用工具.

没有这种工具或并行权限时,明确说明采用单 Agent 多视角推演,分开生成各视角的摘要后再比较;不能把它宣称为独立多 Agent 评估.无论执行载体如何,不要求展示隐含推理链,只输出结论,关键理由,事实依据和可检查步骤.

每个视角返回精简的决策摘要:

`人物 / 模型 | 建议方向 | 支持事实与关键假设 | 主要风险或反证 | 最小验证动作 | 什么结果会改变判断`

每个视角都回答同一问题,遵守同一约束,不能改题以显示人物特色.不得用名言或语气填充分析.子代理只分析,不修改模型,不执行方案或自行继续委派.失败或超时者标记未完成,主 Agent 可在如实说明后补做该视角,不能伪造其结果.

## 4. 碰撞与修订

主 Agent 汇总首轮,找出最影响选择的 1-3 个真实分歧,区分事实分歧,预测或假设分歧,以及价值取舍.没有实质分歧时如实说明,改查共同盲点,不编造争吵.

每个关键分歧保留 `分歧类型 | 相反判断与各自前提 | 当前证据 | 能区分判断的验证 | 什么结果会改变选择`.事实分歧定向核验,假设分歧设计区分性实验或情景,目标取舍回到用户标准;不能用补更多新闻代替用户的价值选择.

将相关视角的摘要交给对方,要求先按对方可接受的方式复述其最有力理由及成立条件,再指出方案最薄弱的假设,给出能区分两种判断的证据或小实验,最后明确保留,修订或撤回哪些建议.涉及人物方法依据或具体历史案例的实质分歧时,主 Agent 按[使用流程](apply-mode.md)只读相关本地来源笔记,共享支持范围和未知;不让各视角重复读全部笔记或网站.笔记未覆盖的事实仍待核验,目标取舍不靠增加来源解决.模型一致同意不是独立事实证据;同一底层模型,原始材料或假设造成的相关错误仍可能存在,不同笔记不自动构成独立证据.

默认一轮交叉质疑.只有一个可补证的关键分歧仍会改变选择时,再做一次定向核验或修订,通常不超过两轮;用户明确要求深入时可扩展,仍需停止条件.没有新证据或可检验的新区别就停止.无法解决的争议进入最终限制或分支条件,不通过投票消除.

## 5. 比较与选择

先展示各视角的关键差异与碰撞后的变化,再整理成少量可执行选项,通常 2-3 个.可以组合互补部分,但要说明为何相容;互斥的预算,时间和风险前提不能强行拼成一个综合方案.在不行动或先验证是现实选项时,把它纳入比较.

用共同标准给出定性对比,每个优劣说明依据.没有测量时不编造匹配分,成功概率或收益率.先排除违反硬约束的选项,再比较余下方案;不能按人物名望,Star 或赞成人数决定.

分别判断模型适用性,方案证据和行动权限,不要压成一个总分:

| 情况 | 本轮处理 | 继续条件 |
| --- | --- | --- |
| 模型超出适用范围 | 排除此视角对此问题的判断,不当作反对票 | 找到已有且适用的方法,或另获蒸馏请求 |
| 已证实违反硬约束 | 排除该方案,同时保留其他缺口 | 修改方案使其满足约束,或用户明确改变约束 |
| 关键输入缺失,无效或无法核验 | 待核验,交付有条件判断及最小补证动作 | 取得同口径且足以区分选项的证据 |
| 关键前提已满足且无硬约束冲突 | 纳入可选方案比较 | 仍需按目标比较代价,不自动成为首选 |
| 本题仅要求分析,没有实际行动请求 | 完成分析即可,不创建执行事项 | 后续行动必须有对应授权 |

同一方案既超预算又缺成本明细时,首先排除并保留两项原因,补齐明细不会自动解除预算冲突.未知不是零风险或中性判断,资料不足也不等于方案被证伪;布尔值,非有限数值和单位不明的值不能充当测得成本.一个方案被排除不意味着其余方案均不可选,只在整体组合共享受限资源时检查组合约束.用户只要讨论时不能因没有执行资料而阻断讨论.

将仍成立的少数反对意见转成 `可观察信号 | 会影响哪个前提 | 出现后重查什么选择`.信号必须来自模型条件或本题证据,不能用流派默认阈值冒充人物标准;不自动创建后台监控.

- 默认自动选择: 给出首选和理由,说明放弃其他选项的关键代价,适用条件以及会使结论改变的证据.如果证据不足以选长期方向,可选择最有信息价值的小实验,而不是假装已经找到了确定答案.
- 用户明确要参与或保留选择: 先完成上述分析,交付可供选择的方案,说明 Agent 的倾向,集中询问真正影响选择的偏好或请用户选项.在答案到来前只停在该决策点,不把沉默当选择.用户选择后据此输出完整方案,复用已完成分析,仅在目标或事实改变时重跑相关视角.

最后交付所选方向,关键依据,保留的反对意见和下一步验证或行动安排.风暴是分析授权;实际写文件,发消息,交易,部署等动作按原任务已有授权判断,不得因选出了方案就扩大权限.

## 完成检查

- 触发来自显式运行请求,问题与共同约束可辨认,所用模型均有真实文件和适用方法.
- 至少两个合格视角完成了首轮,执行载体与未完成项如实标明,没有冒充本人或独立代理.
- 对比能指出实质差异,修订和仍未解决的分歧,选择有依据且不违反硬约束.
- 自动选择已给出可行动结果;用户保留选择时准确标为待选择,答复后继续完成方案.
- 没有读取全库,反复研究人物出处,写入人物模型或执行未授权外部动作.
