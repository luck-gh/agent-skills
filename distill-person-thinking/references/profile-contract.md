# 人物模型合同

## 一个完整人物文件

每个人物在同一来源集合中只保存一个完整核心 Markdown,同一文件可包含多个具体思维模型.内置公开模型位于 `models/思维模型_<常用名>.md`,常用名按[入口命名规则](../SKILL.md#人物身份与文件定位)选取并转换,不直接照抄 person 字段;外部用户成果保留 `<profiles_root>/<slug>.md` 的现行规则.本次采用的外部材料按[来源蒸馏规范](source-distillation.md)另存方法与案例笔记,核心仍须独立可用;来源笔记不是另一份人物档案.

内置 frontmatter 必须声明 lowercase hyphen-case 的稳定 `person_id`,现有人物沿用原英文 slug.文件名和展示姓名只用于定位与呈现,不生成或改变身份.外部既有文件继续按入口的 `person`,`aliases` 和已有文件位置核实身份;没有 `person_id` 不因此拒读,不自动补字段或改名.外部若已声明 `person_id`,必须与已核实人物身份一致.

更新沿用已有身份和精确文件位置.内置模型运行时只读;普通运行中要求更新内置人物时,在明确的外部资料库建立用户版本.用户明确要求维护本 Skill 并收录或修订公开模型时,允许在该次维护范围内修改 `models/` 并同步索引,仍遵守本文件的证据,标签和单文件规则.不得自动修改内置集合或其他人物.

## 文件内容

主体必须是已吸收成形的可执行人物思维方法,包括看问题的角度,判断步骤,需要观察的信号,适用场景与失效条件.不能只交付来源列表,待办或上游索引.采用以下结构;其中 `person_id` 为内置必填字段,不作为拒绝读取既有外部文件的新增条件:

```markdown
---
person_id: <稳定人物-id>
person: <规范姓名>
aliases:
  - <常用别名>
research_cutoff: YYYY-MM-DD
scope: <本模型覆盖的主题和时期>
models:
  - id: <稳定模型-id>
    name: <模型名称>
    summary: <一句话检索摘要>
    domains: [<受控领域标签>]
    tasks: [<受控任务标签>]
    methods: [<受控方法标签>]
    use_when: <适用场景>
    avoid_when: <排除条件>
---

# <人物>思维模型

## Best used for
- <适合的任务>

## Do not use for
- <不适合的任务>

## Core models

### <稳定模型-id>: <模型名称>
- Definition: <可区分于通用常识的判断结构>
- Use when: <触发场景>
- Procedure: <如何用它分析或行动>
- Signals: <需要观察的事实或信号>
- Evidence: S01, S04
- Limits: <失效条件,反例或代价>
- Confidence: high | medium | low

## Decision heuristics
- <场景> -> <规则> -> <停止或复核条件> [Sxx]

## Tensions
- <两个会发生冲突的原则及其适用条件>

## Unknowns
- <资料不足或不可可靠外推的领域>

## Sources
- S01: <本地来源蒸馏笔记链接,原材料日期及支持的方法>
- S04: <本地来源蒸馏笔记链接,原材料日期及支持的方法>
```

模型数量由证据与用途决定,不凑数.仅将影响使用的背景或观点变化写入相关模型的范围,局限或张力;不附研究日志,案例评分记录或长篇生平.

检索字段遵循[模型标签契约](model-tags.md).每个检索项对应一个实际核心模型,保持稳定 ID,摘要与正文范围一致.人物身份,模型方法与检索标签在同一文件内维护.

## 简短出处

蒸馏时核验材料并按[来源蒸馏规范](source-distillation.md)吸收方法与案例,在同文件末尾的 `Sources` 小节保留简短说明与本地笔记链接,原始网页地址和阅读范围保存在笔记中.既有未补笔记的出处仍可直接链接网页,普通使用不因此重做研究.编号在人物范围内唯一且保持绑定,不引用不存在的编号或文件;新建/新增证据的验收不能用仅有 URL 代替应完成的蒸馏笔记.

人物核心不附社区项目索引或设计参考链接.复用研究的地址,版本及比较记录放在 Skill 之外不公开分发的维护资料,可按项目契约纳入私有版本管理;版权通知按许可证要求随包保留.人物原始材料的标题,作者,日期,已读范围和必要定位继续保存在来源笔记中,不能把社区推测写成本人明确立场.不将原始语料和完整访谈复制进模型.

## 更新与验收

- 新证据强化模型时补必要出处;限制或冲突时修订适用范围,局限和置信度,删除已不成立的结论.
- 保存前完成核心与本次来源候选,检查身份,模型步骤,标签与正文一致性及证据绑定,执行蒸馏流程的相关行为检查.来源笔记提炼的新取舍,关键反例和改判条件须回写相关核心,不能只更换链接.
- 内置验收核对 `person_id` 的格式及唯一性,结合 `person` 和 `aliases` 排除人物重复,同 ID 对应不同人或同人使用不同 ID.外部身份核验遵循入口规则,不能仅凭同名认定同一人物或自动合并冲突.
- 只调整内置文件名或导航时,保留 `person_id`,全部 `models[].id`,方法正文及来源绑定;同步索引,来源笔记文件名与双向链接,不留下旧文件副本.核对文件名不含中点,通行中文名与英文别名仍定位同一人物.跨分类重复引用同一人物文件不构成人物重复.
- 按来源蒸馏规范先保存并回读笔记,再保存主文件;最后精确回读本次所有受影响文件,核对相对链接,person_id,source_id 与 supports 中的模型 ID,全部一致才报告完成或应用新版本.
- 写入或回读失败,结果未知时停止使用不一致的本次版本,报告精确文件及已确认状态;按来源蒸馏规范核实和恢复本次修改,不自动覆盖其他文件.普通使用既有完整核心无需补建笔记.
