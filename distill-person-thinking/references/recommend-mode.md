# 根据当前对话推荐

## 从任务定位模型

只在用户显式调用本 Skill 且要求推荐时进入.用当前对话中的目标,卡点,约束和已否定方案,概括一句当前要解决的问题.不读取其他任务历史,不推断用户人格;对话已经充分时直接匹配.只有缺失任务会影响候选时才问一个必要问题.

1. 按标签契约映射领域,任务和思考方法.排除条件优先于正向匹配;以任务和方法匹配为主,领域用来限制外推.
2. 读模型索引的按人物与按领域导航.领域分类只是现有标签和具体范围的中文浏览视图,不意味着整个人物都适用;索引只提供检索提示,权威值在核心 frontmatter 和正文.内置按索引精确中文文件路径定位并核对 person_id,不能用英文文件名过滤器排除它.不因进入某一分类就加载全部人物,不打开所有上游链接.
3. 当轮提供外部 `profiles_root`,或同级 settings 存在时,按入口规则核对.本次推荐允许只读枚举该根单层的核心 `*.md` frontmatter,不递归进入 sources;英文 `<lowercase-hyphen-slug>.md` 文件名过滤仅用于这个既有外部契约,每个文件先预检.外部无 person_id 时仍按入口既有身份规则处理,不补字段或改名.没有配置时使用内置集合,不为了推荐要求建库.配置无效时说明外部集合未检查,仍可交付明确标注为内置的推荐;不得声称搜索了全部本地模型.若用户明确限定外部库,则不能用内置项代替.
4. 核对摘要的必要字段,身份和模型 ID 唯一性及受控标签;格式无效的外部文件报告为未索引,不猜测内容.先按入口核实人物身份,跨分类按内置 person_id 合并人物,按 `(person_id, models[].id)` 去重具体模型;外部匹配与冲突也按入口处理.再挑选最相关的 1-3 个具体模型,同一人物文件只加载一次.未指定来源时选择匹配的完整外部版本,不混拼内外内容;已匹配外部版本损坏或冲突时报告,不能改用同人物内置项掩盖,可继续检查其他合格人物.
5. 只读取入选模型所在的人物核心文件,按使用流程核对方法,范围与标签的一致性.来源笔记不参加检索排序,仅推荐时不加载 sources.不合格项排除并报告,不能标记可用;可继续检查下一个相关候选直到找到最多 3 项或候选耗尽.不做无关人物研究.

排序采用可解释的顺序:排除条件 -> 当前任务与方法的直接匹配 -> 证据完整且已有文件 -> 领域贴合 -> 与其他候选互补.不编造百分比匹配分或精度承诺.一个适合的模型就推荐一个,没有适合项就直说.

## 可用状态与交付

- `可用 / 内置` 或 `可用 / 外部`:完整人物模型文件已通过本次核对,可在所述范围内应用.这不是对人物全部观点的认证.
- `待核验 / 社区候选`:索引只有上游线索,尚未达到本 Skill 的原始证据和文件合同.可以提示后续蒸馏方向,不能代替可用模型.
- 未索引,模型正文缺失或身份冲突的外部项说明未纳入原因,不得凭记忆补写.

默认合计最多展示 3 项,可用项优先;只有没有合适可用模型或用户要求扩展时才展示社区候选.每项写明:

`人物 / 具体模型 | 可用状态 | 对应当前对话的理由 | 可以怎样切入 | 主要局限`

推荐理由必须挂钩对话中的具体问题,不要只复述标签.候选切入是一句话操作建议,不是替用户执行整项任务.仅推荐时到此结束;同一请求已授权选择并应用,则选最贴合的一项进入使用模式.社区候选先补蒸馏和证据核验,不能靠自动安装跳过.
