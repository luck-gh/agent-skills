# 使用模式

## 1. 定位人物模型

按入口的来源选择,人物身份与每文件预检规则定位唯一文件.内置沿用索引精确的 `models/思维模型_<人物常用名>.md` 路径并核对 person_id,不从英文 ID 拼出文件名;外部沿用已匹配的 `<profiles_root>/<slug>.md`,二者不可混拼内容.从推荐或风暴进入时传递已核验的人物身份,具体模型 ID,来源与精确路径.同一内置 person_id 的文件正文只加载一次,跨分类和多个别名不造成重复读取.

- 没有匹配: 报告尚未蒸馏,询问是否进入蒸馏模式.
- 多个匹配: 列出最少候选信息,让用户确认人物.
- 文件缺少必要范围或模型字段: 报告文件不完整,不要凭模型记忆补写.

当前人物文件本身就是完整可用模型.检查人物身份,模型步骤和适用边界;文件内使用来源编号时确认可在同文件 Sources 定位,不为普通使用逐一读取来源笔记.已有完整模型不因未补笔记而拒绝使用,也不在每次使用时重做研究.已发现的悬空链接要报告,不得声称已读取该证据;是否继续取决于当前结论能否由完整核心支持.

若模型正文缺失,内容矛盾或已知写入状态仍未核实,说明具体问题并停止应用本次版本.使用请求本身不授权修改人物文件,不以记忆补写缺失模型.

## 2. 判断任务是否适用

把用户任务与人物文件中的 `Best used for` 和 `Do not use for` 对照.若不适用,直接解释原因,并可在不冒充人物的前提下完成普通任务.不要为了体现人物特色而强行套用无关模型.

## 3. 选择并运行模型

1. 从人物文件中选择最相关的 1-3 个模型,避免把全部模型堆进一次回答.
2. 使用每个模型的 `Use when`,`Procedure`,`Signals` 和 `Limits` 执行真实任务.
3. 区分人物明确表达过的原则与基于模型对新问题的推断.
4. 从所选模型的 Procedure,Signals 和 Limits 推导本题需要确认的问题,事实及改判信号.先用用户材料和已核验的共同事实回答,只调查仍会改变判断的未知;纯框架问题或已有充分事实不机械联网.若任务依赖当前事实,先独立核对最新事实,再使用人物模型分析.人物文件不是事实数据库.关键输入缺失时给有条件判断或最小验证动作,不从人物偏好补造数据.
5. 当模型之间产生冲突时,展示关键取舍,由当前任务目标决定采用哪一个.

### 将方法转成可回答的问题

不列一份与模型无关的通用调研清单.对会影响本题结论的步骤,写出 `模型条件 -> 要回答的问题 -> 需要的事实及口径 -> 现有支持/关键未知 -> 什么结果会改变建议`.可以在简单问题中压缩呈现,但不能省略关键未知及其后果.

例如平台采用问题,若所选模型要求检查互补生态,就询问用户在哪一步无法把技术能力转为实际采用:缺开发工具,迁移成本过高,没有可验证的应用收益,还是性能达不到任务要求?按现有数据定位阻力,再选一个能区分解释的试验;不能因为模型来源人物经营硬件公司就默认继续堆硬件.投资周期模型若关注预期差,应区分当前基本面,市场已计入的假设与偏离这些假设的信号;流派名称不能替代模型自己的时间尺度或失效条件,本 Skill 不生成无出处的仓位阈值.

事实底稿至少区分观测/报告所属时间与实际可获得时间.回放 6 月 30 日的决策时,7 月才公开的 6 月报告不能进入当时输入.历史修订数据,今天的行业分类或最新状态也不能冒充当时版本;无法核验可获得时间时保留未知.工具请求失败,资料不足和模型明确不适用分别报告,不能都压成中性意见或零值.同题对比使用相同事实版本,补入会改变判断的新事实后重看受影响结论.

### 组织产出问题的应用示例

以下是当前 Agent 独立编写的假设应用,用于把已有产出与反馈模型落到可观察步骤,不是人物历史案例或本人规定的管理制度.仅在所选模型及任务适用时使用;不向人物核心补写未经原始材料支持的观点.

1. 先界定谁需要什么成果及质量边界.例如支持团队工单关闭数增加,同时重开率上升,不能直接认定产出提高.在同一时间窗和统计口径下配对数量与质量,分清清理旧积压,难度变化和真实改善;缺少重开数据就保留效果未知.
2. 画出从请求到可接受成果的实际阶段,读取等待,返工和交接证据.排队最长只是瓶颈候选;询问放宽该阶段能力后最终完成量是否增加,还是下游会立刻堵住.用小范围观察或试验验证,改善后重新定位限制,不以每个人都忙作为全局有效的证据.
3. 决定在哪里获取反馈.优先在昂贵返工发生之前检查关键风险,但不把每一步都增加审批当作质量提升.观察的是该任务上的经验,错误类型和结果可见性,不能仅凭资历决定放手程度.委派时约定成果,约束,质量标准和复核信号;方案分析不授权实际分派工作或改日历.
4. 若问题是管理时间,先核对已有授权材料中的实际活动,而非只看计划日历.区分促进他人成果,必要维护及造成反复打断/返工的活动,说明依据.再比较批量处理非紧急事项,训练或更早澄清的具体作用;不套用固定高杠杆比例,会议时长或频率.
5. 决策讨论先允许提出最有力的异议,再明确谁有决定权,尚缺什么证据以及何时需要决定.把定期信息交换与解决特定选择区分;只有信息更新时可提出书面替代,不能擅自取消会议.输出建议及负责人/时间的待确认值,不虚构组织授权.落实决定不代表异议消失,出现约定的新事实才复核,不因意见重复就无限重开.

验收检查:只有关闭数上涨时是否拒绝宣称整体改善;局部提速不能改善最终成果时是否重判瓶颈;资深人员进入陌生任务时是否按任务证据调整反馈;缺决定权时是否仍交付可审查建议而不冒充有权执行.效果需在实际组织任务中验证,示例本身没有证明效率提升.

## 4. 条件加载

- 用户仅要求出处时给出人物文件内的简短引用.需要解释具体方法依据,展开案例或处理会影响判断的证据分歧时,先定位相关模型 ID 和 Sxx,按[来源蒸馏规范](source-distillation.md)只读取对应本地笔记.核对其 person_id,source_id 与 supports,同轮同一笔记只读一次;"深入"不等于读取该人物的全部 sources.
- 本地笔记已提供所需证据时不重开网页.明确要求原文核验/更新,或当前关键证据仍不足且任务允许研究时才定向打开原始出处.笔记缺失或不可读时报告,可继续核心能够支持的部分;依赖缺失证据的结论保留未知,不凭记忆重建笔记或静默扩大联网范围.
- 背景只使用核心与本次相关来源笔记中有证据支持的限定;缺失的重要背景说明未知,不自动扩大为人物研究.本地笔记仍是历史材料的归纳,分析依赖当前事实时另行核实.
- 不读取其他人物文件,除非用户明确要求比较多个人物,或处于显式推荐及思维风暴的有限选模中.

## 5. 输出

先交付用户要求的实际结果.随后用简短说明列出使用的模型名称,关键取舍和重要不确定性.默认使用助手自己的身份和表达方式,不使用人物第一人称,不编造引语.

若用户明确要求模拟表达风格,仍然只把风格作为可选呈现层,不得声称输出来自本人,不得改变事实,授权或安全边界.
