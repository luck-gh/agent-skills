# 使用模式

## 1. 定位人物模型

按入口的来源选择,人物身份与每文件预检规则定位唯一文件.内置沿用索引精确的 `models/思维模型_<人物常用名>.md` 路径并核对 person_id,不从英文 ID 拼出文件名;外部沿用已匹配的 `<profiles_root>/<slug>.md`,二者不可混拼内容.从推荐或风暴进入时传递已核验的人物身份,具体模型 ID,来源与精确路径.同一内置 person_id 的文件正文只加载一次,跨分类和多个别名不造成重复读取.

- 没有匹配: 报告尚未蒸馏,询问是否进入蒸馏模式.
- 多个匹配: 列出最少候选信息,让用户确认人物.
- 文件缺少必要范围或模型字段: 报告文件不完整,不要凭模型记忆补写.

当前人物文件本身就是完整可用模型.检查人物身份,模型步骤和适用边界;文件内使用来源编号时确认可在同文件 Sources 定位,不为普通使用逐一读取来源笔记.已有完整模型不因未补笔记而拒绝使用,也不在每次使用时重做研究.已发现的悬空链接要报告,不得声称已读取该证据;是否继续取决于当前结论能否由完整核心支持.

若模型正文缺失,内容矛盾或已知写入状态仍未核实,说明具体问题并停止应用本次版本.使用请求本身不授权修改人物文件,不以记忆补写缺失模型.

## 2. 判断任务是否适用

把用户任务与人物文件中的 `Best used for` 和 `Do not use for` 对照.若不适用,直接解释原因,并可在不冒充人物的前提下完成普通任务.不要为了体现人物特色而强行套用无关模型.

## 3. 选择并运行模型

1. 从人物文件中选择最相关的 1-3 个模型,避免把全部模型堆进一次回答.
2. 使用每个模型的 `Use when`,`Procedure`,`Signals` 和 `Limits` 执行真实任务.
3. 区分人物明确表达过的原则与基于模型对新问题的推断.
4. 若任务依赖当前事实,先独立核对最新事实,再使用人物模型分析.人物文件不是事实数据库.
5. 当模型之间产生冲突时,展示关键取舍,由当前任务目标决定采用哪一个.

## 4. 条件加载

- 用户仅要求出处时给出人物文件内的简短引用.需要解释具体方法依据,展开案例或处理会影响判断的证据分歧时,先定位相关模型 ID 和 Sxx,按[来源蒸馏规范](source-distillation.md)只读取对应本地笔记.核对其 person_id,source_id 与 supports,同轮同一笔记只读一次;"深入"不等于读取该人物的全部 sources.
- 本地笔记已提供所需证据时不重开网页.明确要求原文核验/更新,或当前关键证据仍不足且任务允许研究时才定向打开原始出处.笔记缺失或不可读时报告,可继续核心能够支持的部分;依赖缺失证据的结论保留未知,不凭记忆重建笔记或静默扩大联网范围.
- 背景只使用核心与本次相关来源笔记中有证据支持的限定;缺失的重要背景说明未知,不自动扩大为人物研究.本地笔记仍是历史材料的归纳,分析依赖当前事实时另行核实.
- 不读取其他人物文件,除非用户明确要求比较多个人物,或处于显式推荐及思维风暴的有限选模中.

## 5. 输出

先交付用户要求的实际结果.随后用简短说明列出使用的模型名称,关键取舍和重要不确定性.默认使用助手自己的身份和表达方式,不使用人物第一人称,不编造引语.

若用户明确要求模拟表达风格,仍然只把风格作为可选呈现层,不得声称输出来自本人,不得改变事实,授权或安全边界.
