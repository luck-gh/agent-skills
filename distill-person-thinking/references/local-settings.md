# 人物资料库本地设置

只有当前任务需要外部人物资料库,且当轮没有显式提供 `profiles_root` 时读取本说明.只查找已有公开 Skill 或指定内置模型不需要本地设置.显式路径始终优先.

## 位置与字段

从当前 `SKILL.md` 所在的 physical skill dir 读取同级 `settings.json`.不得读取环境变量来改变位置,也不得搜索工作区,其他 Skill 或历史目录.随 Skill 分发的 [settings.example.json](../settings.example.json) 只说明字段结构,不提供运行时值.文件必须精确为:

```json
{
  "profiles_root": "<absolute-existing-directory>"
}
```

字段必须通过入口的人物资料库与文件预检.不允许 unknown 字段,凭据,人物资料,运行时状态,确认,批准或动作授权.

## 缺失或无效

蒸馏,更新或明确限定外部库时,文件缺失,JSON 损坏,字段缺失,含 unknown 字段或路径不可用,只询问 `profiles_root`.推荐模式不要求必须有外部库:缺配置则查内置,配置损坏则说明外部部分未检查;不得隐瞒错误或声称已检查全部外部模型.Example 只能用于确定字段和展示格式,不得自动复制为 settings,创建占位目录或充当默认值.当轮显式路径可以直接用于当前任务,不要求先持久化.

只有用户明确要求保存,且真实 `profiles_root` 已通过入口预检时才创建 settings.从当前 `SKILL.md` 精确确定同级目标;目标不存在时原子 no-clobber 创建,已存在且逻辑内容完全相同视为幂等,内容不同时停止并展示冲突,不得合并或覆盖.写后重新读取并严格核对字段与路径.

Settings 只描述人物资料库候选边界.读取或使用模型由用户明确的使用请求授权;推荐请求仅授权扫描核心 frontmatter 与核对入选候选;创建或更新模型由用户明确的蒸馏或更新请求授权.不得因配置存在而批量读取正文,迁移,删除或公开人物文件.
