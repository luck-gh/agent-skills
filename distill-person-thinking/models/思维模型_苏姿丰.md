# 苏姿丰思维模型

## Best used for
- 半导体及复杂技术产品的研发聚焦,长周期路线,架构与商业目标的取舍.

## Do not use for
- 推测本人当前投资或公司未公开路线,依据公司宣传性能给出未经验证的技术选型结论.

## Core models

### capability-led-long-horizon: 能力聚焦与长期技术路线
- Definition: 在客户确有需求且组织有深厚能力的领域集中资源,通过连续产品周期兑现承诺.
- Use when: 热门赛道不断变化,资源不足以同时支持全部方向.
- Procedure: 比较客户需求与现有技术优势;明确希望形成的领先能力,按共享人才/IP/客户知识判断聚焦,不只数项目;列出停止或延后方向;把长期目标拆为产品与客户里程碑;按硬件和软件的不同反馈周期验证,回看上一周期已交付,改变和仍属计划的承诺;核对资金和伙伴能否支持剩余周期.
- Signals: 核心知识与人才,客户采用,连续产品进度,研发可持续性,相邻业务对核心能力的复用.
- Evidence: S01, S02, S03
- Limits: 长周期不能消除生存约束.拒绝当年的手机芯片建议体现当时的能力判断,不构成任何企业都应拒绝手机市场的规则.
- Confidence: high

### architecture-around-system-constraints: 围绕系统约束重选架构
- Definition: 客户购买的是整体计算能力;当单一路径受限,需要联合考虑架构,互连,软件和制造,而非只强化一个器件指标.
- Use when: 团队依赖既有缩放规律或单项性能,整体成本与交付却逐渐失去竞争力.
- Procedure: 明确客户工作负载与性能功耗成本及导入时间;找出旧方案失效机制;区分架构,工艺,互连和软件的贡献,比较组合与接口代价;让关键技术人员共同审视大额投入;用原型及成功和失败产品反馈校正.能效受限时连同电源管理,封装制造与伙伴系统一起验收,区分交付与计划.
- Signals: 系统吞吐与能效,互连及软件开销,开发周期,可复用能力,客户验证,失败产品的反馈.
- Evidence: S01, S02, S03
- Limits: 模块化和 chiplet 都有代价,不能推广成所有产品的默认架构.公开材料说明路线与部分产品实践,不证明全部性能宣传或未来规划已经实现.
- Confidence: medium

## Decision heuristics
- 新风口出现 -> 核对是否建立在核心能力和客户需求上 -> 不因热度重置所有研发投入. [S01, S03]
- 原有缩放办法变慢 -> 重新检查系统组合 -> 在接口和产品验证后才扩大路线承诺. [S02, S03]

## Tensions
- 技术积累需要耐心,客户变化和失败产品又要求及时修正;长期方向不等于冻结每个设计.
- 大额架构投入可能创造优势,也可能压缩调整空间;本人成功回顾不能替代对失败路径的评估.
