# Paul Graham 思维模型

## Best used for
- 写清方案中的前提与因果关系;检验早期产品是否解决真实需求.

## Do not use for
- 预测投资回报或本人近期立场;代替专业安全规范;把用户奉承当需求证据.

## Core models

### writing-to-think: 写作即思考
- Definition: 将想法写成可被陌生读者检验的文字,通过重写发现原先未想到的限制和联系.
- Use when: 一个方案听起来合理,却难以说明理由和前提.
- Procedure: 先形成可检验草稿,写出当前结论与理由;从不了解背景的读者角度指出跳步;区分缺证据,缺解释与离题;补证,加限定或撤回不成立的句子,必要时修改原论点而非只润色;迭代至论证清楚.这是当前任务的操作化,不是本人固定步骤原文.
- Signals: 说不清的因果,缺失的限定,读者误解,修改后改变的观点.
- Evidence: S01, S02
- Limits: 清楚不等于事实正确;形式化推导,实验和实际建造仍可能更适合某些问题.
- Confidence: high

### iterative-discovery: 迭代发现
- Definition: 从具体人的真实问题起步,通过早期交付和观察修正对需求的理解.
- Use when: 团队主要在讨论假想需求,缺少实际使用反馈.
- Procedure: 找到迫切需要解决问题且能采取行动的少量用户;连同招募/上手路径交付最小可运行成果;直接观察并区分缺功能,使用困难和没有需求;检验脱离陪同后是否继续使用;由跨用户重复的反馈调整优先级,再检查相邻市场的适用条件.实验设计是当前推断,不能用此模型批准不安全发布或临时生产架构.
- Signals: 实际使用,重复需求,现有替代方案,用户愿意付出的成本,与口头赞同不一致的行为.
- Evidence: S03, S04
- Limits: 不将软件早期试用直接外推到医疗,航空等高代价场景;少量用户也可能没有代表性.高度人工服务可能掩盖产品自身价值,按工时满足单客需求时应重新判断目标是产品还是定制服务,不能只凭服务满意度证明产品可扩张.
- Confidence: high

## Decision heuristics
- 无法说清方案 -> 写出前提与推导 -> 不通之处回到证据核对,不能仅润色. [S01]
- 需求听起来有前景 -> 检查谁此刻需要 -> 没有真实用户证据时保留为假设. [S03]
- 用户在陪同下满意 -> 检查独立复用及跨用户共性 -> 只有代劳才能成功时,先识别剩余瓶颈而不直接扩张. [S04]

## Tensions
- 快速获得反馈与可靠交付有成本取舍;由错误代价限定实验环境和发布条件.
- 初期集中服务少量用户可以提高学习速度,但需求深度与市场扩展性需要分开验证;初版有人急需不等于以后所有人都需要.

## Unknowns
- 这两个模型不能复现人物的投资直觉,也不覆盖其全部思想.
