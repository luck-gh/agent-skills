# Ilya Sutskever 思维模型

## Best used for
- AI 系统真实任务验证,研究实验选择,算力与数据瓶颈分析.

## Do not use for
- 把访谈预测当作确定时间表,推断未公开架构,用单个故障断言所有模型没有能力.

## Core models

### reliable-generalization: 验证真实泛化
- Definition: 能在熟悉评测中解决问题与能在变化环境中可靠完成工作是两个需要分别测量的命题.
- Use when: 系统常在演示成功,但使用者仍要不断检查或修补结果.
- Procedure: 写明真实任务完成条件和容错程度;建立未用于开发选择的代表场景;分别测熟悉任务表现,少量反馈后的学习速度和跨任务迁移;加入环境变化与连续工作测试,追踪修错是否带回旧错;比较基准分数与人工接管负担,用对照检验训练覆盖或实现错误等解释后再改实验.
- Signals: 跨场景稳定性,往返修错,人工检查时间,边界情形失败与任务完成率.
- Evidence: S01, S02
- Limits: 这是对验证方法的归纳,不是断言特定模型必然缺乏泛化.评测污染或训练目标偏窄是待检验解释,不能只凭失败就认定.
- Confidence: high

### productive-scaling: 检验扩规模的有效学习
- Definition: 资源规模只有通过有效的数据和学习过程才转为能力,瓶颈可能随阶段变化.
- Use when: 团队正在决定更多算力,更多数据还是新训练方法更值得投入.
- Procedure: 拆出数据获得的物理与组织成本,训练效率,反馈质量和评估成本;分开证明研究想法的预算与产品推理运营投入;测每单位资源带来的可靠改善,区别价值估计提速与跨任务泛化;用可负担对照区分方法未成熟和规模不足;负结果先有限排错并预设复核界限,有可解释收益趋势再扩大资源.
- Signals: 单位资源带来的可靠能力改善,新增数据的信息量,数据取得速度,实验结果能否复现.
- Evidence: S01, S02
- Limits: 小规模结果未必保持到大规模,某些研究确需较大资源才能检验.本流程是应用推导,不是本人公开的一套固定投资公式.
- Confidence: medium

## Decision heuristics
- 得分很好却不断需要接管 -> 单独量化真实任务可靠性 -> 未减少复核负担前不据分数宣布成熟. [S01, S02]
- 追加资源后进步趋缓 -> 检查数据与学习配方 -> 用对照实验区分瓶颈,不预设唯一路线. [S01, S02]

## Tensions
- 规模可以提供研究条件,也可能扩大低效配方的成本.研究直觉可支持继续排错,但不能无限抵消反复的独立负证据;复核边界是当前应用约束.
- 有价值的能力展示应推动更严格验证,不能代替对可靠性的证明.

## Unknowns
- 不知道 SSI 内部方法或最新系统表现.2023 与 2025 访谈体现研究阶段判断变化,不能外推为永久定律.
