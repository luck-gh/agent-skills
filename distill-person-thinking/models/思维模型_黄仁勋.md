# 黄仁勋思维模型

## Best used for
- 判断技术方向的长期价值,平台采用瓶颈与软硬件协同投入.
- 在思维风暴中连接技术可行性,开发者使用和商业兑现.

## Do not use for
- 将本人声誉当作市场预测证据,默认全仓押注,要求团队以痛苦证明投入.
- 套用固定管理人数,取消所有一对一沟通,或把其历史判断当作当前公司立场.

## Core models

### recheck-strategic-premises: 反复检查战略前提
- Definition: 坚持的对象是可解释的基础判断,不是某个方案或个人愿望;当问题,技术条件或替代方案变化时重新推导.
- Use when: 战略尚未兑现,需要区别长期建设与沉没成本驱动的固执.
- Procedure: 写出需求为何重要和现有技术为何不足;列出少数因果前提;检查条件是否变化或问题已被别人解决;核算新能力对当前业务的效率与成本负担;找能带来真实使用和收入的小场景.分别判断前提是否仍成立与组织能否继续等待,据此选择继续,调整或停止.资源上限与停止门槛是当前操作化.
- Signals: 未满足需求,替代技术,新场景中的实际使用,成本负担,前提被反证的情况.
- Evidence: S01, S02
- Limits: CUDA 的成功不能证明所有长期投入都值得坚持.定性推理仍须接受成本和用户事实检验,不能排斥合理财务分析.
- Confidence: high

### platform-adoption-loop: 让平台能力变成开发者采用
- Definition: 底层能力只有通过工具,库和应用转为可用价值,才能吸引更多使用者及后续应用;平台建设要覆盖阻碍采用的关键环节.
- Use when: 性能演示突出,开发者仍无法低成本完成实际任务.
- Procedure: 从一个目标应用逆推缺少的数值语义,数据管理,接口,工具和库;找到能嵌入已有工作流的切入口,先打通并验证结果正确;比较迁移维护成本和端到端收益,不能因自动管理就忽略底层开销;观察开发者能否独立使用;仅将已证实共性推广到邻近场景.不预设所有环节自建.
- Signals: 应用迁移时间,独立开发者完成率,重复使用,公共能力复用,新增平台成本与使用价值.
- Evidence: S01, S02, S03
- Limits: 平台协同不保证垄断优势.稳定接口只服务于当前有效的承诺,不要求保留已废弃契约;是否兼容由当前项目要求决定.生态规模和性能宣传须另外核验.
- Confidence: high

## Decision heuristics
- 长期项目迟迟未兑现 -> 检查最初前提和近期有效用例 -> 前提失效时修订方向,不靠信念强度裁决. [S02]
- 新处理器没有应用 -> 定位开发工具与移植障碍 -> 先完成可用场景再扩大平台投入. [S01, S03]
- 一个领域已经跑通 -> 检查邻近需求是否共享核心能力 -> 只有共性被验证才推广. [S01]

## Tensions
- 可编程性增加长期机会,也增加当前成本;技术路线和存续资源必须同时成立.
- 平台统一有助于复用,具体行业又需要不同能力;统一应以真实共性为依据.

## Unknowns
- 未核验未公开路线图,当前订单或竞争结果.不把多年后回顾描述成当时已能预知完整未来.
