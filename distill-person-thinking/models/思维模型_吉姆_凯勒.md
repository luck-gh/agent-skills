# 吉姆·凯勒思维模型

## Best used for
- 芯片和计算系统的架构取舍,性能诊断,以及超出团队能力的复杂性治理.
- 在思维风暴中检查方案能否拆成可实现部分,是否真正改善端到端目标.

## Do not use for
- 复刻未公开微架构,把一次跑分当普遍优势,或者把个人回顾当团队贡献的完整记录.
- 机械规定每隔几年重写,用挑战极限否定已知物理限制或忽略验证.

## Core models

### testable-abstraction-layers: 保持抽象层可理解与可检验
- Definition: 抽象以隐藏可控细节换取系统规模;每层仍须有可理解的行为,可完成的责任与可验证的边界.
- Use when: 局部变更需要理解整个系统,某些任务连资深负责人也无法清楚说明或检验.
- Procedure: 画出层次和依赖,让负责人说明行为与验收方法;连资深者也无法完成时先查任务尺度与设计.评估成熟抽象隐藏的细节和局部代价;用客户完整任务排除功能堆积与必需功能缺失;保留可运行部分,逐步验证局部及组合.只有边界减少实现和验证负担才保留.迁移顺序与验收门槛是当前操作化.
- Signals: 局部可测试性,跨层依赖,修改波及范围,无法解释的异常,责任与能力是否匹配.
- Evidence: S01, S02
- Limits: 抽象可能隐藏关键时序,资源或错误传播,必要时应深入该层.细粒度单元的利用率收益须覆盖协调成本,不能为拆分增加无效接口.重构不构成周期性重写理由,也不能拆坏已运行的交付路径;人的自主性不能用模块类比消除.
- Confidence: high

### separate-performance-constraints: 拆分性能约束再确定改进点
- Definition: 将总体性能拆成可区分的贡献和约束,优先处理真正限制当前工作负载的部分,避免用一个外因解释全部差距.
- Use when: 团队认为换工艺,加算力或增加缓存就会自然解决所有性能问题.
- Procedure: 固定工作负载,精度,并发与比较基准;沿实际流程测量计算,存储驻留/移动,通信和等待;分别判断架构与工艺贡献,列明未解决的外部依赖.比较加资源,减工作量和复用既有设备的总成本;实施一项可验证改进后重测端到端时间,寻找新暴露的标量或协调限制.具体顺序属于当前归纳.
- Signals: IPC 与频率的分别变化,存储和通信开销,串行部分占比,功耗面积预算,局部加速后的总时间.
- Evidence: S01, S02, S03
- Limits: 不同负载的瓶颈会变,更多缓存或芯片不保证继续增益,混合设备也有接口和维护成本.IPC 需匹配负载,手机计算需同时检验电源管理.实际时序,功耗和可靠性要求优先;目标不能缩短必要研发时间或证明外部依赖已有解法.不据公司访谈给出厂商排名.
- Confidence: high

## Decision heuristics
- 工程师反复无法完成模块 -> 检查边界和任务规模 -> 连资深者也无法解释时先重新拆分. [S02]
- 把落后归因于工艺 -> 分别检查架构效率与工艺条件 -> 可控制部分没有做好时不能只等待外部改善. [S01]
- 增加计算单元没有等比例提升 -> 检查存储通信与串行工作 -> 先解决测得的限制再扩大资源. [S03]

## Tensions
- 深入底层能提高理解,成熟抽象又让系统可扩展;需要按实际瓶颈选择深入的位置.
- 雄心目标能推动创新,也可能压过工程事实;差距应变为可验证问题,不是强行承诺.

## Unknowns
- 未核验私有设计细节,厂商性能宣传与最新交付结果.不把本人所称突破推定为可复制成果,也不采纳其对其他学科极限的泛化评论.
