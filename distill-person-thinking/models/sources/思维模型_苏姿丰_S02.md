# 苏姿丰 S02: 用已上市产品检查路线,用系统设计推进下一代

关联核心: [苏姿丰思维模型](../思维模型_苏姿丰.md).

## 原始出处与已读范围

- 材料: [AMD Unveils Expanding Set of High-Performance Products and Technologies](https://ir.amd.com/news-events/press-releases/detail/767/amd-unveils-expanding-set-of-high-performance-products-and-technologies-propelling-next-phase-of-growth),AMD 官方公告,2017-05-16,含苏姿丰和其他管理者发言.
- 核验日期: 2026-09-08.
- 已读范围: 总体增长路线,数据中心和客户端状态,`Technology Updates` 与前瞻声明.不采用 GPU 宣传跑分证明当前性能.

## 材料直接记载

公告以已上市 Ryzen 7/5 为基础,继续提出服务器和其他客户端产品计划.技术更新把下一代架构与工艺推进并列,还包括片上集成,软件和系统设计;Infinity Fabric 的解释来自 CTO.这构成从 2015 年公开规划到部分产品上市的行动记录,并不证明全部早期路线都兑现.公告明确未来时点与收益存在不确定性.

## 据此归纳的方法

`capability-led-long-horizon` 需要跨周期验证承诺;`architecture-around-system-constraints` 需要把计算能力与内存,I/O,互连和软件一起评价.

1. 回到上一个周期的承诺,标出已交付,改变和仍属计划的部分.
2. 对已交付产品检查目标客户和使用场景是否吻合,不要只用发布数量代替成功.
3. 固定端到端目标,区分性能来自架构,工艺还是系统配套,避免全部归因于其中一项.
4. 扩展邻近市场前核实共同核心与额外要求,例如不同内存和 I/O 需求.
5. 使用产品反馈调整具体实现,同时检查长期能力路线是否仍成立.

## 当前应用推断与改判条件

以上步骤为当前操作化.若核心性能进步被互连,软件或导入成本抵消,应调整架构组合.若仅有计划且关键伙伴尚未准备好,不能升级承诺为交付判断.若新市场需求不共享既有能力,应重新比较进入成本.

## 核心回写与局限

回写跨周期承诺复核和分清各层贡献.产品公告能证明公司公开状态,不能验证全部技术领先表述;2015 和 2017 年同公司公告是不同时间记录,也不构成独立第三方评测.
