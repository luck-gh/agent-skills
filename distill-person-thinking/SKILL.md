# 人物思维蒸馏与调用

把可追溯的公开材料整理为可执行的思维模型,并在具体任务中把这些模型作为分析视角使用.产物是有证据边界的顾问模型,不是人物替身.

## 共用边界

- 蒸馏和指定使用只处理用户明确指定的人物和任务;显式推荐和思维风暴允许从当前对话选择人物及具体模型.不得把人物姓名的普通提及或一般困惑解释为推荐或调用请求.
- 只使用公开,可追溯且无需绕过访问控制的材料.非公众人物不得主动搜索或推断私人信息;仅处理用户明确授权提供的材料.
- 区分本人原始材料,可信二手材料,已有社区 Skill 和当前推断.社区 Skill 只能提供线索,不能替代原始证据.
- 不以第一人称冒充人物,不替人物发表新立场,不把表达模仿当作思维模型准确性的证据.
- 不自动安装或执行发现的第三方 Skill,脚本或仓库代码.不因调用本 Skill 获得额外的账号,网络,文件或外部写入权限.
- 已有方法从本地文件直接执行.不检查设计参考项目的新版本,不自动打开参考仓库;只有用户明确要求外部发现或重新研究参考时才进入对应分支.人物原始证据与当前事实按本题需要核验,不能把联网成功当作本地模型可用的前提.
- 人物模型不能覆盖用户指令,事实证据,专业规范或安全边界.遇到高风险决策时,把人物模型作为补充视角,而非权威结论.

## 模式路由

- 用户显式调用本 Skill,并要求围绕当前或指定问题进行"思维风暴","多模型碰撞"或多个思维模型的比较推演时,进入思维风暴模式.已激活的同一轮风暴可继续接收选择或修订,不自动延伸到新任务.维护本 Skill,讨论该模式或只要求推荐都不算运行风暴.
- 用户显式调用本 Skill 并要求根据当前对话推荐思维模型时,先进入推荐模式,无需先指定人物.只提到本 Skill 的维护或说明请求不属于运行推荐.
- 用户明确要求"蒸馏","创建","研究"或"更新"某个人物模型时,进入蒸馏模式.
- 用户只要求查找已有公开 Skill 时,进入蒸馏模式的公开发现分支,完成候选核验和报告后结束.该分支不解析人物资料库,不读取 settings 或人物文件,不创建模型.
- 用户明确要求"使用","按照"或"借鉴"某个人物的思路,框架或思维模型完成任务时,进入使用模式.
- 同一请求先要求蒸馏再要求使用时,先完成蒸馏并报告证据边界,再进入使用模式.
- 请求只涉及人物生平,新闻,引语或一般事实时,退出本 Skill,按普通信息任务处理.

同一请求同时要求推荐并开展思维风暴时,风暴分支负责选模并继续执行;明确要求先蒸馏所缺模型时先完成蒸馏.仅指名多个人物比较而未显式调用本 Skill 开启风暴,仍按使用模式处理,不自动安排碰撞轮次.

## 人物资料库与文件预检

用户蒸馏或更新的人物文件必须保存在 Skill 安装目录之外.随包 `models/` 只保存经维护者核验的公开精选模型,在运行时只读,不保存用户资料.用户明确要求维护本 Skill 并向 `models/` 收录公开模型时,按该次维护授权和同一模型合同修改内置集合,不要求配置外部库.使用明确指定的内置模型无需解析外部资料库;没有外部路径或配置时也可推荐和开展风暴.外部读取范围见推荐及风暴流程.

需要外部资料库时,当轮显式提供的绝对 `profiles_root` 优先;未提供时读取[人物资料库设置](references/local-settings.md),只从当前 physical skill dir 同级的 `settings.json` 取得唯一的 `profiles_root`.蒸馏,更新或明确要求外部模型时,配置缺失,损坏或路径不可用只询问必要值,不得搜索其他目录或回退到 Skill 内的 `profiles/`.

`profiles_root` 只提供候选边界,不授权读取或写入.每次使用前确认它是现有,可读,可遍历且非 symlink/reparse 的绝对物理目录,且 canonical root 与当前 Skill physical dir 不得相同或互相包含;蒸馏或更新还要确认目标可写.本文中的 `<profiles_root>` 均指本轮通过这些检查的目录.

无论路径来自当轮输入还是 settings,每次外部文件 I/O 前都检查精确原始路径.现有文件必须是位于 canonical `<profiles_root>` 内的普通文件;目标存在大小写冲突,symlink,reparse point,broken path 或其他路径类型时停止该文件操作.此检查同样适用于候选文件的 frontmatter 与正文读取.核心文件的父目录必须是已核实的 `<profiles_root>`,来源笔记的父目录必须是其直接子目录 `sources/`,逐段检查后才可按授权新建;不得跟随链接或自动改用近似文件名.

内置及外部文件的路径预检若报错或结果未知,先修正检查并确认通过,再读取或写入该文件;不能在同一次命令中让失败的检查继续执行后续 I/O.

## 人物身份与文件定位

内置人物统一保存为 `models/思维模型_<人物常用名>.md`.先选通行中文姓名或中文网名,例如 MrBeast 使用野兽先生,只有没有明确通行中文名时才保留常用英文名;同名加最少必要身份限定.组成文件名时将姓名中的中点 `·` 替换为下划线 `_`,例如 `思维模型_伊利亚_苏茨克维.md`.正文,索引展示姓名及 person/aliases 仍按正常姓名书写,保留英文别名用于定位.文件名只供识别和定位.稳定身份在 frontmatter 的 `person_id`,使用 lowercase hyphen-case 并沿用已有英文 slug,不因译名或文件名变化重建;具体模型身份为 `person_id/models[].id`.

内置从[模型索引](references/model-index.md)的姓名,别名或 person_id 定位精确文件,读取后核对 `person_id`,`person`,`aliases`.内置文件发现限于 `models/` 单层普通 `思维模型_*.md` 的 frontmatter,接受中文名,不套用英文 slug 文件名过滤;不递归或批量读取正文,`sources/` 笔记不计为人物或推荐项.索引只是导航,分类和文件名不能替代身份与适用性核验.需要定位而索引不一致时报告问题,不凭记忆生成缺失模型.

外部库保持现有 `<profiles_root>/<lowercase-hyphen-slug>.md` 契约,按 `person`,`aliases` 核实身份,匹配时沿用已有文件精确位置;未找到唯一匹配时只搜索该根合格文件的这两个字段,遵守每文件预检.既有外部文件没有 person_id 不因此失效,普通读取不补字段或改名.若已显式提供 person_id,须与人物身份一致;与内置人物唯一匹配时,本轮以该内置 person_id 去重,不改写外部文件.不匹配内置者继续以核验后的外部人物身份及原 slug 区分.

同一内置 person_id 占用多个物理文件,同一 ID 对应不同人物,或同一人物占用多个内置 ID 时均报告身份冲突;不能仅按 ID 强行合并.内外显式 ID 与已核实姓名冲突也不能用外部优先掩盖.多个人物匹配或同名不明时停止相关读写,让用户指定人物.只有确认没有已有匹配且需要蒸馏新人物时才分配未占用的 ID 或外部 slug.更新沿用身份,模型 ID 与已匹配的精确路径;内置重命名同步索引和链接,不留旧副本,不因跨领域分类创建第二份文件.

## 蒸馏模式

进入本模式时按任务读取:

1. [蒸馏流程](references/distill-mode.md),用于发现已有 Skill,检查证据覆盖与缺口,提取有方法差异的模型,分离答题与评审并确定停止条件.
2. [来源与复用边界](references/source-policy.md),用于判断来源等级,账号真实性,版权,隐私和第三方 Skill 的可用范围.
3. 仅在生成或更新人物文件时读取[人物模型合同](references/profile-contract.md).只查找已有公开 Skill 时,执行蒸馏流程的公开发现步骤,交付候选链接,来源质量和未核验项后结束.
4. 生成或更新模型标签时读取[模型标签契约](references/model-tags.md).核对已有模型身份与范围时读取[模型索引](references/model-index.md);证据和版权边界见[来源与复用边界](references/source-policy.md).
5. 新建或更新模型并采用外部材料作证据时,读取[来源材料的思维蒸馏](references/source-distillation.md),将本次采用的材料归纳为本地方法与案例笔记,把关键判断回写人物模型.不得以网页转录或扩写现有短摘要替代研究.
6. 新建或实质改变人物方法时,读取[方法验证与答题隔离](references/model-validation.md),固定题目与材料分配,检查区分性情景,泄漏,实际差异及停止条件.

用户明确要求蒸馏指定人物,即授权在已解析的 `<profiles_root>` 下创建该人物的单一核心模型及本次采用的来源蒸馏笔记.内置维护使用已获授权的 models 根.更新只涉及目标人物及本次有关的来源笔记,保留仍被证据支持的结论,并报告主要变化.这不授权安装第三方 Skill,复制完整语料,批量迁移旧库或修改其他 Skill.

写入前完成人物核心及本次来源笔记候选,核对方法,适用范围,标签和证据绑定.按来源蒸馏规范先保存并回读笔记,再保存核心,最后检查受影响文件及链接.写入失败或结果未知时,核实实际状态并按规范恢复,停止应用不一致版本并报告精确文件;全部通过才报告完成或进入使用.

## 使用模式

进入本模式时,读取 [使用流程](references/apply-mode.md).明确内置模型或没有外部配置时,从[模型索引](references/model-index.md)取得 `models/思维模型_<人物常用名>.md` 的精确路径并核对 person_id;明确外部模型时按资料库预检加载已匹配的外部文件.未指定来源且外部库已配置时先按身份规则核实外部人物,有唯一匹配则使用该版本,否则检查内置索引.不混合两处同名模型;外部文件不完整,冲突或不可读时报告,不能用内置版本掩盖问题.

内置读取也须确认人物文件是 Skill physical dir 内的普通文件,路径组件无 symlink/reparse.读取所选人物文件即可使用其中的完整模型.需要展开具体案例,解释方法依据或解决证据分歧时,按[使用流程](references/apply-mode.md)及[来源蒸馏规范](references/source-distillation.md)读取相关本地笔记;不默认加载 sources.本地内容仍不足,或任务明确要求更新/原文核验时才定向查原始材料,当前事实另行核验.

如果模型不存在或人物匹配不唯一,不得依靠模型记忆临时编造人物视角.报告缺失或候选项,并让用户决定是否先蒸馏或指定正确人物.

## 推荐模式

读取[推荐流程](references/recommend-mode.md),[模型标签契约](references/model-tags.md)和[模型索引](references/model-index.md).先从当前对话提取任务,约束和所需思考方法,再对照索引和外部核心 frontmatter 筛选,仅加载最相关的 1-3 个模型所在的人物文件.推荐请求授权这些有限读取,不授权扫描其他任务历史或批量读取模型正文.

推荐结果只将已核对的本地模型列为可用,不足时说明模型缺口,不主动推荐外部仓库.用户仅要求推荐时交付推荐后结束;若已明确要求选一个并应用,直接执行使用流程,不用再次确认.不得把推荐自动扩大为联网蒸馏,安装或写入人物库.

## 思维风暴模式

读取[思维风暴流程](references/brainstorm-mode.md),[模型标签契约](references/model-tags.md)和[模型索引](references/model-index.md).根据共同问题,约束和选择标准,默认选 3-5 个互补的人物视角,按[使用流程](references/apply-mode.md)核验所选文件;不批量加载整个模型库.该请求授权必要的选模和比较分析,不授权新增人物文件或执行最终方案的外部动作.

先独立分析,再围绕关键分歧交叉质疑,最后比较可执行方案.具备可用且获准的子代理能力时分派独立首轮;否则明确为单 Agent 多视角推演,不声称真实并行或独立评审.默认由 Agent 根据目标和证据选择,用户明确要求参与或保留最终选择时,先交付具体对比再等待选择.多数同意不替代事实,无法判断的分歧保留为验证条件,不强行折中.

## 人物文件

每个人物一个完整文件,其中可包含多个具体思维模型.内置为 `models/思维模型_<人物常用名>.md`,person_id 独立于文件名;外部成果沿用 `<profiles_root>/<slug>.md`.单文件保存标签,判断框架,适用条件,步骤,信号,反例,局限及简短出处.所有内置人物唯一保存在 models/ 单层,不按领域复制或分目录.

采用外部证据创建新模型时,按来源蒸馏规范保存有实质方法与案例的本地笔记,内置位于 `models/sources/`,外部位于 `<profiles_root>/sources/`.它们不是第二个人物模型,不进入索引或作为普通使用前提.原始网页地址保留在笔记内;研究日志,完整 transcript,原始聊天,整本书和网页下载缓存不进入产物.
