# distill-person-thinking

把公开可追溯材料中的判断方法整理为有证据边界的顾问模型,并用它们帮助分析具体问题.可蒸馏指定人物,查找已有公开 Skill,应用已有模型,或在显式请求下推荐和比较少量互补视角.

它关注具体调查问题,判断步骤,取舍,反例与改变结论的条件.不生成名人替身,不模仿本人发表新立场,也不把普通人物提及,新闻或名言查询自动变成模型调用.

## 安装与调用

从维护者提供的分发包或现有工作区取得完整 `distill-person-thinking/`,保留 `models/`,来源笔记,引用与 metadata.公共下载仅含已发布内容,使用当前未发布版本时直接接入当前工作区完整目录.

Codex 用户级入口为 `$HOME/.agents/skills/distill-person-thinking`,Windows 对应 `%USERPROFILE%\.agents\skills\distill-person-thinking`.完整目录可直接安装或由目录链接指向唯一实体,不要覆盖既有目录或维护重复副本.其他 Agent 使用自己的发现机制.输入 `$distill-person-thinking` 调用;必要时重启 Agent 刷新.参见 [Codex 文档](https://developers.openai.com/codex/skills#where-codex-loads-local-skills).

## 无需配置的最小用例

```text
使用 $distill-person-thinking,为这个问题推荐一个现有模型并直接应用:我在做离线笔记工具,目前有搜索、标签、文件夹三套入口,用户常不知道从哪开始.预算只够做一周实验.请给出要验证的假设、需要补充的事实和停止条件.
```

仅要求推荐时会在交付推荐后结束.也可明确指定已有模型,例如按保罗·格雷厄姆的迭代发现方法审查一个产品假设;实际可用姓名与方法以[模型索引](references/model-index.md)为准,不凭记忆临时编造缺失模型.

进阶比较用例:

```text
使用 $distill-person-thinking 开展思维风暴.团队有两周时间,要在先减少现有功能与先改善新用户引导之间选择.请选择互补模型,在同一事实底稿上先独立分析,再质疑分歧.输出方案、关键未知和会改变选择的证据,不要执行产品修改.
```

研究用例:

```text
使用 $distill-person-thinking,更新我指定人物的现有模型.人物和外部 profiles_root 由我随后提供,只采用公开且可追溯材料.先核对已有方法与证据缺口,定向补证;无法核验的结论保留未知,不要批量新增人物或安装第三方 Skill.
```

## 输入,输出和设置

普通使用提供问题,约束及指定人物/方法;推荐和风暴可从当前对话确定任务,不扫描其他任务历史.内置模型无需配置或 Python.随包模型在运行时只读,核心文件可独立使用,需要解释出处时才加载相关来源笔记.

创建或更新用户模型时,提供 Skill 目录之外已存在的绝对 `profiles_root`,或按[设置说明](references/local-settings.md)配置同级 `settings.json` 的唯一字段 `profiles_root`.参见[安全示例](settings.example.json).路径不授权任意读写,每个外部 I/O 仍需预检.外部成果为一个 `<slug>.md` 核心及按需 `sources/` 笔记;研究日志,完整访谈转录和网页缓存不进入模型库.

应用输出为有依据的分析,条件方案和验证动作.蒸馏输出是包含步骤,信号,边界,取舍与出处的模型及来源笔记.联网研究取决于宿主工具和公开材料可访问性;独立风暴首轮或评审取决于获准的子代理能力,没有时明确标记单 Agent 推演.

## 如何判断模型有价值

先核对解释,行动,反证与时间背景的覆盖,同源转载不算独立证据.去掉姓名和语气后,比较模型是否带来具体问题或判断方法的差异;只有泛泛口号时不升级为核心方法.使用时从具体模型推导需要确认的事实,已充分提供的信息不重复调查.

验证先固定题目与标准,避开核心和来源笔记的示例答案,将答题与评审材料隔离;泄漏的题目作废并换题.评审对照核验过的原始材料,历史回放按实际公开时间筛资料,不只看报告期.流程见[蒸馏](references/distill-mode.md),[方法验证](references/model-validation.md)与[应用](references/apply-mode.md),价值取舍仍必须有证据支持.

应用流程还提供组织产出的假设示例:配对数量与质量,检验局部瓶颈是否影响最终成果,按任务经验安排反馈并保留异议的复核信号.这些是当前 Agent 的操作化示例,不是新增的人物观点或已证实的效率收益.

## 常见问题与验证范围

- 模型缺失或身份冲突时不会临时冒充人物回答;需要指定正确模型或先蒸馏.
- 多视角多数同意不等于事实正确;争议保留为待核验条件,不强行平均.
- 有限的旧版/新版独立模拟对照支持新增流程更明确,不证明人物思维已还原,真实泛化,训练污染已排除或决策收益.
- 外部路径预检失败后的完整 I/O 停止与部分写入恢复仍有历史复测缺口,本次流程对照未关闭它.实际失败需核实状态并停止应用不一致版本.
