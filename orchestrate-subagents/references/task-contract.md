# 派发任务契约

只在实际派发或补充任务包时读取.只规划时不要求填写完整模板.字段可以合并为清楚的自然语言,但必需信息不能丢失.

## 必需内容

```text
角色与承载:
你是单一成果的执行所有者,不是根总控.使用<已确定承载>,依据为<用户要求或最小影响>.

目标与独立成果:
<一个明确且可验收的目标及交付>

输入与前置依赖:
<必要原始需求,精确路径,材料及已满足依赖;未满足的前置条件不得用推测替代>

范围与所有权:
- 允许读取:<必要路径或状态>
- 允许修改:<精确路径或状态;只读任务写“无”>
- 独占所有权:<文件,目录,任务或外部状态>
- 明确禁止:<无关范围,重叠工作和未授权副作用;默认无递归委派或创建新任务权限>

执行与停止条件:
负责范围内的调查,实施,调试,修复和验证闭环,不得把实质工作退回根总控.
在目标和边界内自主选择实现及工具;高风险操作遵守适用的严格步骤.
停止条件:<完成,需要用户,受保护边界或状态不明等具体条件>.
瞬时失败最多由同一所有者重试<0或1>次;未授权取消时不得取消.

验证与完成条件:
<目标质量标准,适用测试或校验,客观完成条件与必要检查点;简单成果可用一句话说明要求如何由证据支持,多项条件或多结果合流时逐项对应要求与证据>
<工作单元先以自身成果和证据判断完成.若它还负责把多个修改或产物组成单一最终候选或共享状态,且正确性依赖组合,指定由该原实施或获授权的整合所有者在组合后复验;并列只读成果或仅汇总结构化结论无需额外复验>

返回:
- 状态:完成 / 部分完成 / 阻塞 / 取消 / 未知
- 结论和修改文件或状态
- 实际验证,命令,退出码与结果,以及它们支持的要求;简单成果允许合并说明,多项条件或合流结果逐项对应;未运行项及原因
- 若本工作单元负责上述组合,返回最终候选或共享状态的复验结果与执行所有者;否则不要求持有后续整合证据
- 结果时间点及文件/任务/工具依据状态,可能使结论失效的条件
- 遗留风险;未完成时提供最小失败证据,已尝试动作及所需信息
```

## 仅在相关场景补充

- Skill 写权限:先完整读取并使用 `$new-skills`,再按需读取领域 Skill.按其平台契约执行 initializer,metadata,通用 validator,平台 validator 和内容风格检查;只对本轮相关领域逻辑运行测试,不无条件叠加领域测试.只读使用或解释不要求生命周期变更流程,明确要求验收时仍遵从对应验收契约.
- 基础规则刚更新:使用新版相关 Skill 后再执行依赖它的工作,记录版本或入口哈希以证明规则切换,不逐次审计全部读取.
- 模型与上下文:简短记录本工作单元使用用户指定,自动选择或继承,请求的模型与 reasoning,选择理由和当前工具支持情况;自动选择高等级模型的依据按模型选择指导提供.追加不同成果时更新这份记录,不复用旧任务的理由.按内部或用户侧场景检查覆盖权限与上下文组合,继承时省略相应覆盖参数.等级不授权角色变更;请求值与工具确认值分开报告,未回显时不得宣称实际运行模型已确认.
- 领域 Skill:提供根据 metadata 选中的主要入口,要求执行方完整读取,无匹配时写“无”.不复制 Skill 正文,不把缺少工具,资料或权限解释为模型能力不足.
- 能力升级交接:提供原执行方已结束的状态依据,最后写入状态,失败与修复证据,交接所有权及剩余升级预算.不得让新执行方复做已确认完成的副作用.
- 分支协调:明确后代范围,槽位,文件/状态所有权与收口责任;没有这些授权仍是叶子.
- 高风险步骤与独立复核:写明必须遵守的步骤,适用验证和复核授权;按成果评价开放任务,不强制统一工具路径.复核者接收原始需求,边界与质量标准,不接收实现方预期结论.
- Git 或其他外部副作用:逐项写明已获授权的动作及精确范围,未列出的动作不授权.
- 用户侧任务,串行 checkpoint 或回调:只添加对应场景 reference 要求的字段,不得自行扩大数量,承载或授权.

内容风格入口由已确认的 `new-skills` physical dir 提供:

```text
python -X utf8 -B <new-skills-physical-dir>/scripts/check_content_style.py --json <target-physical-dir>
```

任务包不得成为第二份 Skill 实现.只传当前工作的必要输入,授权和验收条件,不要粘贴无关引用或其他分支讨论.
