# 内部子代理场景

只在 `routing.md` 已把请求路由为当前主任务内的内部子代理时使用本文件.

## 根主控与执行方边界

- 本 Skill 只在根主控生效.普通内部执行方是叶子工作者,不调用本 Skill,不创建用户侧新任务,也不默认继续委派.
- 只有任务包已按 `routing.md` 明确指定分支协调角色,说明后代范围,槽位,所有权和收口责任时,该分支才能协调内部后代.这是有界例外,不授权创建用户侧新任务.
- 每个叶子执行方拥有一个成果和范围内的调查,实施,调试,修复及验证闭环.需要另一所有者时返回根主控决策,不得自行扩大分工.

## 派发

- 先检查内部协作工具的真实 schema,空闲槽位,当前模型参数能力和用户并发约束.
- 使用主文件的公用任务包,写明内部承载选择依据,前置依赖,文件/状态所有权,停止条件,重试预算,验证要求和返回结果依据状态.
- 只并行依赖已满足且所有权不重叠的工作.文件所有权重叠时串行化,不得让多个执行方同时写同一文件或外部状态.
- 槽位已满时进入 `WAITING_CAPACITY`,使用事件等待.不得改变承载方式,创建用户侧新任务,盲目增加代理或由根主控接管.
- 模型与 reasoning 只在工具 schema 支持时设置.不支持时写 `omitted` 或 `refused`,继续使用内部承载.

## 生命周期

```text
PLAN -> DISPATCHED -> WAITING -> ALL_REQUIRED_RETURNED -> COLLECT_ONCE -> FINAL
NO_CAPACITY -> WAITING_CAPACITY -> DISPATCHED
WAITING -> NEEDS_USER -> WAITING
WAITING -> RETRY -> WAITING
WAITING -> BLOCKED
WAITING -> CANCELLED
WAITING -> UNKNOWN
```

1. 派发后记录任务名,逻辑角色,承载方式,模型映射,范围,依赖,所有权和必需完成集合.
2. 进入 `WAITING` 后不要发送最终答复.内部子代理只能把结果返回仍在编排的当前任务,不得依赖主任务 `FINAL` 后回传.
3. 使用事件等待接收状态变化.禁止高频轮询,重复读取无变化快照,完整线程或原始工具输出.
4. 收到部分结果时只更新完成集合和紧凑摘要,继续等待其余必需结果.
5. 缺少任务内必要信息时补充最小信息.需要用户批准,授权或选择时进入 `NEEDS_USER`,由根主控把决策留给用户.
6. 瞬时工具或通信失败时,只有剩余重试预算大于 0 才进入 `RETRY`,并由同一所有者重试一次.不得更换代理复制工作.
7. 验证失败时把最小失败证据交回原实施所有者修复.独立复核只在用户已授权且风险值得时派发.
8. 失联,超时或状态不明时只做一次紧凑状态检查.仍无法证明状态则进入 `BLOCKED` 或 `UNKNOWN`,不得重复派发可能写入的工作.
9. 只有用户或任务包已授权取消且工具支持时才能进入 `CANCELLED`.记录工具确认和可能存在的部分结果.
10. 所有必需结果齐备后进入 `COLLECT_ONCE`,只综合一次,然后 `FINAL`.

## 任务包补充字段

在公用任务包中明确:

- 承载方式是当前主任务内的内部子代理,完成后由当前根主控统一收口.
- 普通执行方是叶子,不得创建用户侧新任务或递归委派.有界分支例外必须逐项显式授权.
- 只在当前工具 schema 支持时设置最小必要上下文继承;否则写 `omitted`.
- 写明前置内部任务或“无”,以及等待它的状态条件.
- 完成后只返回结构化摘要,证据,验证结果和依据状态,不得发送原始日志.

## 验收

只有公用返回格式合规,范围与所有权未越界,指定验证已报告,必需依赖齐备且结果状态足够新时,才把工作单元加入完成集合.任何 `BLOCKED`,`CANCELLED` 或 `UNKNOWN` 必须在最终汇总中单独列出.
