# 用户侧新任务场景

只在 `routing.md` 已确认用户明确授权创建新任务,新线程,新聊天或侧栏任务时使用本文件.

## 授权边界

- 严格遵守用户指定的任务数量,标题,目标,项目,目录,工作树,模型和 reasoning.不得额外创建审查,辅助,收集或管理任务.
- 创建用户侧新任务不等于授权它继续委派.新任务不得创建其他新任务或内部子代理,除非其任务包逐项明确授权.
- 创建用户侧新任务也不等于授权监控,取消,回调,置顶,归档,重命名,删除,提交,推送或发布.
- 用户未授权当前根主控监控时,创建并交接后停止读取进度.不得推断任务已开始或已完成.

## 创建前检查

对每个拟创建任务确认:

- 它对应可独立跟进的成果,不是当前任务中的临时步骤.
- 公用任务包足以让它脱离父任务隐藏上下文独立完成闭环.
- 前置依赖,文件/状态所有权和副作用边界明确.共享工作区存在所有权冲突时先串行化.
- 当前工具明确支持用户指定的项目,目录,工作树,模型与 reasoning 参数.不支持的参数写 `omitted` 或 `refused`,不得静默替换.
- 创建是否会隐式新增工作树,复制分支,改变目录或产生其他持久对象.若会,先询问一个最小必要问题并取得明确选择.

## 创建与交接

- 使用系统提供的用户侧任务或线程工具.不得改用内部子代理工具.
- 创建请求使用主文件的公用任务包,不要复制完整父任务历史,其他任务的结论或未经证实的预期答案.
- 成功创建后返回当前产品要求的可识别入口,并报告标题,目标,承载方式和用户后续跟进方式.
- “已创建”只表示入口存在,不得写成“已完成”.“已完成”必须有任务返回的完成结论和验证结果.

## 三种生命周期

### 仅创建并交接

用户未要求根主控代管时使用:

```text
CREATE -> HANDOFF -> FINAL
```

创建入口,报告交接信息,然后 `FINAL`.不等待,不读取进度,不推断完成状态,也不期待自动回传.

### 创建并由根主控协调

只有用户明确要求统一协调或汇总时使用:

```text
CREATE -> WAITING -> ALL_REQUIRED_RETURNED -> COLLECT_ONCE -> FINAL
WAITING -> NEEDS_USER -> WAITING
WAITING -> RETRY -> WAITING
WAITING -> BLOCKED
WAITING -> CANCELLED
WAITING -> UNKNOWN
```

1. 创建后进入 `WAITING`,使用紧凑事件快照维护完成集合.只处理状态转换,完成或需要决策的更新.
2. 缺少任务内必要信息时只补充最小信息.审批,范围冲突或用户选择进入 `NEEDS_USER`.
3. 瞬时失败只由同一任务按预算最多重试一次.验证失败返回原实施任务修复.
4. 状态不明时只做一次紧凑状态检查,仍无法证明则标记 `BLOCKED` 或 `UNKNOWN`.不得创建替代任务复制可能已写入的工作.
5. 取消只在用户或任务包已授权且工具支持时执行,并记录可能的部分结果.
6. 全部必需结果齐备后只进入一次 `COLLECT_ONCE`,再 `FINAL`.

### 主任务结束后回调

只在用户明确要求当前主任务先 `FINAL`,待用户侧新任务完成后再通知时使用.创建前按主文件入口读取 `new-task-callbacks.md`,完成其能力检查,标识,单次回调和收集者规则.回调不是默认节省 token 模式.

## 任务包补充字段

在公用任务包中明确:

- 这是用户侧独立新任务,不是当前主任务内的内部子代理.
- 用户指定的标题,数量,目录,工作树,模型与 reasoning,以及每个不支持参数的 `omitted` 或 `refused` 状态.
- 用户跟进方式是直接跟进,当前根主控事件等待,或完成后回调.
- 当前任务是否获授权继续委派;默认“否”.
- 使用回调时填写主任务 ID,`batch_id`,`task_id`,总任务数和收集者;否则写“不使用回调”.

## 验收与汇报

- “进行中”表示工具已证明任务开始但尚未满足验收标准.
- “已完成”要求结构化完成结论,验证结果和依据状态.
- “已独立审查”要求确有另一个获授权且上下文独立的执行方完成复核.
- 未获监控授权时只报告创建与交接状态,不得报告推断的后续进度.
