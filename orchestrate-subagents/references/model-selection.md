# 按需自动选择模型

在主文件的自动选模,明确模型分配方案或能力升级分支读取.先满足 `routing.md` 中对应承载的授权与工具条件.用户已指定有效模型或要求继承时无需重新推荐.模型与 reasoning 建议不改变承载,任务数量或角色权限.

## 选择边界

1. 用户明确指定且当前工具支持的值优先,即使它不在映射中也应遵从.用户要求继承时省略相应覆盖,不自动升级用户固定的值.
2. 只用即将调用的派发工具 schema 检查可用模型,reasoning 和上下文组合;映射数据不声明运行时可用性,其他工具支持的模型不能作为当前工具的依据.
3. 根据当前工作单元的实际歧义,判断强度,风险与可验证性选择最低足够等级和主要画像,再读 JSON 候选.不得仅凭驱动,架构或复杂项目等主题标签判定需要高等级模型.选择 `L3` 或 `L4` 时,简述具体判断难点及较低等级不足的依据;范围明确且可局部验证的实施与测试优先按 `L1` 或 `L2` 的实际能力匹配.质量和安全要求成立时,高风险判断可以直接使用强模型,无需先失败一次.
4. 保留当前工具支持且画像匹配的候选,按需要的判断强度筛选.同等级候选只有在任务需要和工具描述能提供可靠差异时才择优;目录顺序不是优先级.不能区分或没有匹配候选时报告 `omitted` 及原因,只有已知继承模型足够且允许继承时才继续;否则返回决策点.用户指定无效值则报告 `refused`,不静默替换.

等级和 JSON 映射是本地路由建议,不是官方产品排名,价格顺序或保证质量的上限.用户显式选择与当前宿主规则始终优先;运行任务时不得修改模型目录,隐藏开关或添加兼容补丁.

## 工作单元与总资源

模型和 reasoning 随当前工作单元评估,不永久绑定代理身份.追加工作的归属与换模交接按内部子代理场景处理;用户指定或继承要求仍优先,不得借重新评估覆盖用户选择.

少量困难判断与大量常规实施可分别派发,但只有成果边界清楚,判断结果可形成精简契约且交接收益大于上下文重建与协调成本时才拆分.同一问题的调试,修复和验证保留闭环,不强制拆成研究,实施和测试流水线,不为模型等级增加代理层.评估总资源时包括可能的返工,不把较低等级当作官方价格排序或实际省钱的证据.

## 通用等级

- `L4`:重大歧义或高风险推理.适合难以局部验证的协议与架构判断,重大跨分支冲突及复杂风险分析.
- `L3`:复杂判断.适合多来源整合,复杂故障定位,代码与协议审查,以及确有必要且获授权的分支协调.
- `L2`:聚焦理解与修改.适合边界明确的代码探索,目标修复,小型重构,测试及细粒度界面迭代.
- `L1`:明确且易于验证.适合固定范围的资料整理,日志扫描,代码位置映射及重复规则检查.

等级描述工作判断强度,不表示代理角色.所有等级均可用于叶子,都不自动获得递归权限;不得建立逐级委派流水线.当前主控已在运行,其模型不由本目录重选.

## 任务画像

选择一个主要画像,仅在消除实际歧义时补充次要画像:

- `strategic-control`:根级目标,授权,风险与最终收口.
- `cross-branch-decision`:跨分支冲突,依赖与架构决策.
- `branch-coordination`:协调后代,维护分支依赖并整合结果.
- `dependency-integration`:整合多个独立来源或执行结果.
- `complex-review`:需要较强判断的代码,协议,安全或质量审查.
- `high-risk-reasoning`:失败影响重大且需要深入推理的协议,架构或一致性问题.
- `ambiguous-problem-solving`:存在重大歧义,需要甄别竞争解释的开放问题.
- `browser-debugging`:需要观察,定位与验证闭环的浏览器问题.
- `read-only-code-exploration`:固定问题下的只读源码探索.
- `targeted-code-change`:原因或目标已清楚的小范围修改与测试.
- `focused-refactor-test`:边界明确的小型重构和聚焦验证.
- `granular-ui-iteration`:既有应用中的快速,细粒度界面修改.
- `bounded-scan`:固定范围的资料,日志或结构化结果扫描.
- `documentation-research`:边界明确的文档检索与归纳.
- `code-mapping`:只读梳理代码位置,关系与所有权.
- `repeatable-validation`:固定命令或规则下的重复验证.
- `high-volume-clear-work`:输入输出明确的高吞吐独立工作.

## 解析与 reasoning

具体模型名称只属于 JSON 数据,不得复制到本 Skill 的 Markdown,metadata 或固定任务模板;实际派发的任务包和用户报告可以写解析出的请求值.结合判断强度和编辑验证闭环选择画像;同属代码或资料任务也可能因重大歧义而需要更高等级.映射不是允许列表,不阻止用户选择未映射但受支持的模型.

reasoning profile 使用 `light`,`balanced`,`deep`,`exceptional` 四个通用值.机械低风险工作默认 `light` -> `low`,常规理解与编辑验证默认 `balanced` -> `medium`,复杂逻辑与高风险审查默认 `deep` -> `high`.只有确有需要且工具支持时才采用 `exceptional` 对应的更高 effort,不得默认最高值.用户指定的有效 effort 优先;默认建议值不受支持时,仅在工具说明提供充分依据时选其他支持值,否则省略并说明,不能猜测枚举或发出无效参数.

能力不足后的升级使用主文件的停止,交接和一次预算规则.升级时重新判断所需能力,不要求逐级增加,不把缺少工具或权限误判为推理不足.
