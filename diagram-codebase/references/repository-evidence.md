# 本地文件取证

先按 offline-analysis.md 清点并离线扫描,根据结构摘要定位入口与装配节点,再查询问题范围内的实现和连接两端.扫描前仅定向读取入口工作约定与必需构建配置,不通读业务源码.跳过依赖,缓存和生成目录;片段不足以证明系统边界时只描述片段,明确遗漏.

| 线索 | 核对位置 | 能证明什么 |
| --- | --- | --- |
| import/include/包依赖 | 实际使用点,编译条件 | 静态依赖,不直接等于运行调用 |
| 启动/路由/实例化 | handler,装配/绑定位置 | 入口及结构归属 |
| 函数指针/事件/回调 | 注册,触发和实现 | 已核对的间接关系;缺一端标未知 |
| 缓存/存储 | 读写和错误处理 | 命中,未命中,异常与回退 |
| 进程/设备部署 | 启动与部署配置 | 已知部署边界,不由模块名推断 |

Markdown 中就近记录支持关键陈述的项目相对路径,符号与必要行号.用户描述和推断单独注明.过时 README 和未实现规划不进入当前架构.没有源码时说明是设计图,不生成虚假行号.

将每条关键关系还原为来源模块,动作,目标模块,条件/阶段和证据.调用箭头从调用者指向被调用者;依赖箭头从使用者指向被依赖者;数据流从提供者指向消费者.同一对模块可有不同类型的双向关系,不可用一个含糊的"依赖/数据"标签混合方向.摘要中未展开的模块不能只凭文件名写完整职责,按需核对其公开接口和代表性实现;目录存在或符号定义只证明可定位,不证明谁调用了它.

对错误路径读取调用方是否接收,检查和传播返回值,必要时追到返回宏定义.区分原样传播错误码,统一映射和忽略返回,不将所有非零概括成某个具体常量.延后提交状态不等于前面没有写硬件,发生失败时分别说明已发生副作用和是否存在回滚.缺少回滚实现不能描述成原子事务.这里只补关键片段,不为核验通读全仓.

唯一取证对象是指定目录当前实际存在的源文件,不区分它是否受版本管理.记录扫描范围,文件相对路径,符号/行号和证据局限;需要冻结证据时使用文件 SHA-256.不采集 Git 状态,提交号,分支或历史,不读取 .git 元数据,不因 Git 所有权问题进入排障流程.内部索引的文件/配置哈希用于检测内容变化,不依赖版本控制.

更新时先按当前文件集合与内容哈希检查索引新鲜度,过期则重扫相关范围,再定向查询受影响的局部内容,核对关系两端和接口,不使用 Git diff 选择取证范围.保留无关视图,节点 ID 与坐标.静态证据不能证明运行时配置,时延,资源安全或实际命中;把这些限制放到对应结论旁边.
