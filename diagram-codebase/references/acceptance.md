# 轻量验收

## 交付门

1. 事实:所有文件工程先执行离线扫描或验证既有索引新鲜度,再查询关键关系两端及局部条件.清点/环境探测不代替扫描,报告范围,配置,状态和未支持项.区分源码,用户设计和推断,片段外的系统不补造.提前返回后的更新不能画成必然发生,异步事件不能因声明顺序变成同步步骤.
2. 双文件:draw.io 能速览,Markdown 有独立完整结构,接口及关键流程.除模块标识/名称,还要将两份的一句话总结,边方向/类型,条件,阶段与图例逐项对照源码.两份写了一样的话不等于事实正确.人工核对证据为独立列表项,每项一个来源位置及其支持的结论,不将多个路径挤成段落;格式见 markdown-authoring.md.
3. 结构:有 Python 3.10+ 时运行下面的只读标准库检查.没有解释器时手工核对并说明脚本未执行,不安装环境.
4. 阅读:有现成阅读器时打开实际 draw.io 和 Markdown.按 drawio-authoring.md 在 100% 与适合页面视图核对文字/标签遮挡,连线穿字,容器标题留白与缩放后可读性.已知截图遮挡算视觉失败,修改后须复核实际候选;未实际打开则标记视觉/渲染未验证,结构通过不冒充可视验收.

语义走读按图示的每类路径核对:入口 -> 守卫 -> 调用/副作用 -> 返回或终点.检查空操作重复返回,失败后继续执行,忽略的错误码,状态提交与回滚是否混淆.宏控制返回时补读宏定义;源码已存在但当前索引未展开的头文件只定向核对必要片段.这是 Agent 的证据审查,不添加正则规则去假装自动证明控制流.

核对分析模式:source 的成功表示源码结构提取通过,不要求工程 SDK 齐全,不要求生成环境配置.调用表达式/实参可指导 Agent 定向核对,不能自动当作已解析调用或已执行回调;宏体没有自动展开,条件编译各侧不能混成同一当前架构.configured 保留实际输入与新鲜度检查,失败不能静默改用 source 宣称等价完成.两种模式都要报告其真实解析覆盖和未知项,不能将模型判断升级为编译/运行证据.

阅读器探测以当前宿主已有打开能力,用户提供的信息或已知安装位置为准.PATH 查不到 draw.io 可执行文件只说明不在 PATH,不能证明 VSCode 插件或其他阅读器不存在.没有实际查看能力就报告未视觉复核,不整盘搜索或自动安装.

```text
python -B scripts/check_diagram.py architecture.drawio --markdown architecture.md
python -B scripts/check_diagram.py --markdown architecture.md
```

脚本只输出文本,不创建 JSON/HTML/截图,不修改输入,不启动子程序/浏览器,不联网,不调用模型.检查普通未压缩 draw.io 的层/ID/父引用/连线/几何,Markdown 围栏与主图模块锚点覆盖;它不验证全部 draw.io 语法,Mermaid 语义,源码或视觉.不能将其 PASS 称为全部验收通过.

新生成文件采用本 Skill 的轻量约定:可编辑矩形/容器和绑定端点的关系线,模块 ID 为 mod_ 开头.既有复杂图可保留,不支持的结构明确报告后用其编辑器复核,不能为通过本脚本删除真实结构.输入限 UTF-8,每份最多 4 MiB;禁止 DTD/实体声明.退出码 0 表示所执行检查通过,1 表示文件/结构问题,2 表示参数错误.

## 修改与失败

先在入口约定的 `_work/<主文件名>/candidate/` 保存候选,检查通过再交付.已有两份成果要先在对应 backup/ 留可恢复副本再替换;失败不覆盖上一版,也不把旧成果说成本次成功.脚本非零先看具体诊断,只做有依据的修复,不放宽检查来掩盖问题.交付前核对工程内新建文件都在约定的输出树中,最终文档不引用过程目录作为必需依赖;新建的可复用分析配置在输出目录顶层,与可清理过程文件分开.核对当前配置是否实际用于扫描,其来源/适用范围和未支持项是否说明;不把仅记录 HDL 参数当作解析器已经支持它们.不为验收擅自删除过程目录或移动仍在使用的旧文件.

候选生成时就使用以最终文件位置为基准的相对链接,不等复制后补写链接.先完成候选的语义,双文件,结构和可执行的视觉检查;修复只编辑受影响节点/段落,不重发整份文件.交付后以字节比较或文件 SHA-256 确认与已验收候选一致,再检查最终位置的配套文件和链接能定位.字节一致时无需重复整份结构检查;内容变化则回到候选修复并复查受影响的语义,结构和布局.结构检查结果不能替代视觉检查;阅读环境或相对资源位置变化时仍核对阅读结果.未验证的项目如实保留,不因为文件一致就变成已验证.备份保护和最多三轮修复/连续两轮无改善停止的限制不变.

图文件写入本身无需第三方运行包;图结构检查只有 Python 标准库.文件工程分析必须先离线扫描,解析环境按 [initialization.md](initialization.md) 按语言准备与验收,不因图检查可手工进行而跳过源码扫描.实际查看依赖用户已有的 VSCode draw.io 插件或等价编辑器,以及支持 Mermaid 的 Markdown 阅读器.不强制任何厂商/版本,不自动安装,不保证所有阅读器支持全部 Mermaid 图型.维护期 Skill validator 的 PyYAML 属于仓库开发环境,不是绘图运行依赖.

## Skill 回归

```text
python -B -m unittest discover -s tests -p "test*.py"
```

测试结构错误,锚点缺失/重复,围栏,只读失败和隔离标准库执行.随包 assets 双文件也走同一检查.行为回放另用原始 fixture,不能拿预制图冒充独立分析:

| 场景 | 必须核对 |
| --- | --- |
| 本地文件/版本管理无关 | 普通目录与含 .git 的目录都按当前文件扫描,不调用 Git,不把 .gitignore 当扫描过滤条件,不进入 Git 排障 |
| 软件过时规划/动态注册 | 不补造服务,区别注册/执行和缓存错误 |
| 固件 DMA | 提交返回与 ISR 完成分开,缓冲区所有权与未知项明确 |
| 控制与失败分支 | 使用 firmware/control_paths.c 原始输入:核对启动停机,空操作早退,宏返回,原样错误码,被忽略返回,部分硬件副作用与末尾状态提交;不把预制图或静态检查当作行为通过 |
| 已安装环境/工程路径 | 先复用明确解释器或 Skill venv,一次确认实际范围的解析分支;优先工程已声明位置,不全盘找工具链;无额外配置需求不搜索环境 |
| 准备汇总/可选进度 | 混合缺包/版本不符/未支持语言和可确定配置错误集中报告且不启动解析或写缓存;坏配置不猜范围;--progress 不改事实/stdout,超时与写入失败有阶段记录,正常不建日志 |
| 源码结构模式 | 用 firmware/source_structure.c:缺失 SDK 不阻断 C 源码结构,三侧条件保留,声明/宏/调用表达式不混淆,传回调不算执行,字符串/注释无伪调用;头文件独立提取,语法错误 partial,不读旧环境配置,两模式缓存隔离,失败不覆盖本模式成功索引 |
| 候选复用验收 | 候选先按最终路径写链接并完成检查,复制字节一致不重复整份结构检查;内容变化复查受影响部分,最终链接核对不能省略,未视觉验证不能冒充通过 |
| HDL 参数/非阻塞/模拟贡献 | 不把互斥硬件画成同时存在,不伪造逐句调用或模拟求解顺序 |
| Python await/任务 | 不把 coroutine 当已运行,不把 await 当线程 |
| Skill 条件/排除 | 明确 else 与未声明 else 分开,普通引用不成执行边 |
| 笔记双链/同名/计划 | 保留歧义与引用类型,无依据不画甘特排期 |
| 局部更新 | 稳定 ID/无关布局保留,两份相关内容同时核对 |
| 可复用配置 | 默认/自定义输出中按需 analysis-config.json;无配置 C/Python/文档可扫描,不强制搜索工程;未变直接复用,来源/环境/内容变化明确拒绝,仅源码变化不重建配置;pending 和未支持参数不可冒充就绪,未知输出不覆盖,原生配置不搬动,清理过程目录不删除配置 |
| 配置交流 | 缺项不影响语义则不追问;关键宏/目标或范围冲突集中询问,复用对话已有信息,询问前只查所需配置来源;用户确认后记录,不以 parser PASS 证明目标配置完整 |
| 单一配置文件 | 标准输入准备/更新后仅有 analysis-config.json,不创建 _work 草稿或转发脚本;中文/引号/空格参数往返正确,可捕获写入失败清理内部临时文件并保留旧配置;拒绝旧 --input 草稿接口 |
| 缺少查看器/检查器 | 仍能生成文件,如实列未验证项,不安装环境 |

静态检查,原始输入行为回放,实际渲染和视觉分别记录.不以文件数/字符量声称 Token 命中率或固定节省.
