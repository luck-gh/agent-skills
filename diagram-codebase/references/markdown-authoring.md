# Markdown 架构详解

Markdown 不是附件索引,必须独立回答系统是什么,如何组成,如何交互,有哪些限制.可从 [architecture.md](../assets/architecture.md) 骨架开始,删去不适用内容;不要机械填空或默认加载模板.

## 内容组织

1. 一句话用途,本地目录的扫描范围,分析模式与已知缺口;提供同名 draw.io 相对链接.source 写明未选择构建变体,条件/调用目标未求解;configured 说明实际消费的配置及未确认项,不罗列无关环境信息.以当前文件为准,不附 Git 提交号,分支或工作区状态.
2. 完整结构概览:Mermaid flowchart 的模块名称,ID 和关键边与 draw.io 对应.低层细节可分图展开,但读者无需打开 draw.io 才能了解全貌.
3. 模块职责与接口:每个主图模块有同名 `<a id="mod_x"></a>` 锚点和具体解释.列出入口,输入/输出,前置条件,同步/异步,错误路径,状态/所有权及关联模块,只保留实际适用字段.
4. 关键流程:选择能回答问题的流程图,时序图或状态图,不每类都画.甘特图仅用于有任务/依赖/排期依据的计划.
5. 关键约束,待确认项与源码证据.证据就近放在对应说明,末尾可归总,不重复粘贴源码全文.

新图模块 ID 采用 ASCII 字母数字下划线,如 `mod_queue`,同时用于 draw.io 与 Mermaid.模块锚点放在代码围栏之外;参考锚点的真实链接不会代替模块解释.仅 Markdown 请求也采用同一组织,无需生成 draw.io 占位文件.

## 证据排版

对应说明后单独写 `证据:`,下方使用普通 Markdown 无序列表,一条证据一个列表项,每项独占一个源文本行.每项只放一个来源位置和一句支持的结论;同一文件的不同位置分别列项,不把多个路径用逗号/顿号串成一段,不用空格或制表符对齐.长路径允许阅读器自然折行,不要求屏幕上强制保持单行.列表前留空行.

代码证据写项目相对路径,已核对的符号/必要行号以及支持的结论.路径使用行内代码或可定位的链接,不混淆推断和事实.用户设计按来源逐项列出,没有源码时不补造路径.以下仅为格式示意,路径/行号不能直接充当真实证据:

```markdown
证据:

- `src/api.c:40-52`: 参数校验失败时提前返回.
- `src/api.c:70-74`: 所有配置成功后才提交状态.
- `src/interrupts.c:110-118`: 中断处理函数调用请求解析接口.
```

## Mermaid 选择

| 问题 | 图型 | 注意事项 |
| --- | --- | --- |
| 整体组成,数据路径,条件分支 | flowchart | 每条边明确关系类型,同图统一抽象层级 |
| 一次交互如何完成 | sequenceDiagram | 区分调用返回与异步完成,用 alt/else 表示真实分支 |
| 状态如何改变 | stateDiagram-v2 | 事件与守卫条件来自实际转换点 |
| 任务如何排期 | gantt | 日期/工期注明依据,用户提供的计划不伪装成源码事实 |

使用标准 `mermaid` fenced code,不混用 `puml`,`flow`,`sequence` 或 ditaa 方言.不需要独立 mmd,也不要求安装 Mermaid CLI.使用阅读器支持的基础语法,短标签和明确图例;避免初始化脚本,click,外部图标与链接执行.

时序图的纵向距离不代表耗时,par 只用于有依据的并发.箭头不能代替同步语义说明.甘特图无法从普通调用关系恢复;没有排期依据就省略或先询问,不得补日期.纯字符统计图不属于本 Skill 的触发范围.

## 关键流程语义

- 先确定图覆盖正常路径还是包含失败的完整场景.仅画成功路径时在标题或图内注明,失败边界仍在附近交代;不能把含少数失败分支的图当成已覆盖全部失败.
- 提前返回,异常终止或永久停机必须终止该路径.alt/else 结束后仍有共同步骤,不能仅在 alt 中写"返回/停机"就认为后面的步骤不会发生.用带明确条件的 break 中断场景,或将后续步骤限制在成功分支;失败分支太多时改用有终点的流程图.普通被调函数返回不等于结束整个系统,break 只用于确实结束当前展示场景的路径.
- 同一次调用在每条路径只画一次对应返回;空操作提前返回后不能再画统一返回.按源码核对循环跳过,条件守卫和最终状态提交,不要从函数排列恢复顺序.
- 同一标签合并多个动作时核对它们的条件是否相同.例如成功提交状态和失败写日志不共享"成功后"这个条件;使用中性短标签,把各自条件放在详解,需要时拆边.
- 外部参与者的行为,写入/触发先后或部署协议没有本地证据时,在图内或紧邻流程注明假设/用户约定,不能只在远处模块段落保留限制.

修改时保留无关段落和图源,复核双文件共享的模块与关键关系.若用户手改 draw.io 改变了架构,先以已核实意图更新 Markdown,不要机械反向覆盖.

参考 [Mermaid sequenceDiagram](https://mermaid.js.org/syntax/sequenceDiagram.html) 和 [gantt](https://mermaid.js.org/syntax/gantt.html).检查围栏不等于 Mermaid 语法已渲染通过.
