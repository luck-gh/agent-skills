# 来源与安装前检查

## 来源身份

按以下优先级识别安装包:

1. 厂商官方网站的产品下载页或官方发布仓库;
2. 厂商维护的包管理器清单;
3. 经厂商文档明确链接的 CDN.

不要使用搜索广告,软件下载站,镜像聚合站,论坛附件或来源不明的直链.重定向后的最终主机,文件名和内容仍需与官方发布信息一致.官方页面无法访问时暂停,不用第三方来源替代.

记录以下证据:

```text
product:
publisher:
version:
channel:
architecture:
installer_type:
source_page:
download_url_or_package_id:
retrieved_at:
```

不要把 URL 中的版本号作为唯一证据;与页面,安装器元数据或官方清单交叉核对.

## 签名与哈希

下载完成,执行之前:

1. 读取 Authenticode 签名状态,证书主题,时间戳和证书链;
2. 将签名发布者与已锁定的官方发布者比较;
3. 若厂商发布哈希,使用其指定算法计算本地文件哈希并逐字符比较;
4. 记录本地文件大小,最终路径和最后写入时间,避免核验后文件被替换;
5. 执行前再次确认实际命令引用的是已核验的同一文件.

将 `Valid` 之外的签名状态,意外发布者,缺失的预期签名,哈希不一致或核验后文件变化视为硬停止.不要通过取消阻止,忽略 SmartScreen 或关闭安全软件来继续.

有些官方包可能无签名.只有官方明确说明且存在可信的独立完整性证据时,才向用户解释风险并请求是否继续;不要替用户接受风险.

## 主机与卷检查

确认:

- Windows 版本,版本分支和架构满足厂商要求;
- D 盘是固定,本地,在线的 NTFS 卷,不是网络,可移动,SUBST,云同步或临时挂载路径;
- D 盘空闲空间覆盖下载,解压,安装主体,升级并存和回滚备份,并留出合理余量;
- 目标父目录存在或可安全创建,不是 reparse point,解析后的规范路径仍位于预期 D 盘根目录;
- 目标目录为空或属于已识别的同产品版本;
- ACL 允许预期安装上下文写入,但不向普通用户开放不必要的修改权限;
- 暂存目录和日志目录有空间,并且不会把敏感令牌写入日志.

不要用修改 ACL,取得所有权或关闭防护作为默认修复.若权限阻止安装,说明需要的最小权限和精确路径,再通过平台审批请求提权.

## 现有状态与冲突

只读盘点以下来源并交叉核对:

- 已安装应用/卸载项的显示名,版本,发布者和安装位置;
- 主程序文件版本和架构;
- 服务,计划任务,驱动,浏览器扩展或 shell 集成;
- 厂商包管理器记录;
- 用户数据,配置,插件,许可证和工作区位置;
- 相关进程是否正在使用目标文件.

不要仅按模糊产品名选择进程,目录或卸载项.发现多个版本,多个架构,per-user 与 per-machine 并存,企业管理策略或来源不明的现有目录时,暂停并把冲突列给用户.

## 安装器能力

从官方帮助,安装器自带帮助或厂商清单确认:

- 安装,升级,修复和卸载的支持方式;
- 自定义目标目录参数和适用范围;
- 静默/被动/交互模式及 UI 行为;
- 日志参数;
- 所需权限;
- 标准与厂商自定义退出码;
- 重启控制方式;
- 是否支持降级,并行版本和回滚.

把无法确认的参数保留为空并暂停.不要根据其他产品,安装框架外观或网上示例推断同名参数.
