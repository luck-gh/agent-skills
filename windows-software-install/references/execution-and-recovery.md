## 执行记录

在执行前建立记录:

```yaml
operation: install | upgrade | repair
product: ""
publisher: ""
requested_version: ""
channel: ""
architecture: ""
installer_path: ""
installer_sha256: ""
signature_publisher: ""
target_path: ""
log_path: ""
working_directory: ""
command: ""
privilege: standard | administrator
timeout_seconds: "<positive-bounded-integer>"
expected_exit_codes: {}
reboot_policy: suppress-and-report
rollback_plan: ""
```

执行前必须把 `timeout_seconds` 占位符替换为适合该产品,操作和环境的正整数秒数,并记录选择依据和明确上界.拒绝 `0`,负数,空值,无限值,以及任何表示“禁用超时”或“永久等待”的值;未得到有效的正数有界超时就不要启动安装器.

让 `reboot_policy` 默认保持 `suppress-and-report`:阻止安装器自行重启,并把需重启状态报告为待处理.只有用户在了解未保存工作和影响后另行明确授权本次重启,才可把策略改为 `authorized-reboot`.厂商退出码,安装器默认行为或先前的安装授权都不能替代这项单独授权.

只有厂商未提供其他强哈希且包可合法执行时才把 SHA-256 用作本地审计指纹;若厂商提供指定哈希,另行记录并比较其算法和值.

执行记录与传输通道必须遵守 `SKILL.md` 的“保护秘密传输”硬门禁,不得由本模板,安装器习惯或风险接受放宽.只为已确认非敏感的参数使用参数数组或安全的原生调用方式,避免未经转义的字符串拼接.

## 有界执行

1. 再次核对安装包身份和目标路径.
2. 只请求完成操作所需的最小权限.
3. 在确认输出和日志通道符合 `SKILL.md` 的秘密传输门禁后,捕获启动时间,结束时间,原始退出码,标准输出,标准错误和安装器日志;意外捕获秘密时停止传播,只保留完成诊断所需的最小脱敏证据.
4. 使用已记录的正数有界超时;拒绝 0 和无限等待.超时后停止发起新命令,先判断安装器是否仍在运行,是否等待 UI/UAC、是否生成日志或已启动子进程。
5. 不要因无控制台输出判断卡死,不要盲目终止 `msiexec`,厂商服务或同名进程.
6. 将厂商定义的需重启返回码记录为“待重启”,不要擅自重启,也不要把它降格为普通成功.

安装器启动了脱离父进程的子进程时,使用厂商支持的等待方式或以最终状态证据为准.不要仅以 bootstrap 进程退出判断安装完成.

## 失败分类

区分并报告:

- 下载或完整性失败;
- 前置条件不满足;
- 权限或策略阻止;
- 路径参数被拒绝或忽略;
- 安装器返回明确失败;
- 超时但最终状态未知;
- 安装成功但需重启;
- 主体已写入错误位置;
- 验证失败.

不要在原因未知时自动重试.参数错误,签名错误,路径错误或策略阻止的重试不会变得更安全.

## 升级与修复

在升级或修复前:

- 记录当前版本,路径,架构,安装上下文和可回退状态;
- 导出或备份厂商支持的配置与用户数据;
- 验证备份可读,并避免把备份放进将被覆盖的目录;
- 记录插件,扩展,服务账号,端口,许可证和环境变量影响;
- 确认新版是否支持就地升级,跨版本升级和回退;
- 保留旧版安装包或厂商支持的恢复介质(若许可允许).

不要假设 repair 是只读操作.它可能恢复默认配置,重新注册服务或把主体写回原路径.

## 迁移

将 C 盘旧版迁移到 D 盘时,优先使用厂商明确支持的迁移或"卸载后重装"流程.把迁移拆成不可传递授权的阶段.任何会改变状态的阶段开始前,为该阶段建立独立授权记录,绑定精确软件,版本,来源/哈希或其他可验证身份,动作,目标,参数和当前预检;不存在可覆盖多个阶段的整体"迁移授权":

1. 只读盘点主体,用户数据,配置,插件,服务和许可证,并准备 D 盘新安装方案与回滚方案.
2. 建立备份会写入文件时,先为精确备份对象,目标,方法和当前预检取得独立授权;随后只读验证备份可读.
3. 卸载旧版前,为精确软件,旧版本,发布者或其他可验证身份,卸载器来源/哈希,卸载动作,保留数据选项,目标,参数和当前预检取得独立授权.
4. 卸载完成后重新执行预检.安装到 D 盘前,为精确软件,新版本,来源/哈希或其他可验证身份,安装动作,目标,参数和新的当前预检另行取得授权;卸载授权,一次"迁移"批准或卸载成功都不能授权安装.
5. 将验证拆成只读检查和可能产生副作用的动作.只读检查按已说明范围执行;启动 GUI,创建配置/账户,联网,下载组件,迁移数据或其他会改变状态的验证,必须按精确动作,目标,参数和当前预检分别取得新授权.
6. 仅在用户确认新版本可用后提议清理.删除旧目录,旧备份或厂商允许清理的暂存/缓存时,为每个精确对象,清理动作,参数和当前预检分别取得独立授权;不要清理 Installer 缓存或共享组件.

每个阶段开始前都重新核对软件,版本,来源,哈希或可验证身份,动作,目标,参数和当前预检.任一字段漂移,结果冲突或状态 unknown 时立即停止;前一阶段的批准或成功不能传递到下一阶段.即使旧版已经卸载,也不得以当前不可用状态逼迫用户授权或继续安装;保持停止状态,报告可选恢复路径并等待对下一精确动作的新授权.

不要先删除旧主体,不要手工移动已安装目录,不要用 junction 掩盖 C 盘路径,不要清理 Installer 缓存或共享组件.

## 回滚与恢复

把回滚设计为显式分支,而不是失败后临时决定.回滚计划,安装/迁移批准,前一动作成功或系统已处于降级状态都不授权新的恢复动作.每个会改变状态的回滚或恢复动作开始前,按精确软件,版本,来源/哈希或其他可验证身份,动作,目标,参数和当前预检另行取得授权;漂移,证据冲突或状态 unknown 时停止.

- 安装前失败: 不改变现有版本,保留日志;删除暂存是新的清理动作,须对精确对象另行授权.
- 安装中失败: 先只读判断状态.只有厂商自动回滚作为不可分割副作用已在启动前绑定到该安装器的精确授权时,才执行后记录观察结果;未纳入授权时不得预先启动安装器,若仍意外发生则停止后续副作用并报告.另行启动厂商或 Windows Installer 回滚命令必须取得新的精确授权,再验证旧版是否可用.
- 升级后验证失败: 若厂商支持,先提出回退到已锁定旧版和恢复兼容配置的方案;运行旧版安装器与恢复配置是不同副作用,分别取得精确授权.
- 路径错误: 不要手工搬移或删除,说明需要分别授权卸载和重装.
- 状态未知: 停止重复执行,只收集已授权范围内的日志和只读状态,报告人工决策点.

回滚同样可能需要提权,停服务,卸载,写文件,清理或重启,沿用 `SKILL.md` 的授权矩阵并逐项授权,不把"恢复"视为无限授权.不得因旧版已卸载,安装失败或恢复压力而自动执行下一动作.
